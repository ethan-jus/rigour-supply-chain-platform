# HR 人事与薪酬

HR 独占 `rigour_hr`，维护员工、部门、岗位、任职、经营指标、薪酬及考勤月度规则。IAM 管登录及授权，Sales 管原始外勤和拜访证据，Order 管交易及回款，ERP 管商品规格。

## 商品提成

- 商品分类和规格型号来自 ERP `/api/v1/erp/payroll-products` 及 `/categories` 服务 API；HR 对外提供 `/api/v1/hr/payroll/products` 和 `/product-categories`。分类查询包含下级，型号按真实 SKU 精确匹配，前端直接填写计算方式和提成标准，不再提供参考标准选择；历史商品组字段保留兼容，不参与金额计算。规则保存在 `hr_payroll_rule` 的版本化 JSON，查询和存取使用 MyBatis-Plus Mapper。
- 销售与城市总按 SKU、部门、订单日期对应的生效期间选择独立规则。支持数量乘单位金额、订单净回款按明细金额分摊后乘比例；两种方式都在全额回款后一次计提。退款或资料异常进入待核对，同部门、同角色、同 SKU 的启用规则期间不得重叠。
- 城市总实际提成 = 下属销售提成 × 配置比例（CITY_TEAM）+ 城市总独立提成（CITY_MANAGER）+ 配置允许的本人销售提成（SALES）。下属不含本人，按城市归属规则有效期内的订单汇总。已结算销售提成取已确认/已发放薪酬快照，尚未结算部分使用相应销售规则。三类提成分别防重，明细保留销售员工编号、原规则版本和金额。
- HR 可随时编辑规则并保留审计。未确认薪酬重新核算时采用新标准，确认前重新核对来源指纹；已确认/已发放快照不覆盖，纠错继续使用原有撤回或跨月补差流程。
- Portal「提成设置」只维护商品提成和城市总提成，不含团队成员名单等人员管理功能。城市总表单整合负责人、多选管辖城市、生效日期、团队销售提成计入比例（0–100%）、本人销售是否另计和独立商品标准；截止日期、启停和备注放在更多设置。
- 城市总规则 JSON 的 `cityCommission.teamPercent` 控制团队金额，先计算销售原提成再按比例保留两位小数。`products=null` 沿用部门商品标准，空列表明确不计独立提成，非空列表按城市及任期内订单匹配 SKU，覆盖部门城市总标准而不叠加。旧规则没有 `cityCommission` 时仍按 100% 团队提成及原部门标准核算。
- 一次新增多城通过 `POST /api/v1/hr/payroll/rules/city-managers` 保存，1–100 个城市，同一负责人、每城独立请求编号；复用 MyBatis-Plus 存储、规则锁、权限和审计，任一城市冲突整批回滚，原请求可幂等重试。列表按城市总分组，城市与负责人独立筛选；每城后续单独编辑，交接时修改原记录截止日期，再新增接任配置，保留原记录启用以计算历史订单后续回款。
- 核算按订单城市和订单日期匹配每城有效规则，多城市汇总到城市总当月薪酬；本人订单不计入团队，是否另计销售提成由配置决定。金额明细保留管辖配置版本和团队比例，完整规则写入核算快照及指纹。HR 修改后未确认结果需重新核算，已确认/已发放结果仍被原有流程锁定。
- 月度薪酬的商品提成明细及薪酬确认弹窗分别展示团队销售、城市总独立、本人销售和本期计入工资的提成；待回款金额单独说明，核算金额与发放登记区分。先确认销售、再核算确认城市总是操作提示，本期没有增加强制的确认顺序门禁。

## 一期考勤

- Portal 入口：人事 → 考勤规则设置、员工考勤。
- `GET /api/v1/hr/attendance/rules`：规则列表按月份、部门（0 为公司默认、空为全部）、锁定状态筛选，过滤后分页，公司默认优先，部门按组织层级排序。只显示实际设置的规则；恢复公司默认的部门保留版本及审计，但不列入已设置规则。返回当月已设置/已锁定部门供新增弹窗禁选。
- `/api/v1/hr/attendance/rule`：按“月份 + 部门”维护规则。`departmentId` 为空时设置公司默认；部门规则只对本部门生效，未设置时回退公司默认，不继承上级部门，也不沿用其他月份。部门 `expectedDays=null` 表示恢复公司默认，保留递增版本和审计；公司默认不允许清空。
- `/api/v1/hr/attendance`：按权限范围分页读取当月任职期间重叠的员工；销售通过签名服务 API `/api/v1/sales/attendance-evidence` 批量提供打卡日期。
- 筛选独立传入 `employeeName`、`employeeCode`、`departmentId`、`attendanceStatus`，姓名和编号分别包含匹配，多个条件取交集；部门包含自身及下级，始终叠加租户及员工数据权限。`/api/v1/hr/attendance/departments` 在考勤或考勤规则读取权限下提供本租户组织树选项。
- 打卡依据为 Sales 临时拜访的 `SUBMITTED` 且未删除记录，按上海日期去重；不以拜访审核、录音时长或客户数量认定出勤。员工与打卡账号采用既有已核对编码绑定。
- 实际出勤默认使用在职期间打卡日数，缺勤默认使用 `max(应出勤－实际出勤,0)`。当月只显示截至今日的实际天数，月份结束后显示缺勤。未绑定、来源不可用和未配置规则分别保留未知。
- `POST /api/v1/hr/attendance/{month}/{employeeCode}/confirm`：HR 确认前按月独立调整实际出勤、缺勤（0 至当月天数，0.5 天步长），填写缺卡原因与单选请假类型。`actualDaysOverride` / `absentDaysOverride` 非空时分别优先于系统计算，显式 `null` 恢复自动计算，0 是有效人工值；人工缺勤不要求等于应出勤减实际出勤。当实际值被调整而缺勤未调整时，月末缺勤按调整后的实际值计算。原始打卡日期与 `punchDays` 保留，不回写 Sales。
- 请假类型来自 Foundation `ATTENDANCE_LEAVE_TYPE`，初始为无、调休、事假、病假，支持字典扩充。确认必须选择本租户启用的字典项；停用的历史项仍可显示，确认前须改选启用项。类型不自动换算天数、不联动工资。
- 员工按档案中的当前所属部门匹配应出勤规则，不按历史调动分段；列表标明“本部门规则 / 公司默认”。公司默认和本部门规则均未设置时，应出勤和自动缺勤保持未知。月中入离职不自动折算默认应出勤。没有排班、请假审批、整月批量结算或自动扣薪；现有工资绩效计算保持独立。
- 月度列表没有定时生成任务，也没有“生成本月”操作：打开、查询、翻页或刷新列表时，按所选月份实时组合员工、规则、打卡和历史人工资料；未确认员工默认 `PENDING`。查询不创建业务记录，确认才持久化最终结果。旧人工资料迁移后仍待确认，不自动变为已确认。
- 状态文案和筛选选项由 Foundation `ATTENDANCE_STATUS` 字典提供，初始为 `PENDING`（待确认）、`CONFIRMED`（已确认），流程编码固定。筛选在总数及分页前执行，未持久化的员工也属于待确认。
- 仅待确认记录可执行考勤确认；确认须已有应出勤规则，实际和缺勤最终值明确（当月自动缺勤暂未计算时由 HR 填写）。后端拒绝重复确认、旧版本及越权操作。确认时冻结应出勤、实际、缺勤、请假类型、原因、打卡依据和部门/规则来源，后续打卡或规则变化不改变已确认结果；当前不提供撤销确认。
- 同租户、同月份、同部门仅一条规则，禁止重复新增和无变化提交，尚无关联员工确认前可修改。任一员工确认后锁定确认时所属部门的当月规则；若使用公司默认，还会锁定该月公司默认。锁定后不可修改、恢复默认或新设覆盖规则，其他部门和月份独立，不因员工后续转部门解锁。规则变更与确认共用租户月度数据库行锁，并在确认落库前校验部门及生效规则，防止并发修改绕过锁定。
- 考勤查询与写入统一经 MyBatis-Plus Entity / Mapper / Store，包括规则、员工分页、部门选项、确认记录和审计；月度行锁 SQL 放在 Mapper 中。`hr_attendance_rule` 是现有规则记录表，复合键仍为租户、月份、部门，不另建重复表。复合键实体不使用单列 `ById` 方法，所有查询、更新显式限定业务键。
- 表：`hr_attendance_rule`、`hr_attendance_note`、`hr_attendance_audit`、`hr_attendance_month_lock`，按租户隔离，版本冲突拒绝覆盖，写入与审计同事务。
- 权限：`hr:attendance-rule:read/write` 管公司默认和部门规则，`hr:attendance:read/write` 管员工查看和考勤维护；后者同时执行员工数据范围。

## 运行与验收

工程启动类为 `HrApplication`，服务名 `rigour-hr-payroll-service`。出站通过注入的 RestClient.Builder 和 Nacos 服务名寻址，身份使用签名上下文；凭据遵循根 AGENTS.md。环境配置和迁移策略见平台开发规范。

本期升级包括 HR V15/V16/V17/V18、Foundation V37/V38、IAM V132，以及 HR、Sales、Portal 的对应代码。生产仍按项目规定独立执行数据库升级；本地测试不代表线上迁移或业务数据验收完成。

定向验证：`./mvnw -pl services/rg-scdp-hr/hr-server,services/rg-scdp-sales/sales-server -am -Dtest=HrAttendanceServiceTest,HrAttendancePersistenceTest,SalesAttendanceSourceServiceTest,SalesAttendanceSourceStoreTest -Dsurefire.failIfNoSpecifiedTests=false test`。
