# 台式机应用一键部署

本阶段发布 IAM、Gateway 和门户，入口 http://192.168.12.7:5100 。开发允许 HTTP，不配证书，不关闭真实认证、PKCE、签名或权限检查。业务服务和销售工作台按后续批次接入，不能把登录成功当作全部模块可用。

在 Mac 的终端执行 `python3 scripts/desktop/deploy.py`，或双击“ 一键部署.command ”。要求三个项目沿用当前并列目录，后台与门户在干净且已推送的 dev 分支；Mac 已安装 Java 21、Node 24、pnpm，并拥有台式机 SSH 密钥。

流程：Git fetch → 只快进更新 dev → Maven verify → 门户 lint/类型检查/测试/build → 校验发布包 → 上传 D 盘 → 本机数据库备份 → Docker 应用更新 → 健康检查。任何构建失败均不更新运行中的应用。

采用 Mac 拉取和构建，是因为台式机访问 Git 智能协议接口实测超时；不需要把 GitHub 凭据复制到 Windows，也不依赖台式机访问镜像仓库。发布包只含 JAR、网页和非敏感部署模板，不含 .env 或签名私钥。

- 状态：`python3 scripts/desktop/deploy.py status`
- 日志：`python3 scripts/desktop/deploy.py logs`
- 应用回退：`python3 scripts/desktop/deploy.py rollback --version 版本号`

脚本不会自动 push、强制覆盖分支、删除数据卷或执行 Flyway repair。只有数据库迁移版本及配置快照一致时才允许自动回退应用；数据库不自动回退。首版脚本整套更新上述 3 个应用，不提供任意业务服务的单独发布。

运行目录 Linux `/srv/rigour-dev/apps`，物理位于 D:\RigourDev\wsl\RigourDev；Windows 可通过 `\\wsl.localhost\RigourDev\srv\rigour-dev\apps` 查看。`releases` 保存发布版本，`current` 指向最后验收成功的版本，`config` 保存运行配置，`keys` 保存本机签名私钥，`backups` 保存发布前的 IAM 数据库和配置备份。Mac 构建日志和发布包位于 `~/Library/Caches/RigourDev`。

配置直接由本机文件管理，第一批不引入 Nacos 配置发布流程，也不加载仓库中指向旧云服务器的 dev/local 配置。服务仍可注册到本机 Nacos。正式构建不使用 desktop 模式；HTTP 开发站点只在可信内网访问。
