# 薪酬优化与 DEV 验收记录（2026-10-21）

## 结论与范围

本轮代码缺口已修复并在本地连接 DEV 的真实业务来源上验证。9 月 216 人试算中，185 人依据完整，31 人仍需资料核定；不能据此宣称全部员工已完成正式工资验收。10 月仅预核算，不生成工资。

员工、订单、到账和打卡使用现有业务数据；缺失薪资标准、试用期截止参数、指标权重及部分 HR 月度指标使用明确标记的 DEV 测试参数。测试标准不能当作已批准的正式薪资政策。

## 本轮修复

- 月度薪酬准备面板集中显示档案和规则缺口，支持筛选、逐人及批量只读试算。结果在同一面板展开，缺失金额显示待核定，保存前可核对明细。
- 已确认、已发放记录可只读试算，对比原快照与当前结果；预览不改原工资、确认状态或发放记录。锁定状态与权限边界由后端验证。
- 准备列表批量读取部门和规则，避免逐人重复查询。离职后结算提示与档案缺失分开显示。
- 总部按员工、月份填写完成率，与底薪、绩效、补贴、提成调整及扣款集中在“核定薪酬”。核定弹窗限制高度、正文滚动，操作区保持可见。
- 数值薪资维护支持总部人员；底薪八折只作用于底薪，绩效基数不打折。
- 首次导入或新建员工的初始任职起点使用已有入职时间；重新入职仍以重新任职时点开始，避免覆盖真实调动历史。
- 明确排除的商品分类及后代按不计提处理，不再误报缺少标准；另行配置的商品标准仍可适用，范围外的未知商品继续提示待核定。
- 城市回款与提成来源对历史导入归属采用一致判断：已有冻结归属优先；导入来源和原归属完整且无待复核快照时使用原归属。归属缺失、待复核记录继续阻断，不伪造归属。
- 新增 API 模型分别独立文件。DEV 辅助工具要求私有备份、指定 DEV 环境、版本检查和审计，避免覆盖已应用修复的备份。

## 页面实际走查

起点：正常登录 `http://localhost:5100/#/supply-chain/hr/payroll`，使用当前管理员账号。

1. 打开生成面板，筛选人员、跨筛选保留选择、逐人只读试算：通过。月人数与当前筛选人数分开显示。
2. 销售、城市总、见习城市总、总部各生成 1 条 9 月样例：通过，4 条均待确认，金额与试算一致。
3. 打开总部“核定薪酬”：个人完成率与金额调整集中显示，同部门其他人不受影响。
4. 实际修改个人完成率、底薪、补贴和扣款并保存重算：金额按预期变化；随后恢复原完成率和金额，临时覆盖及扣款已清除。
5. 核定弹窗适配当前视口，正文滚动、底部按钮固定；原始依据和待核定项可查看。
