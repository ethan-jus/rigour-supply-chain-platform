# 成本看板在线授权批读

## 请求与行为

原链路在每个费用接口先在线取得供应链访问身份，再分别请求看板和各来源／导出动作授权，管理员通常约 10 次 IAM HTTP。增加授权线程不能减少 IAM 重复计算和数据库占用。

新增内部 `GET /internal/v1/iam/supply/authorizations?actions=...&actions=...`：1—32 个动作，逐项校验编码与长度，重复请求动作去重。整个查询串沿用原用户、租户、会话及版本的 HMAC 签名，不接收正文指定的其他主体。

- IAM 在一次只读、可重复读事务内核验会话和资格，加载同一主体的权限、版本、绑定员工和已分配角色事实，再逐动作生成原有 `functionAllowed` 与完整角色子句。
- 管理员、普通用户 SELF／部门／自定义范围仍使用原解析规则。未分配角色不参与计算，找不到已分配角色时拒绝。角色事实只加载一次，保留原分配顺序；无权限动作返回拒绝策略。
- 员工事实只在本次授权计算复用，键包含租户用户和员工编码；计算结束即清除。后续请求重新读取，不使用跨请求授权缓存。
- HTTP 客户端与请求上下文验证完整动作集合、重复／缺失／额外动作、主体、ACTIVE 状态、功能许可与权限集合一致性，以及应用、成员、员工、组织四项版本。与本请求初始在线身份不一致即整体失败，全部验证通过后才写入单请求上下文。
- 批读失败、错误响应、超时或版本变化不降级成旧策略或放行。

成本看板将自身 READ 和来源／导出动作一起批读，通常变为初始访问身份 1 次加批策略 1 次 IAM HTTP。既有单动作 API 保留；批读及不支持批读的自定义客户端共用原有 8 线程、128 有界队列，未增加并发。批读只提交一个任务，deadline 同时覆盖排队和网络等待；超时或队列拒绝立即失败并取消任务，清理已取消队列项。即使底层读取晚返回，也不会发布策略或回退为已有权限。

该 deadline 只覆盖批策略预取；初始访问身份和其他 HTTP 调用仍受各自连接／读取超时配置约束，不将它解释为整个费用接口的统一 10 秒上限。

旧客户端的单动作懒读取和并发预取也与初始在线快照核对应用、成员、员工、组织四版本、员工编码和完整权限集合；任一事实变化立即拒绝，不缓存失败结果。并发预取只有全部动作验证通过后才发布，不能因首个动作成功而保留部分旧策略。

## 接入与验证

先启动新版 IAM，再启动包含新版 iam-client 的 BI；旧 IAM 没有批端点时批读会失败，不进行静默回退。本轮不涉及数据库迁移、Portal 或角色授权写入。

定向回归日志：本机 `/tmp/rigour-cost-live-review/iam-batch-final-tests.log`。覆盖：

- 单动作与批动作逐项结果一致；普通用户 SELF／部门范围、未分配角色排除；每批公共事实一次读取。
- 不同租户／用户的员工及角色隔离；后续请求权限撤销、会话失效与员工事实变化可见。
- 批响应缺失、重复、错误主体、错误动作、错误模式、四项版本变化、功能标记矛盾全部拒绝，失败批不发布部分策略。
- 真实隔离 HTTP 请求的查询串与原用户会话签名；错误结果与 HTTP 503 不额外请求单动作端点。
- 成本入口将 READ 纳入一次批读、下一请求移除薪酬权限后不复用；原单动作／有界并发兼容回归及成本金额回归。
- 旧客户端懒读与并发预取的四版本、员工编码及权限集合变化拒绝；失败批无部分缓存。慢批读取、排队超时清理、满队列拒绝及晚返回不发布已加入定向回归，日志 `/tmp/rigour-cost-live-review/iam-fallback-consistency-tests.log`。

上述隔离测试和编译不能代替 DEV 并发性能、真实角色撤权与页面联调。服务由主任务统一重启并复测，实际 HTTP 数量、P95 和剩余瓶颈以新的 DEV 运行证据为准。
