# 运输成本和成本看板计算规则及审查记录

核对日期：2026-11-17，提交范围核对更新至 2026-11-18。适用现有 Order、Integration、BI、IAM 和 Portal 实现。本文描述当前规则，并把建议与已实现行为分开，供业务负责人核对成本是否符合实际管理需要。金额单位均为人民币元。

## 1 业务入口和数据流

| 场景 | 保存路径 | 业务需要处理的内容 |
| --- | --- | --- |
| 货拉拉 | Integration 拉取列表和企业详情，保留原始返回；已完成订单在 Order 中生成或更新运输记录 | 从销售订单选择已有运输记录，或在运输记录关联业务订单；平台账单和原始备注只读 |
| 订货宝 | 完整保存发货资料；有快递单号时生成或复用运输成本记录 | 缺运费时在运输记录编辑，或使用 Excel 批量补录；缺销售单、员工、地区等资料时在对应档案入口维护 |
| 手工录入 | 销售订单选择物流后新建，或在运输记录新建，保存到同一台账 | 填写实际配送信息、运费、付款状态和凭证；从销售订单发起时带入订单、人员和收货信息，运输类型为销售订单配送 |

同一运输可以关联多张销售单，同一销售单可以关联多次运输。关联已有运输只建立关系及分摊，不再增加一笔运费。物流关联不替代原销售单的发货、库存和资金流程，不回写客户档案。

Integration 负责三方请求、授权和附件归档；Order 负责运输记录、订单关系、运费和附件权限；BI 通过版本化的 analytics-source 接口取得投影，不跨库修改原单。人工上传和平台附件都归档到自有 COS。查看、下载通过业务权限接口读取，不把临时签名地址当成永久文件地址。

## 2 运输费用怎样计算

### 2.1 手工账单

没有费用明细时，可以直接填写运输费用总额。有明细时：

`运输费用总额 = 所有费用项目金额之和 − 优惠及减免`

优惠、减免、抵扣、折扣统一作为扣减。填写正数优惠 5 元与历史保存的负数优惠 −5 元，均只扣减一次。金额未填完整时保持未知，不自动补成零。

例如基础运费 67.25、附加费 10、优惠 5，总额为 72.25。前端按分汇总，后端用十进制金额重新校验，不能依靠页面展示的合计绕过保存校验。

有明细时仍可以直接修改总额，按已确认的操作规则只调整第一项基础运费，其他费用和优惠保留：

`新基础运费 = 新总额 − 其他费用的净额`

如果没有基础运费，自动增加一项基础运费。其余费用有未填金额，或计算后基础运费为负数，阻止本次调整并提示核对明细。不会静默清空已有项目。只有总额时不强制用户拆分。

### 2.2 货拉拉账单

保留企业详情原始金额、已支付、未支付、退款、优惠、赠金和费用明细，不把已支付金额直接等同于所有情况下的运费。

当前接入兼容已验证的两类返回：

1. 平台总计已经扣除优惠：直接使用平台净额，不再减一次优惠。
2. 平台返回的原始总计尚未扣优惠：只有在总计减优惠等于已付加未付、所有费用项目金额完整且明细合计也能核平时，采用核平后的净额。

例如原始总计 65.31、优惠 10、已支付 55.31、未支付 0，且明细为 65.31 和 −10 时，运输费用采用 55.31。原始总计仍保留供追溯。退款、赠金或未明确的费用不能靠推测凑平，继续沿用既有核对规则。

平台费用、付款状态和明细只读，付款状态来自货拉拉企业接口。未返回的值显示“−”或对应的未记录状态，不猜成已付款。平台账单用于解释同一笔运输费用，不能再次求和到成本台账中。

### 2.3 订货宝运费和 Excel 补录

发货商品金额不代表运费。接口没有明确运费时，运输金额为空并处于待完善；业务可以直接编辑这笔运输记录。

Excel 必填快递单号、运费；物流公司可用于缩小匹配范围。只匹配已有、可编辑且运费未填的记录，不通过导入创建运输。文件内重复单号、没有匹配、多个匹配、已作废或已填金额均不直接覆盖。零元运费需要说明。

上传原文件独立归档，每笔费用凭证仅包含本笔明细，避免在一笔运输中暴露整份其他记录。重复提交依据文件和单据的处理结果识别已补录，不能重复新增费用或覆盖业务后来修改的运费。

### 2.4 多单分摊

普通销售关联按所选订单等分，按分处理尾差。例如 10 元分给三单为 3.34、3.33、3.33，合计仍为 10 元。高级分摊沿用已有平均、按订单金额、数量或手工规则及校验；非成本追溯关系不参与分摊。

`每笔运输的分摊总额 = 本笔公司承担的运输费用`

不能因为关联了三张销售单，就在看板中把整笔运费重复计算三次。销售订单的“本单分摊费用”反映该单承担的份额；“计入运输成本”只累计资料已完善的有效份额，两者在资料未完善时可以不同。

## 3 单据状态和操作

| 状态 | 判断 | 允许操作 |
| --- | --- | --- |
| 待完善 | 运费、业务订单、业务员或部门未补齐；手工记录还没有成功保存的凭证 | 查看、编辑、作废 |
| 已完善 | 金额已知、存在有效业务订单关系，参与成本分摊的关联均有员工和部门；手工单至少有一份成功保存的凭证 | 查看、编辑、作废 |
| 已作废 | 已执行作废 | 查看、删除 |

状态自动判断，没有额外手工确认按钮。已完善仍可编辑，编辑后按当前资料重新判断。付款与资料完善是不同含义：未付款不等于待完善，已付款也不能代替订单和人员归属。

平台同步、订货宝来源记录可作为来源依据，不强制业务重新上传同一套来源附件；手工记录的附件必须上传成功后才满足凭证要求。来源返回为空、历史信息不完整不伪造值。

销售订单“选择物流”及“物流发货”只使用有效运输，排除已作废记录；这里不重复展示成本单据状态。运输记录详情只读，新增、编辑、关联、作废保留在各自业务入口并按权限控制。

## 4 同步和重复处理

- 货拉拉只把已完成订单生成运输记录，列表和详情按同一平台订单标识更新；明细或附件失败可以重试，成功归档的文件复用，不重复上传计费。
- 订货宝按来源发货标识和快递单号维护原运输关系；有物流单号才生成运输成本，没有单号仍保留发货原文。
- 业务补录或修改的运费受到人工修改标识保护，后续来源变化不静默覆盖。来源原文、运输资料和本系统业务字段分别更新。
- 销售原单、客户、员工或地区存在歧义时由业务核对，系统不凭同名自动合并。业务补齐后由原同步计划复查原单，继续使用原记录及关系。
- 当前订货宝自动计划最终间隔为 60 分钟；是否全部处理完成以各项结果为准，不能把“扫描结束”理解为所有缺资料记录已成功。

## 5 列表查询和页面展示

运输主列表以费用单号、快递单号、物流公司、车型、下单／发货时间、路线、收货点数、运输类型、费用和单据状态为摘要。货拉拉用原始下单时间，订货宝及手工单用发货时间；全局倒序后分页，并以稳定次序处理同一时刻，不能只对当前页排序。

完整路线、联系人、费用分项、付款信息、回单、装卸照片、原始备注和变更记录放在详情。空备注显示“−”，平台原文只读。附件统一分类展示，平台和手工文件通过来源标识区分，不再显示两套同类空区域。

销售选物流先在服务端限制有效、允许销售关联的运输，再按物流公司、快递单号、下单员工、收货地址、日期及已有销售关联筛选、计数和分页。收货查询覆盖中途及最终收货点；命中中途点时在路线摘要明确展示命中地点。

布局随容器宽度换行，表格首尾固定，列内容需要空间时在表格内横向滚动。金额输入提示使用正常表单字号，不使用金额看板的大字样式。查看页面无编辑、作废等写操作。

## 6 成本看板当前统计规则

### 6.1 来源和分类

| 类别 | 当前事实来源和范围 |
| --- | --- |
| 物流运输 | Order 运输记录，公司承担、资料已完善的有效金额 |
| 采购成本 | ERP 已确认采购货款及采购实际运费，分项展示 |
| 商品损耗 | ERP 已确认损耗金额，单独展示 |
| 仓储、办公、营销 | ERP 成本台账或对应的 HR 报销事实，按来源类别分组 |
| 人力薪酬 | HR 已确认薪酬事实，沿用来源核定金额 |
| 员工报销 | HR 已确认报销，差旅、住宿、打车等仍归报销费用 |

经营费用合计为物流、仓储、办公、营销、人力薪酬、员工报销及尚未分类的场地费用的有效金额之和。采购、损耗各自单列，不把三项简单相加称为利润或全部经营支出。报销关联原成本但尚未核实抵销时，保留核对，不能与原成本重复计入；固定资产也不直接按全额经营费用统计。

历史采购约定运费只追溯，实际采购运费以 ERP 采购成本核实为准，避免与运输台账重复。

### 6.2 生效条件和范围

BI 事实需同时满足来源确认状态、金额已知、直接计入规则及当前权限范围。Order 的已完善投影为 BI 可统计状态；待完善、作废及被删除记录不能进入正常合计、图表、明细或导出。

本轮将待完善运输笔数单独展示，并提供原运输列表入口；该笔数不与金额求和。来源缺金额不是零元成本。无已确认记录时金额显示 0，并说明没有已确认记录，不代表公司没有实际支出。

城市和部门按来源明确归属以及现有 HR、CRM 对应关系解析，冲突或歧义保留待归属，不按名称猜城市。统计范围取看板授权与原单权限交集，导出还校验独立导出权限。

### 6.3 时间

当前源码将带有台账分区且填写费用所属月的事实按月统计；薪酬、租金及指定周期费用也按所属月统计。按月事实在所属月份整体计入，不按本月已经过的天数摊销。其他事实按费用日期。

因此运输记录展示的具体发货时间与费用看板的所属月可以同时存在，它们不是同一个字段。当前月从月初至数据截止日，对比上月相同已过天数；短月取月末。历史月按完整自然月对比完整自然月，全年使用同比，未来期间不允许查询。

### 6.4 公式和精度

| 指标 | 公式 |
| --- | --- |
| 类别或城市金额 | 对满足条件的金额求和 |
| 单据笔数 | 按原单据标识去重，不按照片或分摊行计数 |
| 变动额 | 本期金额 − 可比期金额 |
| 增幅 | 变动额 ÷ 可比期金额 × 100%；分母为零时不生成百分比 |
| 类别占比 | 类别金额 ÷ 当前范围总金额 × 100%；分母为零时不生成比例 |
| 增加或减少贡献 | 单项同方向变动 ÷ 全部同方向变动 |
| 未付款金额 | 当前统计集合中明确为未付款的单据金额；未记录付款状态不猜成未付款 |

服务端金额使用 BigDecimal，两位小数四舍五入，比例一位小数。前端图表坐标可用数值，但表格与导出使用接口金额。同一查询使用同一已发布快照，后续来源作废、撤销或权限变化还需用当前可见集合核验，不能把旧事实继续当作有效。

## 7 产品审查结论和建议

| 发现的问题 | 本轮处理或建议 |
| --- | --- |
| 总额有明细后不能输入，优惠正数被加上 | 已统一扣减并允许总额调整基础运费；新增、编辑、详情使用相同账单结构 |
| 平台原始总计和实际净额混用 | 在金额及费用明细能相互核平时识别净额；保留原始总计，不能重复扣优惠 |
| 详情有编辑、作废，附件有重复区域 | 已移除详情写操作，凭证统一分类及来源、时间展示 |
| 查询命中中途收货点，但摘要只显示终点 | 已增加命中地点展示，并在服务端先过滤再分页 |
| 低金额和大幅下降容易被误读为降本 | 已突出待完善笔数及无确认记录说明；经营者应先看资料完整度，再判断费用下降，不能把登记缺口当节省 |
| 费用日期与所属月容易混淆 | 当前按月规则保持原业务实现，页面按所属月标识；建议业务再确认物流是否应按实际发货日统计，本轮未擅自改变历史结算期间 |
| 未付款合计不等于应付余额 | 保留现有付款状态口径；如需部分付款的准确应付余额，应另定义付款分录和未付余额指标，不能用整笔费用代替 |
| 经营费用不是利润 | 页面采购和损耗单列；暂无完整销售成本、税费及折旧口径，不能从本看板推导净利润 |
| 权限只有菜单可见性，动作不清晰 | 查看、新增编辑及关联、作废、删除已作废单据、导出分别配置；原手工确认入口停用，后端同样校验动作权限 |
