# CRM / Sales / Order / Integration 服务边界

本轮范围：DEV 改造与联调；保留现有数据、已执行迁移和 24 小时 / 7 天 / 60 天保护、48 小时本人冷却规则。不得发布生产或建立历史客户档案映射。

## 唯一业务归属

| 领域 | 权威服务 | 工作端读取方式 |
| --- | --- | --- |
| 门店主档、公私海、负责人、认领释放、客户地域与归属范围 | CRM（IAM 提供身份和功能授权，HR 提供员工组织） | Sales 工作端调用 CRM，不再独立扩大客户范围 |
| 客户拜访政策、正式拜访、有效性、保护期限 | CRM | Sales 获取 CRM 受理和政策快照，采集证据；CRM 决定有效性 |
| 工作日、考勤、现场照片录音及技术校验 | Sales | 本人 / 管理范围查询；客户和归属使用 CRM store_id / ownership_id |
| 订单、订单状态、制单人与业务员历史归因 | Order | Sales 是操作和查询入口；Order 后端校验权限，禁止前端 employeeId 扩权 |
| 高德服务端搜索、详情、逆地理编码、Key | Integration | CRM / Sales 通过签名内部 API 调用；底图 JS Key 独立 |

公海是公司资源，“我的公海”指 CRM 授权可见的公海，不是个人所有权。客户转交后不能改写历史拜访人、制单人和订单销售归因。

## Sales 工作端的数据来源

| 工作端内容 | 查询口径 |
| --- | --- |
| 可领取公海 | CRM 返回当前用户地区权限内、未被认领且可作业的门店；城市过滤不能扩大服务端授权 |
| 我的客户 / 合作客户 | CRM 返回本人当前归属及合作状态；负责人查看团队时仍由 CRM 校验范围 |
| 我的拜访 | Sales 保存本人采集、上传、离店过程；正式拜访状态及有效性以 CRM 为准 |
| 客户历史拜访 | 按 CRM 的门店历史查看权限读取，保留前任业务员记录与原始归因 |
| 我的订单 / 客户订单 | 由 Order 校验查询权限；业务员归因与实际制单人分开保存，不能随客户转交改写 |

Sales 不建立第二套客户主档或独立公私海权限。现有新门店“我的客户”页面读取 CRM，采集入口调用 Sales；完整工作端订单页面仍需后续实现。旧 Sales / 临时打卡数据及接口在历史迁移前保留，不将其当作新门店归属的权威来源。

## 同步和故障边界

- 业务提交与待投递结果在源服务事务内持久化；后台重试，不在用户请求中等待 CRM 回调 Sales。
- CRM 接收租户、门店、归属周期、采集标识、政策版本和单调版本；重复或旧版本不重复生效，人工核验不被自动结果覆盖。
- 成交、取消、作废等由 Order 同步；CRM 保存查询和生命周期所需事实，不成为第二个订单编辑源。
- 本地生命周期计算不调用 Sales 或 Order。仅对明确有未决拜访 / 订单受理的周期暂缓回收，不能把未收到结果当成未成交。
- Sales 停止不影响 CRM 查询、手动维护、认领释放和已确认事实的保护计算；Integration 可用时高德入库与补全不依赖 Sales。
- 历史政策、在途采集和已关联订单须完成初始化核对；不静默改变政策阈值或新旧 ID。

## 验收目标

1. 高德适配器仅存在于 Integration；Sales 和 CRM 不持有 Web 服务 Key。
2. CRM 签到不再回调 Sales；规则和最后有效判定归 CRM。
3. 在 CRM 暂停时保存 Sales 证据 / Order 结果，恢复后重试；重复、乱序、跨租户请求验证。
4. 24 小时首访、7 天跟进、本轮成交 60 天、释放后本人 48 小时冷却保持。
5. Sales 停止时，DEV 公海、私海、维护、认领释放与地图查询正常。
6. 工作端的客户数据与权限来自 CRM；本人订单 / 拜访查询在后端限制，不能通过改查询参数读取他人。
