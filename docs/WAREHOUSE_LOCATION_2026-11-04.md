# 仓库所在地与业务归属

## 本次范围

- “所在地区”表示仓库实际地址省市区；“业务归属地区”沿用 `region_code`，仍用于客户地区与库存履约关联。所在地不自动改写业务归属，也不据名称推定成本城市。
- 复用 Foundation 已发布的行政区划目录，在现有 `erp_inventory_warehouse` 增加 `location_area_code`（区县编码）与 `location_area_version`（目录版本）两个可空字段，不新增业务表、不保存省市区名称。
- ERP 列表、详情返回按目录版本解析的 `locationDisplay`；编辑可搜索省、市、区县并选择完整区县路径。历史目录按原版本解析，目录暂不可用时保留编码及明确提示。
- 行政目录通过 ERP 自身的仓库读取权限入口访问，再由签名 SERVICE 调用 Foundation；不要求仓库经办拥有 IAM 系统设置权限，不跨库查询。

## 同步事实与限制

2026-11-04 只读检查 Integration 保存的最近仓库原始回执，字段包括 `stock_id`、`stock_num`、`stock_name`、`address`、`phone` 等，检查的回执未包含省、市、区字段。订货宝后台截图存在省市区，不能据此假定 `getStockInfo` 已提供相同字段。当前实现支持人工维护，未添加猜测的第三方字段或后台私有接口，也未宣称自动补齐成功。

仓库基础资料同步原来将 `region_code` 设为空；现已移除此赋值。同步更新名称、地址等基础资料时保留已有业务归属和所在地。人工更新整张仓库档案后，继续遵守既有的人工维护保护规则。

后续自动同步必须先取得可核验的来源字段契约，按租户、连接器和仓库来源绑定定位记录，再核对行政目录编码与版本。缺失或不明确的省市区保留待维护状态，不能按仓库名、地址文本或同名城市自动认定；人工归属不被覆盖。

## 保存兼容

- 新建：所在地可为空；选择后区县编码与版本须成对提供，并由服务端核验已发布目录与区县层级。
- 编辑：所在地字段均未传入表示旧客户端请求，保留原值；`locationAreaCode=""` 且版本为空表示用户主动清空所在地。
- 清空所在地不影响 `region_code`。更新保持原租户、仓库权限和 `revision` 校验。
- 迁移为 ERP V44，须由现有 ERP 运行项启动应用；不改写已有 V/B 脚本，不新增 Flyway 过滤。

## 物流保存前维护提示

- 物流及仓储页面保存前重新读取所选仓库主档。缺少业务归属地区时明确提示仓库名称、编码及待维护字段，并提供新页面打开的“仓库信息维护”入口；当前表单和附件草稿保留。
- 补齐后再次点击保存，重新检查主档，不使用先前的缺失结果。主档加载失败、无权限或不在可用费用城市范围时停止保存，不能当作已维护。页面切换后迟到的检查结果不提交旧单据。
- 所在地区仅用于实际地址展示，物流成本依赖业务归属地区；填了省市区不能替代成本归属。
- Order 的物流服务在保存及确认时也检查仓库业务归属缺失、运输城市不一致及授权城市，避免绕过页面；不扩大租户、城市或仓库数据范围。
