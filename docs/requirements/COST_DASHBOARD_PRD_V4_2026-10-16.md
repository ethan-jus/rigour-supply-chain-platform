# 成本数据看板产品方案

版本 V4　日期 2026-10-16　面向经营负责人 CEO 老板

本方案把成本看板定位为经营费用复盘工具：管理层先判断本期费用发生了什么变化，再确定值得优先查看的城市和费用事项，最后拿到对应单据核实。产品主线为经营简报、费用分析、支出明细。系统继续在原成本和报销模块录入，本看板负责读取、比较和追溯。

## 01 产品定位和事实边界

已确认：主要用户为经营负责人、CEO、老板；费用由系统现有模块录入；看板要清楚表达对比、占比和支出；视觉需延续销售业绩、城市经营看板。用户本次要求从产品经理维度重新设计。

设计判断：上一版提供了较多分析功能，但经营费用、采购、损耗及专题入口权重接近，管理层仍要自己决定先看什么、把哪些图组合起来。V4将“本期优先复盘哪些支出”作为主要任务，指标、图表和下钻都围绕这个任务组织。

工作假设：使用场景以经营例会前准备、会上追问和会后核实为主，默认当月累计查看。具体会议频率、真实关注事项、允许波动范围尚未通过访谈确认。这些假设支持先做可评审原型，不视作已经得到业务批准的规则。

产品目标是让使用者看清变化并找到证据。当前无法核验真实费用是否录全、经济事项是否重复，也没有完整预算、付款流水、成本结转与营销归因，因此不承诺自动识别浪费、节约金额或利润。

首版默认聚焦已确认经营费用。采购和损耗保留独立分析入口。工资模块确实存在，但其归属月、薪资可见范围和计入方式需要另定，本期不纳入。未计入范围必须明确，不能把当前合计命名为公司全部成本。

## 02 用户场景和需要完成的判断

老板与经营负责人共用一个产品入口，通过授权范围决定所见数据；首版不增加三个内容重复的角色首页。财务或业务经办人作为协作核实角色，其日常录入和更正仍使用原系统。

| 使用场景 | 用户需要完成的判断 | 产品提供的下一步 |
| --- | --- | --- |
| 老板快速查看 | 本期费用是多少，比上期增加还是减少，主要变化在哪里 | 首页显示一个主要金额、可比差额和前三个变化事项 |
| 经营负责人准备复盘 | 哪个城市哪类费用的变化值得先核实 | 按城市与费用项的绝对差额排序，查看构成和单据 |
| 例会上被追问 | 某项多出的金额对应哪些支出，上期是什么情况 | 同条件切换本期与可比期，比较对应记录 |
| 业务会后核实 | 变化来自业务活动、集中登记还是归属有误 | 提供待核实问题及证据，不替业务确定原因 |
| 查看其他成本 | 采购集中在哪些供应商，损耗登记在什么商品和原因 | 独立分析范围下拆解对象，避免混算经营费用 |

示例任务：负责人看到“成都营销费用增加”→打开变化卡片→看到本期、上期、差额及待核实问题→查看本期单据和上期单据→到原业务流程核实活动或服务期间。老板无需先理解数据库或菜单分类。

本期在看板内完成发现、比较、定位和取证。任务派发、负责人认领、原因填报、整改跟踪不是已有能力，本期不伪装为可用按钮，也不自动发送消息。后续若需要管理闭环，应另行确定参与角色、状态、权限和通知规则。

## 03 信息架构和功能取舍

沿用现有成本看板入口 /supply-chain/bi/city-cost 及权限标识 supply.bi.city-cost。保留系统双层导航、白色页签、深色内容区、蓝色主色和期间选择习惯，改变内容权重与使用顺序。

| 层级 | 用户任务 | 内容和进入方式 |
| --- | --- | --- |
| 经营简报 | 看清整体变化并确定先查什么 | 默认首页，一个主要费用合计、变化事项、累计对比、费用构成 |
| 费用分析 | 进一步解释差异分布 | 城市对比、费用构成、支出对象三种视角；按需切换采购或损耗 |
| 支出明细 | 核对事实和原始来源 | 精确筛选、当前及可比期、单据详情、导出 |
| 变化复盘抽屉 | 不离开当前页面先判断是否需要深查 | 已知事实、业务待核实问题、主要单据、两期完整明细入口 |

首页不再将采购、损耗作为与经营费用同权重的三张大卡。它们位于“其他成本记录”，可一键进入对应范围。七类专题收进“费用分析—支出对象”，避免老板面对七个并列入口再判断选哪个。

未付款标记、待确认、未归属信息仍可查看，放在首页补充区。权限不足或数据读取失败会影响判断，必须在页面显著提示，不能折叠隐藏。技术来源、版本与源键放入单据展开区。

页面标题使用业务语言；金额和占比同时表达；不使用未经批准的红线、健康分、节省潜力或智能诊断标签。增加和减少都可能有合理原因，颜色仅表达系列或方向。

## 04 经营简报页面规格

全局筛选为年份、月份或全年、授权城市、对比方式。顶部展示两期实际日期和币种。默认当月截至共同可用日；生产截止日由有效数据范围决定，不能直接取浏览器当天。原型固定截至2026-10-16。

| 区块 | 展示规则 | 点击行为 |
| --- | --- | --- |
| 费用概况 | 经营费用合计；可比期金额；变化金额及增幅；确认记录数 | 查看完整分析，保留期间和城市 |
| 本期费用概况句 | 只组合经计算的事实：金额增减与最大费用类别占比 | 不生成原因或节约结论 |
| 优先查看哪些变化 | 默认前三个增加项，可切换前三个减少项；每项为城市与费用类别交叉单元 | 打开变化复盘抽屉 |
| 累计费用对比 | 两条线按月内日序对齐，显示各自实际截止日；全年按月累计 | 查看当前经营费用完整明细 |
| 钱主要花在哪些方面 | 费用类别排序条形、精确金额、占比；保留未分类金额 | 类别到城市再到单据 |
| 其他成本记录 | 采购和损耗独立金额及入口 | 进入对应范围的费用分析 |
| 补充信息 | 当前付款标记、待确认记录、待归属金额及各自解释 | 查看对应集合 |

概况和优先查看位于首个阅读区域；图表用于验证概况，不用大量卡片分散注意力。首屏不是必须塞下所有信息。较窄设备纵向展开，城市矩阵和单据表在自身容器横向滚动。

累计曲线按 cost_date 逐日汇总后累计，不能解释为实际付款或录入节奏。两期不等长时保留实际终点；当前月使用等长同期，历史完整月保留自然月天数差异。没有可比期不绘制假的零线，也不生成增长结论。

全局筛选后金额、排序、图表和明细同步更新。进入明细必须保留业务条件；清除条件由用户明确操作，不能静默扩大范围。无记录、合法零值、金额未填分别处理。

## 05 变化复盘和证据路径

把所有已确认经营费用按“城市×费用类别”拆成互斥单元。对每个单元计算本期减可比期差额。默认按正差额从大到小显示前3项；切换减少后按负差额绝对值从大到小显示前3项。这是优先查看顺序，不是异常检测。

各项增加 = 所有正差额之和。各项减少 = 所有负差额绝对值之和。净变化 = 各项增加 − 各项减少，并且必须等于经营费用总额差。增加卡片占比 = 该项增加额 ÷ 全部增加额；减少卡片使用全部减少额。不能除以可能很小或为零的净变化，也不能把城市差额与类别差额重复相加。

演示数据中，各项增加33,177.09元、各项减少27,697.38元，净增加5,479.71元。待归属仓储费用增加9,345.60元，占全部增加28.2%。这些数值仅用于原型校验，不是实际经营结果。

| 抽屉内容 | 产品规则 |
| --- | --- |
| 已知事实 | 显示明确两期范围、本期与上期金额、记录数、差额和增幅 |
| 待核实问题 | 按费用类型提供核实方向，注明发生原因尚未确认 |
| 待归属情况 | 优先提示核实城市归属，不默认归总部或某一城市 |
| 主要支出 | 显示本期金额最高8笔，可查看详情；完整集合不受8笔限制 |
| 两期证据入口 | 本期与可比期分别进入完整明细，保留城市、类别、权限 |

核实提示举例：营销费用需核实活动、渠道和服务期间；场地费用需核实合同与集中登记；办公费用还需核对租赁报销是否重复；运费需核实运输次数与承担范围。没有数量或执行证据时，不判断单价上涨、浪费或违规。

可比数据缺失或读取覆盖不完整时，停止生成变化排序。完整读取范围中某组没有记录可作为该组登记金额为零；全期数据缺失不能作为零。读取完整也不意味着业务已经录全，页面始终称已登记或已确认费用。

## 06 深入分析和其他成本

费用分析提供城市对比、费用构成、支出对象三种视角。默认保留进入时的期间、城市和范围。经营简报始终回到经营费用；采购和损耗不改变首页的产品主线。

城市对比以“城市×费用类别”矩阵为主，切换金额、城内占比、差额。点击交叉格直接取证。辅助城市条形图使用同一刻度，不能把大城市支出高简单解释为效率差。

经营规模参照沿用V3的条件：经营费用÷同期销售订单应收金额×100，展示每100元交易额对应已登记费用。仅在城市、期间、权限和数据覆盖可对齐时出现；它不是利润率，也不设行业标准。待归属费用保留并显示排除金额。

| 分析对象 | 系统现有可用维度 | 能回答的问题 |
| --- | --- | --- |
| 运费 | 运输环节 承运方 运输方式 | 费用分布在哪段运输和哪些承运方 |
| 仓储和办公 | 仓库或场地名称 合同快照 | 哪些场地登记费用较多 |
| 营销 | 费用类型 渠道 经办员工 | 投放费用集中在哪里 |
| 报销 | 类型 员工编码 部门编码 | 哪类事项和人员登记了报销 |
| 采购 | 供应商 商品规格 | 采购登记额集中在哪些供应商和商品 |
| 损耗 | 商品规格 损耗原因 | 哪些商品记录了损耗及所填原因 |

同名不同ID不合并，手填名称与正式主档分开。缺少维度的金额保留“未记录”组及金额覆盖提示。不能把不同单位商品计算成一个平均单价，也不能根据经办部门把所有费用自动分摊成部门成本。

对象分析支持金额、占比、变化、记录数、当前付款标记、走势和完整明细。没有营销效果、运输计价数量或可比库存基数时，首版不计算ROI、每单配送成本、损耗率等效率指标。

## 07 指标和数据来源

主要观察指标为已确认经营费用和同范围期间差额。城市费用项贡献与类别占比用于解释变化；付款标记与待确认是辅助核实数据。首版不建立公司降本目标，不把原型金额当基线。

| 指标或规则 | 定义及来源 | 重要限制 |
| --- | --- | --- |
| 经营费用 | ERP仓储 办公 营销 待分类场地；Order公司承担运费；HR报销 | CONFIRMED且金额非空；报销不能再加一次 |
| 采购与损耗 | ERP成本台账PURCHASE和LOSS分别合计 | 不叠加采购订单，不等于销售成本 |
| 日期 | 各源cost_date或costDate | 不用创建日期替代，不按租期自动摊销 |
| 期间对比 | 当前月同期；历史完整月环比；同比对应年同区间；全年同截止日 | 闰年及月底裁剪，明确实际区间 |
| 增幅 | 差额除以可比期金额 | 零基数标注上期为零；缺历史不计算 |
| 金额占比 | 分组金额除以当前确认集合总额 | 金额零时不计算；展示舍入允许99.9%等 |
| 唯一粒度 | 租户 源服务 源表 源ID对应一条费用记录 | 多订单 多配送点 多附件不能倍增金额 |
| 未付款 | 同一确认集合中UNPAID | 付款状态快照，不是实付流水或到期时间 |

数据模型具备相应字段，不代表真实记录已经填全。本次核对了Portal费用路由及沿用本任务源码核验结果；没有连接业务数据库测量完整率、更新时间或真实金额。

来源归属：ERP为erp_cost_entry；Order为order_logistics_cost；HR为hr_expense。现有BI销售参照为bi_sales_order_fact.payable_amount，按order_date排除删除和取消订单。费用城市与经营城市须明确映射，不依靠模糊名称猜测。

金额使用整数分或BigDecimal；展示两位小数。VOID、非公司承担运费不计入；押金仅详情单列；疑似跨台账重复只提示待核实，不自动扣减。生产数据变更后两期均重算，界面显示批次和更新时间。

## 08 状态和权限设计

| 情况 | 用户看到什么 | 处理规则 |
| --- | --- | --- |
| 正常读取 | 同批次费用概况与图表，明确截止范围 | 全部组件和下钻使用相同版本 |
| 读取中 | 保留筛选；显示加载状态 | 不把旧金额伪装成新筛选结果 |
| 没有本期记录 | 当前范围没有已登记数据 | 不用零费用图或正常经营标签填充 |
| 无可比记录 | 本期可看；差额 增幅 排序显示暂无可比 | 不作零基数增长解释 |
| 报销无权限 | 明示经营费用不含报销，专题不露金额或人员 | 汇总 明细 导出 原单跳转一致鉴权 |
| 读取失败 | 保留上次同范围完整快照并明确提示 | 无可用快照则显示失败；不部分拼接 |
| 待确认或缺金额 | 仅在补充区给金额和笔数 | 不进入确认费用、排序或占比 |
| 待归属城市 | 合计和变化中保留待归属组 | 不进入具体城市的规模参照 |

老板角色不能自动绕过权限。角色名称、城市范围、报销和薪资权限必须分别处理。订单若只有部分人员数据权限，不得和全城市费用计算经营规模参照。

明细导出为全部匹配记录，不能只导出当前页；保留两期标识、筛选条件、口径版本、数据版本和原始来源。可见列最小化，技术源键放在明细来源区。正式单据跳转由原业务页面再次鉴权；原型仅展示详情，不模拟修改成功。

刷新涉及多个来源时，以全部必需来源成功的共同快照对外服务；缺一来源不生成貌似完整的简报。当前原型模拟无数据、报销不可见和读取失败，正式异步加载与服务端鉴权仍需开发。

## 09 首版范围和实现路径

| 优先级 | 能力 | 本版处理 |
| --- | --- | --- |
| P0 | 简报概况 期间对比 变化排序 累计趋势 构成 | 默认产品主线；必须统一集合和可比规则 |
| P0 | 城市费用交叉 支出对象 两期明细 导出 | 完成发现到证据的查询链路 |
| P0 | 权限 来源状态 归属缺失 版本及来源追溯 | 作为可信使用前提，不因界面简化而省略 |
| P0有条件 | 每100元交易额对应已登记费用 | 两侧口径、映射、权限和覆盖满足后显示 |
| 后续评估 | 工资纳入 预算对比 阈值提醒 解释与处理记录 | 先明确业务规则和必要数据，再另定需求 |
| 当前不做 | 自动分摊结转 支付核销 利润 现金流 自动派单 | 本系统当前成本台账能力不足或超出本期任务 |

业务输入不变。ERP、Order、HR继续分别拥有写入职责；新增内部analytics-source成本数据集，通过既有版本化分页读取模式进入BI本地读模型，再由BI接口提供概况、变化项、分组、趋势、明细。Portal只负责展示与交互，不能跨库查询或自行拼出权限不一致的总额。

建议新增产品查询契约为brief、changes、breakdown、trend、records，并统一携带scope、城市、两期、口径版本、快照版本、授权范围。它们是本方案拟新增的能力，不是已经可调用的接口。records必须支持本期与可比期以及完整筛选导出。

接入需先解决文本UUID游标、稳定变更版本、城市映射和多源快照一致性；当前guard版本不可未经核实当成完整变更版本。生产实现仍遵循interfaces→application→domain，基础设施实现端口，跨服务使用既有Nacos服务名与签名链路，不引入跨业务库SQL。

数据库变更若必要，仅新增迁移，保留已发布脚本和校验；先核对有效Nacos配置。DEV/local启动可能运行共享库Flyway，本轮不以启动服务作为只读验证。实现顺序为口径与权限契约→来源读取→BI聚合与核平→页面联动→真实数据验收。

## 10 验收方式和试用目标

功能验收关注用户是否能完成判断与取证，不以图表数量衡量完成度。以下操作应在同一筛选范围内完成，汇总和明细金额一致。

| 编号 | 业务验收任务 | 通过条件 |
| --- | --- | --- |
| A01 | 说出本期费用与变化 | 能指出金额、实际两期日期和增减，不误读为利润 |
| A02 | 找出优先复盘事项 | 能识别城市与类别、差额、增加或减少的贡献分母 |
| A03 | 核实变化 | 从卡片进入证据，再查本期与上期单据，条件不丢失 |
| A04 | 核对构成 | 类别金额合计等于总额；点击类别再点城市仍保留条件 |
| A05 | 查看采购或损耗 | 进入独立范围；返回简报恢复经营费用 |
| A06 | 导出证据 | 全部匹配记录的金额与页面一致，来源标识保留 |
| A07 | 识别不确定信息 | 能区分已知金额、待核实原因、无历史和待归属 |
| A08 | 权限与失败 | 不露无权数据，不把缺源或旧快照表述为完整新结果 |

建议组织老板或CEO代表、经营负责人及核实人员进行任务式试用。暂定设计目标：首次打开后30秒内说出费用规模和方向，3分钟内独立定位一个变化项的两期证据。这是拟验证的可用性目标，尚无试用结果，不能写成产品已达到的效果。

记录任务是否独立完成、耗时、错误口径解读及中断位置。核心验收是能完成A01至A08，尤其不把登记费用误认为真实现金流或利润。后续若加埋点，只记录必要操作事件、筛选类型及成功状态，不采集敏感单据正文。

上线前还需实际业务样本核验：三个来源各取确认、待确认、作废、空金额、外部来源、城市缺失和多源关联案例，验证汇总、删除更正同步、权限和分页导出。真实基线、目标阈值和使用节奏待试用收集，本轮设计不依赖这些未确认信息才能交付。
