# 成本数据看板需求与实现方案

版本 V2.0　日期 2026-10-16　面向业务负责人 产品 研发 测试

本版根据最新要求重做需求与原型：成本数据全部来自系统已经录入的成本及报销单据，看板负责读取、计算、比较和展示。页面让业务直接看出费用规模、构成占比、城市差异、付款状态和费用变化，并能点击追溯到单据。本文为待实施方案，当前交付仍是需求与交互原型。

## 01 本版目标和变化

正式入口保持“数据看板 → 成本数据看板”，升级原城市成本入口，保留 /supply-chain/bi/city-cost 和 supply.bi.city-cost。视觉延续现有销售业绩及城市经营看板：双层导航、深色内容区、年月选择、大数字和蓝绿配色。

| 业务问题 | 本版直接给出的答案 |
| --- | --- |
| 本期花了多少 | 已确认经营费用、较上期差额与增幅；采购和损耗在独立区域查看 |
| 费用花在哪里 | 各类费用环形图，同时标金额与占比；类别颜色全看板一致 |
| 哪些城市花费更多 | 本期与上期双条形图，直接标城市、金额、差额和增幅 |
| 哪些费用增加或减少 | 分类增减图，以零线区分增加和减少，按变化绝对金额排序 |
| 哪些已付款 哪些未付款 | 付款状态占比条与金额，点击查看对应单据 |
| 报销集中在哪些类型和员工 | 报销类型占比、员工金额排行及全量员工明细 |

相较 V1：首页由台账列表导向改为图表分析导向；增加累计趋势、环形占比、双条形城市对比、城市百分比堆叠和增减分析。首页不放来源系统筛选、源表、UUID、采集批次或技术诊断。数据质量降为“待核对”辅助入口，原始记录信息收到详情中。

本版不增加费用录入、Excel 导入、外部采集或新成本微服务。原有系统中保存的外部单号只作为关联凭证保留，不代表看板要再次从外部拉取。预算、利润、存货结转、租金生成、自动分摊和实际现金流不在本期范围。

版本关系：本版的页面、指标、交互与交付清单取代 V1 对应设计。架构边界、数据库安全规则和源单据状态仍沿用已核对结论。本版没有将任何原型功能声明为正式上线。

## 02 数据从系统哪里读取

数据路径是“系统原单据 → 读取已有字段 → 按权限和口径计算 → 看板图表及明细”。业务无需再次录入或维护看板专用数据；源单据保存、修改、确认、作废后，下一次成功计算结果反映变化。

| 系统已有模块 | 所属服务和表 | 看板使用的事实 |
| --- | --- | --- |
| 商品采购 | ERP erp_cost_entry 的 PURCHASE | 费用日期、采购金额、商品供应商及城市；单独统计 |
| 商品损耗 | ERP 同表 LOSS | 费用日期、损耗金额、商品仓库及原因；单独统计 |
| 仓储和办公室费用 | ERP 同表 RENTAL | amount、premises_type、城市、费用日期；押金不纳入费用 |
| 营销费用 | ERP 同表 MARKETING | 日期、金额、类型、事项、经办人和城市 |
| 三段运费 | Order order_logistics_cost | 日期、金额、承担方、运输环节及城市；仅公司承担计费用 |
| 员工报销 | HR hr_expense | 日期、金额、类型、员工编码、部门快照、城市及付款标记 |

共同使用原状态 DRAFT、CONFIRMED、VOID。确认金额只包含 CONFIRMED、金额非空、公司承担记录；待确认另列，已作废不计入。编辑已确认单据会回到待确认，因此下一成功计算会减少已确认金额并增加待确认金额，这是源状态的真实变化。

ERP 和 Order 草稿允许空金额；HR 报销金额必填。空金额显示“未填”，不能替换成零；合法确认零元保留笔数。费用日期 cost_date 统一用于全局筛选；费用月份 cost_month 只保留详情，不混算。

已确认经营费用 = 公司承担运费 + 仓储 + 办公 + 营销 + 员工报销 + 场地待分类。报销已经包含在经营费用中，不能再加一次。采购额不是销售成本，损耗也不是付款流水，二者不放入经营费用或其占比分母。

ERP 办公费用与 HR 办公室租赁报销可能对应同一事项。系统录入不自动保证经济去重；疑似项只提示业务核对，未核实前保留原金额，不宣称已核定会计总成本。

## 03 页面和指标设计

顶栏提供年份、月份或全年、授权城市、刷新及全屏。第二行明确本期和上期起止日期。四个章节为“费用总览、城市对比、报销分析、费用明细”；右侧为“待核对、统计说明”。切换全局日期或城市时，四个章节同步更新并清理旧下钻条件。

| 首页指标 | 算法及展示 | 点击行为 |
| --- | --- | --- |
| 已确认经营费用 | 当前授权范围确认经营费用总额；展示上期差额、增幅 | 本期确认经营费用单据 |
| 已付款经营费用 | 同集合中 PAID 金额；展示占已确认费用比例 | 本期确认且已付款单据 |
| 未付款经营费用 | 同集合中 UNPAID 金额；展示占比 | 本期确认且未付款单据 |
| 待确认经营费用 | DRAFT 中非空金额之和；显示总笔数及未填笔数 | 本期待确认经营费用单据 |

付款字段当前只支持 PAID、UNPAID。“已付款经营费用”始终配“按台账付款标记统计”；它表示本期发生费用的当前付款状态，不表示本期实际支付流水。若历史记录出现未知标记，付款图增加“状态未记录”桶，不强行归到未付款。

采购、损耗在四指标下方独立显示金额及进入明细入口。其待确认金额可在各自明细查阅，不混入经营费用待确认卡。

首页的三条简短读数均由图表同一集合计算：最大费用类别及占比、已归属城市中金额最高的城市及占总费用比例、本期较上期增减额。它们只描述数据，不推断城市绩效或费用合理性；无可比数据时不生成增长结论。

正式显示金额用元和两位小数，所有数值有明确单位。大金额纵轴允许用万元缩写，悬浮和明细仍显示精确金额。百分比一位小数，独立四舍五入可能导致显示和为 99.9% 或 100.1%，不得修改原金额凑整。

## 04 费用支出趋势

首页默认显示累计费用双折线，并可切换按日发生额；全年模式切换为累计与按月发生额。蓝线代表本期，灰色虚线代表可比期，图例标出两期金额。

| 设计项 | 处理规则 |
| --- | --- |
| 横轴 | 月视图为日序，全年为月序；两期按对应日或月对齐，页首列明实际日期 |
| 纵轴 | 金额从零开始，两条线共用一个刻度；不使用双轴制造变化错觉 |
| 累计值 | 从本期起点到当前横轴点的确认经营费用累加；最后一点等于本期费用总额 |
| 发生额 | 当前日或月的确认经营费用之和；所有点之和等于本期费用总额 |
| 悬浮信息 | 日期或序号、本期金额、可比期金额、累计或发生额标识 |
| 下钻 | 图下“查看本期费用”进入相同范围明细；正式版支持选定日期点查看该日明细 |

当前月示例：2026-10-01 至 10-16 比较 2026-09-01 至 09-16；不能拿半个月对比上月全月。已结束月份比较完整自然月，月长不同时以实际天数绘制，超出短月部分不补零延长。当前年比较截至同月日的上年；完整历史年比较全年，闰年和月底按合法日期裁剪。

当前有完整计算批次且某日无记录，可补零以表示该日没有登记费用；没有源数据覆盖或整期没有可比记录，显示“无可比数据”，不补造上期零值。首屏无本期记录展示空状态，不把所有卡片展示为已确认的零成本。

“支出趋势”在本版明确指费用发生趋势，统计日期为费用日期。除非后续系统增加付款日期和逐笔付款金额，本期不另画现金实际支出趋势。

## 05 构成占比和费用增减

“费用花在哪里”采用环形图，中央显示经营费用合计。侧边或下方图例直接给出类别、金额、占比，无需悬浮才能知道比例。公司运费、仓储、办公、营销、报销和待分类场地费使用固定颜色。

| 图表 | 计算和交互 |
| --- | --- |
| 费用构成环形图 | 类别占比 = 当前类别确认费用 ÷ 当前筛选范围确认经营费用；点击类别进入对应明细 |
| 零金额类别 | 可以在图例显示 0.00 和 0.0%，不制造可见扇区；全部金额为零时显示零金额说明 |
| 费用增减图 | 每类差额 = 本期类别金额 − 可比期类别金额；横向条从零线向右或向左伸展 |
| 增减排序 | 按差额绝对值降序；两侧共用对称金额尺度，标明正负差额和增幅 |
| 增减下钻 | 点击类别进入本期对应单据，可切换同条件上期查询；两期不能静默混合 |
| 无法计算增幅 | 上期零本期非零显示“上期为零”；没有可比数据不画增减贡献，不显示无限大或虚构 100% |

增减图回答“总体变化主要来自哪些费用”，并不把增幅百分比当成金额占比。类别差额的合计必须等于总体差额；增加和减少只表示方向，不自动用红绿标记经营好坏。

完整性要求：场地未分类仍计入待分类桶；缺失城市也不会导致类别构成少算。报销不可见时整图排除报销并提示“当前合计不含报销”，不得在图例中泄露报销金额或把它写成零。

演示样例仅用于核对图表：经营费用 180048.71 元；仓储 66828.88 元，占 37.1%；营销 45616.78 元，占 25.3%。上期总额 174569.00 元，本期增加 5479.71 元，增幅约 3.1%。这些数值是虚构测试值，不是系统实际经营数据。

## 06 城市费用对比

首页先显示本期与上期双条形城市图；“城市对比”页提供更完整分析，可在经营费用、商品采购、商品损耗之间切换。切换时标题、金额、差额、占比分母和下钻条件必须一起切换，不能复用另一个范围的总额。

| 展示 | 具体规则 |
| --- | --- |
| 城市双条形图 | 一座城市一组，本期蓝色、上期灰色；同一金额刻度且从零开始；金额标在条末 |
| 差额与增幅 | 在城市名称一行给出本期减上期及增幅；没有可比期时只展示本期 |
| 排序和待归属 | 按本期金额降序；未映射记录作为“待归属城市”保留，不冒充正式城市 |
| 城市本期占比 | 该城市本期金额 ÷ 当前筛选范围所有城市本期金额，包含有权查看的待归属桶 |
| 城市百分比结构图 | 仅在经营费用范围展示；每条代表该城市 100% 费用，按固定类别颜色堆叠 |
| 结构图标签 | 足够宽的色块直接显示比例；小块不强塞文本，悬浮显示类别、精确金额和占比，图例常驻 |
| 城市对比表 | 城市、本期、上期、差额、增幅、本期占比；与图表使用同一数据集合 |

城市结构图用于比较费用构成，长度都为 100%，不能据此判断金额多少；每条同时显示该城市合计。金额比较使用上方双条形图。结构图分母是该城市的费用，不是全部城市合计。

点击蓝条进入该城市本期单据，点击灰条进入上期单据；明细顶端必须明确“本期”或“对比期”。点击城市结构色块，同时带入城市和费用类别。已选择单一城市时占比自然为当前范围的 100%，页面保留筛选提示，不暗示其占全公司 100%。

城市代码继续使用现有经营城市与原费用地区映射。缺失和多义归属进入待核对，不能按名称临时猜测。权限先于映射和聚合，受限用户不能通过“待归属”桶看到全租户费用。

## 07 付款状态和报销分析

付款图使用 100% 堆叠条，直接展示已付款和未付款比例；下方逐项列出金额与百分比。公式为各付款标记金额除以同一确认费用合计，已付款 + 未付款 + 未记录 = 已确认经营费用。点击任一色块或金额查看对应单据。

| 报销分析功能 | 展示与处理 |
| --- | --- |
| 四个指标 | 已确认报销、已付款报销、未付款报销、待确认报销；仍按费用日期及付款标记 |
| 类型构成 | 差旅、交通、住宿、办公等来自系统报销类型字典；环形图并列金额和占比 |
| 员工金额排行 | 已确认报销金额前 10 位横向条形图，标金额和部门；强调只作费用分析 |
| 全量员工明细 | 员工编码、姓名、部门、已确认/付款标记金额、笔数；按编码区分同名员工 |
| 员工下钻 | 点击员工带入 employeeCode，不能用姓名模糊查询代替精确过滤 |
| 类型下钻 | 点击类型带入稳定类型编码；停用字典值仍可查历史，未知类型保留其他桶 |
| 无报销权限 | 返回限制状态，不返回姓名、部门、金额、人数或重复候选对方信息 |

已确认报销是经营费用的一部分，首页与报销页的金额可在相同过滤条件下核平。工资、提成、薪酬计算结果不加入本版报销或成本合计。

系统目前的报销状态是待确认、已确认、已作废；页面不制造审批中、审批驳回等不存在的流程。办公室租赁报销与 ERP 办公费用只提示可能重叠，不能只因同金额就自动排除。

本版原型默认经营费用中已付款 120729.05 元，占 67.1%；未付款 59319.66 元，占 32.9%。这些数值均从同一份虚构费用单据计算，原型没有连接真实系统，也不能验证正式付款完整性。

## 08 明细追溯和交互边界

所有图表下钻都携带期间、城市、业务范围、类别、状态、付款标记、员工或类型等条件。下钻金额来自所选集合，不能只把图上的显示金额传给明细页面。正式版携带相同计算结果版本，避免新旧金额混用。

| 场景 | 展示和行为 |
| --- | --- |
| 明细列表 | 单号、事项、类别、城市、日期、金额、状态、付款标记、计入或排除说明；默认日期倒序和稳定源键 |
| 明细检索 | 单号、事项、原始单号、员工及状态；正式版另有类别/付款标记筛选，支持 20/50/100 分页 |
| 详情 | 原金额、日期、员工部门、付款与确认状态、承担方、费用月份、押金及分类专属字段 |
| 原始信息 | 详情折叠区保留原始关联单号、来源标识及业务记录身份；首页不需要用户理解数据库表 |
| 回原台账 | 正式版按业务记录 ID 定位原页面并再次鉴权；确认、修改、作废仍由原模块完成 |
| 导出 | 全部匹配授权结果，非仅当前页；保留筛选、期间、口径、计算版本及来源信息，空值和零分开 |
| 待核对 | 金额未填、城市未归属、场地待分类、疑似重复；按单据去重计数，一笔可含多个原因 |
| 空与失败 | 无记录给空状态；读取失败且有旧结果时保留并提示时间；首次失败无旧结果时显示不可用 |

没有 HR 原始来源字段并不是用户输入错误，本版不把“来源未记录”列为报销必须处理的问题。付款、城市和分类的真实缺失必须保留并说明影响金额；不为了让图表完整而补造事实。

全局筛选在章节间保留；切换全局筛选重置旧的局部条件与页码。清除下钻条件回到当前期间的全部授权台账。正式版将筛选保存到 URL，原型采用内存状态。抽屉支持 Escape 关闭及焦点返回，表格可横向滚动，键盘可操作按钮与图例。

CSV 转义引号换行和公式前缀，不输出令牌、签名附件地址及无权字段。下载全部结果与当前查询一致，不能把页面可见的十条当作全量。

## 09 如何实现系统读取和计算

业务数据只存在于既有领域模块中；看板不另建业务录入副本。正式链路为 Portal → Gateway 身份与会话校验 → BI 授权查询；BI 沿用现有分析读取机制，通过 ERP、Order、HR 的内部数据接口取得系统台账字段并计算。禁止浏览器拉全量分页求和，也不直接跨业务库 JOIN。

| 变更位置 | 需要完成的工作 |
| --- | --- |
| ERP Order HR | 提供最小成本读取契约：源ID、租户、版本、金额、日期、类别、状态、付款标记、城市、权限字段及必要明细 |
| BI 数据接入 | 复用 analytics-source 和 bi_source_* 模式，接入三类现有台账；仅建立分析读取需要的投影，不建立外部采集平台 |
| BI 计算 | 统一确认集合、公司承担、日期、城市映射、权限；一次计算产生指标、趋势、构成、付款、城市与增减数据 |
| Portal | 新增手写 API 与看板组件，复用现有路由权限和图表组件；生产图表用项目已有图表库，原型 SVG 不作为强制实现选型 |
| IAM | 复用原成本看板入口并明确查看、导出、刷新权限；源类别数据范围与 BI 权限求交集 |

需要的接口能力以 /api/v1/analytics/supply/cost-dashboard 为前缀：GET /overview 返回首页图表；GET /cities 返回指定范围城市比较和结构；GET /expenses 返回报销类型和员工；GET /entries 与详情、/export、/quality 支持追溯；GET /filter-options 返回授权候选项。

共同响应应含本期与可比期范围、金额精确字符串、单位、口径版本、计算版本、实际完成时间、数据覆盖范围及 restrictedCategories。前后端不能各自用不同分母重算；后端以 BigDecimal 计算，原型整数分只用于演示。

点击页面刷新重新查询当前可用结果。源单据变更在下一次成功分析更新后体现，界面展示最后成功时间；建议初始更新周期 5 分钟，实际根据既有刷新机制及联调容量定版。此处是系统内部读与算，不是新增外部同步。

## 10 技术正确性和数据库约束

系统中已有数据并不意味着现有 BI 已能查询。本轮已核对源码：成本三表尚未进入现有 BI 数据集；原成本示例和 bi_city_cost_record 不自动叠加。本版只补足真实读取与图表所需能力，不能将演示数值回退为生产结果。

| 必要约束 | 实施要求 |
| --- | --- |
| 唯一身份 | tenant + sourceService + sourceTable + sourceId；一张费用关联多张业务单仍只计一次 |
| UUID 分页 | 原费用 ID 为 VARCHAR UUID；现有数值/二进制 UUID 分页需适配 TEXT_UUID 的查询、排序和校验 |
| 版本可靠性 | 源新增、修改、确认、作废在本域事务内推进变更版本；当前 guard.version 不能直接当成已可靠递增 |
| 整批一致性 | 保留完整成功结果；单源失败或读取期间版本变化，不发布半批费用，避免某类金额突然归零 |
| 城市语义 | HR 经营部门代码与 CRM 地区代码复用现有确定映射，缺失和歧义保留待归属 |
| 权限一致性 | 筛选项、图表、合计、明细、待核对、导出使用同一租户与源范围；报销不可见不能泄露重复对方 |
| 缓存和更正 | 缓存包含权限版本、筛选与计算版本；作废、编辑回待确认后移出确认金额；组织变化可追溯 |

源数据读取开始与结束校验版本，发布完整结果；这不等同于跨服务数据库同一时刻的分布式快照。显示各源完成信息供运维核对，业务首页只保留最后更新时间和是否有缺失范围。

数据库操作先核对 profile、环境变量、Nacos 等最终配置及实际实例、Schema、tenant 类型和 flyway_schema_history；源码版本不是部署历史。DEV/local 服务启动可能自动迁移共享库，不能作为只读检查。

新增表与字符列 utf8mb4 / utf8mb4_general_ci；已有 V/B 迁移不改不删，保留 validate、禁止 clean、自动 baseline、out-of-order 和 repair 掩盖失败。运行迁移脚本必须显式目标库、服务和动作；生产启动关闭 Flyway。凭据和业务导出不进 Git。本轮不执行数据库操作。
