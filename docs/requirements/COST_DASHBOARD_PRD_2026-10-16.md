# 成本数据看板需求与实现方案

版本 V1.0　｜　日期 2026-10-16　｜　适用对象 业务负责人 产品 研发 测试

本方案将现有成本管理及员工报销汇集到数据看板，回答费用发生在哪里、由什么构成、哪些仍待确认、每个金额对应什么单据。交付范围为需求文档、交互原型及技术方案；正式前后端、数据库迁移和部署另行实施。

## 01 目标与交付范围

建议升级现有“数据看板 → 城市成本看板”为“成本数据看板”，保留 /supply-chain/bi/city-cost 与 supply.bi.city-cost，避免重复菜单和失效书签。正式页面参考当前销售业绩看板、城市经营看板，采用深色内容区、顶部期间筛选、指标组、趋势、表格及单据下钻。

本期定位是“手工台账分析”。经营费用、商品采购、商品损耗分别展示，不能用采购金额直接计算销售成本或完整经营利润。已确认台账汇总仍可能含跨模块重复事项，名称和提示必须保留这一边界。

| 范围 | 本期处理 |
| --- | --- |
| 采购及损耗 | 读取 ERP 手工台账，分别统计金额与笔数，保留货品、供应商和来源单据 |
| 三段运费 | 读取 Order 采购运输、仓间调拨、城市配送台账，仅公司承担计入公司费用 |
| 仓储及办公 | 读取 ERP RENTAL，以 premises_type 分类；押金仅详情展示 |
| 营销及报销 | 营销读取 ERP；员工报销读取 HR，按城市、员工、部门和类型分析 |
| 查询与核对 | 期间、城市、类别、来源、付款标记；趋势、构成、明细、CSV、质量提示 |
| 本期不扩展 | 自动估值、存货结转、费用分摊、租金自动生成、付款核销、关账、利润、预算、工资并表 |

角色目标：经营负责人看构成与城市差异；财务核对人员追溯确认及付款标记；城市负责人查看授权范围；员工或录入人回原台账补录。角色名称是使用场景，不代表系统自动授予权限。

事实证据按源码、浏览器和数据库验收分别记录。本文“现有”指已核对源码；“拟新增”指后续实现；没有连接数据库核对实际表结构、迁移历史或真实成本完整性，不能把源码存在视为部署完成。

## 02 项目架构与功能地图

当前递归 POM 为 47 个 Maven 工程、11 个启动应用，即 Gateway 加 10 个领域服务。后端 Java 21、Spring Boot 4.0.7；Portal 为 Vue 3、TypeScript、Vite、Element Plus；独立 Workbench 为 Vue 3、Vant 飞书 H5。三个业务仓库分别维护 Git 状态。

| 服务及库 | 具体业务实现与职责 |
| --- | --- |
| Gateway 无业务库 | 接收浏览器请求、JWT 校验、IAM 在线会话核验、剥离伪造身份头、下游签名路由 |
| IAM rigour_iam | OIDC 和飞书身份、应用成员、角色、菜单、动作权限、数据范围与会话；员工档案由 HR 持有 |
| Integration rigour_integration | 订货宝采集及同步编排、原始数据、映射与重试；飞书导入批次、预检、投影和核对 |
| CRM rigour_crm | 客户、联系人、地址、地区类型、销售责任归属及订单归属引用 |
| ERP rigour_erp | 商品 SKU 规格价格、供应商、采购、仓库、库存及调拨；采购、损耗、营销和场地成本台账 |
| Order rigour_order | 销售订单、发货履约、回款退款、资金单、发票与凭证核对；物流成本台账 |
| Sales rigour_sales_work | 外勤签到、轨迹、拜访计划、证据和复核；含服务内置临时拜访 H5 |
| HR rigour_hr | 员工部门岗位、考勤确认、经营目标、薪酬规则与月度核算、员工报销 |
| BI rigour_bi | 从领域 API 取得源快照，构建本地维度事实，支持经营、销售、城市、客户、商品、人事和核对 |
| Foundation rigour_settings | 公共与租户业务字典、历史值解析、合并及审计 |
| AI 职责库预留 | 当前只有启动和配置骨架，未发现业务 Controller，不能规划成已具备的分析能力 |

页面存在不等于功能闭环。Portal 部分采购付款、库存盘点等仍为占位；Workbench 不能等同于 Sales 内置拜访 H5。原成本原型也是独立演示项目，不是正式 Portal 业务实现。

## 03 服务调用与代码规范

主调用链：Portal → Gateway → IAM 核验会话 → 领域服务验签、取租户、校验动作及对象范围 → application 用例 → domain 与出站端口 → 本域仓储。看板走 Portal → Gateway → BI，不能由浏览器分页拉取所有业务台账后拼总数。

| 业务链路 | 调用及约束 |
| --- | --- |
| 订单出库 | Order 保存执行意图 → ERP 查回执及回调认领 → ERP 本地扣库 → Order 完成回执；失败可以核对重试，不是跨库原子事务 |
| 外部业务采集 | Integration 采集订货宝、飞书并调用 HR、CRM、ERP、Order 的投影 API；目标领域是本库唯一业务写者 |
| 成本和报销 | Order 经 ERP 取采购及调拨引用；ERP 场地用仓库、营销用 HR 员工；HR 报销用本域员工与 Foundation 字典 |
| 现有 BI | 定时或受权刷新 → 各域 analytics-source → 版本分页校验 → bi_source_* → BI 分析查询 |
| 本期扩展 | 新增 ERP 成本、Order 运费、HR 报销三个数据集 → BI 费用事实和授权聚合 → 成本看板 |

跨服务使用注入的 RestClient.Builder 和 Nacos 服务名。Gateway 使用 lb://，禁止新增固定 IP 或端口互调；领域只依赖其他服务的 api/client，不依赖 server 实现，不跨业务 Schema JOIN。

入站层依赖 application，application 依赖 domain/port，infrastructure 实现端口；domain 不依赖 Spring、数据库或他域实现。现有持久层混用 MyBatis-Plus、JDBC，沿用所改模块模式。HTTP 继续使用 /api/v1、ApiResponse、requestId 和稳定错误码。

金额沿用 DECIMAL(18,2) / BigDecimal，接口精确十进制字符串，前端不得用浮点做权威汇总。日期遵守领域 LocalDate，业务期间使用 Asia/Shanghai；审计时间按 UTC 存取。

Portal 手写 API 在 src/api/core，生成文件不能手改。复用现有权限 store、路由守卫及导航资源。Access/ID Token 保持内存，不为原型改认证。所有查询、缓存、索引、唯一键都包含 tenant。写操作需幂等、版本及本域事务审计；本期 BI 不新增业务台账写入口。

## 04 当前成本数据能力

| 类别与页面 | 实际数据入口 | 已有字段与行为 |
| --- | --- | --- |
| 商品采购 purchases | ERP /api/v1/erp/costs/purchases；erp_cost_entry 的 PURCHASE | 商品规格数量单价、金额及说明、供应商、仓库、采购引用、外部补录 |
| 商品损耗 losses | ERP /api/v1/erp/costs/losses；同表 LOSS | 商品及仓库、数量金额、损耗原因；不自动扣库存 |
| 运费 logistics | Order /api/v1/orders/logistics-costs；order_logistics_cost | 三段运输、合运引用、发收方、承运方、承担方、金额、来源及附件 |
| 仓储与办公室 | ERP /api/v1/erp/costs/warehouse-rentals；同表 RENTAL | 仓库或手填场地、premises_type、费用月份、合同、租期、押金；前端 office-rentals 复用该接口 |
| 营销 marketing | ERP /api/v1/erp/costs/marketing；同表 MARKETING | 类型、事项、经办员工、城市、渠道、服务日期、金额及来源 |
| 员工报销 expenses | HR /api/v1/hr/expenses；hr_expense | 员工和部门快照、类型、城市、费用日期、金额、付款标记、备注与历史 |

三类领域台账共有 DRAFT、CONFIRMED、VOID。已确认单据可带原因修改，修改后回到待确认；金额应随下一成功快照更新。ERP / Order 草稿允许金额为空，确认需金额；HR 报销金额必填。零元确认需原因，不能把空金额当零。

费用付款字典目前只有 PAID、UNPAID。没有足以计算实付日期、部分付款金额、应付到期或现金流的完整费用付款流水。报销“确认”也不等于多级审批通过，不设计虚构审批状态。

ERP / Order 有来源系统及外部单据快照，保留 SYSTEM、DHB、OTHER、MANUAL、MIXED、UNKNOWN 等现值。HR 报销没有对应原始来源字段，展示“来源未记录”；不能由“在系统内录入”推断原业务来自本系统。

现有 BI 数据集未接入上述三张费用表；城市成本仍有 bi_city_cost_record 导入入口。cockpit-costs.ts 存在演示成本生成逻辑，不能作为真实成本来源。

## 05 指标定义和核平规则

统一基础集合 B：当前 tenant、当前有权查看的记录、费用日期落入期间、满足全部全局筛选。确认集合 C：B 中 status=CONFIRMED、amount 非空、运费 payer=COMPANY。所有汇总先过滤权限，再按源业务记录唯一键归集。

| 指标 | 精确定义及展示 |
| --- | --- |
| 已确认经营费用台账 | ΣC 中 LOGISTICS + WAREHOUSE + OFFICE + MARKETING + EXPENSE + RENTAL_UNKNOWN；保留“台账”与未经济去重提示 |
| 已确认商品采购 | ΣC 中 PURCHASE；独立卡片，不计入经营费用 |
| 已确认商品损耗 | ΣC 中 LOSS；独立卡片，不计入经营费用 |
| 待确认已填金额 | B 中 DRAFT 且公司承担的非空金额之和；同时展示笔数、空金额笔数 |
| 标记已付款金额 | 对相同确认集合，payment_status_code=PAID 的金额；不能命名本期实付 |
| 标记未付款金额 | 同集合 UNPAID 金额；不能冒充应付账款余额或逾期金额 |
| 已确认报销 | ΣC 中 HR EXPENSE；是经营费用子集，不能再次相加 |
| 费用占比 | 当前城市或类别经营费用 ÷ 同一筛选范围经营费用合计；分母为零显示 — |
| 环比差额和增幅 | 本期减可比期；增幅为差额 ÷ 可比期。上期零本期非零显示上期为零；无可比数据不当零 |
| 笔数和人数 | 笔数按源记录唯一键；人数按 employee_code 去重，不能按姓名去重 |

可核平关系：确认台账总额 = 经营费用 + 采购 + 损耗；经营费用 = 六个费用分类和；城市汇总含待映射桶后 = 当前授权总数；相同集合的 PAID + UNPAID + 付款状态未知 = 确认金额。任何未知分类或付款值保留未知桶，不静默丢弃。

金额展示元、两位小数，图表可缩写但 tooltip 和明细显示原值。整数分样例用于原型计算；正式结果由后端 BigDecimal 产生。金额下降不自动代表经营改善，金额排名不使用优劣奖牌。无数据、真实零、未知值、无权限、刷新失败须使用不同状态。

## 06 日期归属与重复处理

V1 全局时间基准固定为 cost_date 费用日期，默认当前年月，截至业务时区今天。ERP 的 cost_month 作为费用月份保留在明细与导出，暂不混入统一趋势；不能有些类别按月份、有些类别按日期而不提示。需要费用月份口径时应新增独立口径版本。

当前月 2026-10-01 至 2026-10-16 对比 2026-09-01 至 2026-09-16；已结束月份比较完整自然月；当前年比较截至相同月日的上年，完整历史年比较全年。目标月天数不足取月末，闰年按实际有效日裁剪。显示明确的起止日，缺少可比快照不填零。未来日期不纳入当前期。

| 情形 | 处理规则 |
| --- | --- |
| 城市一致性 | 费用 city_code 为原始地区，现有经营城市取 HR 销售部下级 department_code；复用 bi_sales_contact_city_dim 的 source_region_code 映射 |
| 映射校验 | 当前 OperatingCitySql 按唯一规范化名称匹配 CRM 地区。新费用链只使用已产出的稳定代码映射，不再另造名称猜测；一对多、无匹配标记待映射 |
| 待映射记录 | 全租户授权可见单独待映射桶；受限用户只有确实通过该原始对象权限才可见，不能把空城市解释为全部可见 |
| 历史归属 | 保留 sourceCityCode、cityNameSnapshot、部门及员工快照、mappingVersion；组织改动重新映射须形成新批次并保留可解释差异 |
| 技术去重 | 唯一键 tenant + sourceService + sourceTable + sourceId；revision 变化更新记录，不增一笔 |
| 多来源与合运 | 一张费用单关联多张采购或销售单仍只计一次。源引用独立集合，查询不得通过 JOIN 放大主表金额 |
| 经济重复 | 报销 OFFICE_RENT 与 ERP OFFICE 同城市、同日期、同金额可形成候选；只能提示两笔待核对，不能仅凭文本或金额自动扣除 |

V1 不引入自动重复认定或跨台账抵扣。业务核实后按原台账授权操作更正或作废，再由 BI 刷新反映。若业务要求保留两份合法单据但经济金额只计一次，需要后续增加明确关联、计入规则及审计；在此之前不宣称已核定总成本。

## 07 页面结构与筛选交互

页面继承现有主导航、二级菜单和多页签。内容背景 #071d2c，分隔线 #223b50，辅助文字 #9eb4cc，金额蓝色、薄荷绿和琥珀色只作类别区分。顶部品牌与看板标题、当前授权范围、年/月/全年、刷新、全屏；下方显示期间、可比期间与数据截至时间。

| 区域 | 功能及交互 |
| --- | --- |
| 章节导航 | 成本概览、城市对比、报销分析、单据明细、数据质量；保留全局筛选 |
| 全局筛选 | 年月、城市、费用类别、原始来源、付款标记；字典及城市选项仅返回授权值，选择即重查 |
| 筛选反馈 | 顶部展示当前范围；重置返回当前年月及全部授权值；切换全局条件清理局部下钻和页码 |
| 指标组 | 经营费用、采购、损耗、待确认四卡；点击带入指标集合与状态进入明细，不能只传显示金额 |
| 趋势 | 经营费用本期与可比期折线；月按日、年按月，悬浮显示日期、元和笔数 |
| 构成 | 六类经营费用横条，标签直接显示金额；点击类别进入已确认明细；零分类不伪造占比 |
| 城市表 | 经营费用、采购、损耗、其中报销、待确认、费用占比、质量提示；点击城市进入同口径下钻 |
| 底部 | 来源成功批次、完成时间、数据截至日期、授权范围或缺失来源提示；统计口径入口常驻 |

需求中的正式版保留筛选到 URL 查询参数，返回原台账后可恢复。V1 原型采用内存交互，刷新页面恢复默认值，不承诺 URL 持久化。正式列表请求取消过期响应，防止快切城市后被旧结果覆盖。

桌面按现有看板密度设计，主要验收 1440 与 1920 宽度；窄屏指标两列，图表纵向，表格容器横向滚动，页面不能整体溢出。键盘可操作、抽屉 Escape 关闭、焦点返回触发按钮；图表同时有对应数值表。

## 08 报销明细与数据质量

| 模块 | 要增加的功能与展示方式 |
| --- | --- |
| 报销概览 | 已确认报销、标记已付款、标记未付款、待确认；金额随全局城市及期间联动，员工姓名不能泄露至无权用户 |
| 报销类型 | 读取 REIMBURSEMENT_EXPENSE_TYPE 的稳定编码和历史名称；已停用类型仍显示历史记录，未知类型归其他待分类 |
| 员工分析 | 员工编码与姓名、部门快照、已确认/付款标记金额、笔数；点击员工进入相同集合明细，不作为绩效评价 |
| 单据列表 | 单号、事项、类别、原始城市/经营城市、日期、费用月份、金额、来源服务/系统、状态、付款标记、承担方、归集结果 |
| 列表筛选 | 全局条件加单号/事项/原始单号/员工/类型关键字、单据状态；默认日期倒序加稳定源键，分页 20/50/100 |
| 详情抽屉 | 公共字段、来源表/ID/revision、业务引用、金额确认原因、类目专属字段、质量提示、返回原台账入口 |
| 分类详情 | 采购损耗展示商品数量单价与说明；运费展示运输环节及发收方；场地展示月份合同租期押金；营销展示渠道及服务期 |
| 附件与历史 | ERP / Order 复用原台账已授权接口和临时签名 URL；HR 复用已有操作历史，不能伪造尚未确认存在的报销附件能力 |

数据质量以记录列表支持处置：金额未填、城市待映射、场地待分类、来源未记录、付款状态未知、疑似重复、来源刷新失败。每类定义总数、影响金额与适用状态；同一记录可多个问题，卡片合计不能代替去重记录数。HR 原始来源未记录属于数据模型能力缺口，不能提示员工必须填写不存在的字段。

重复候选若另一笔不可见，不返回其单号、人员或金额；可以仅显示当前记录需核对，或由有权角色核对。所有异常入口遵守与明细相同权限。BI 只查询，修改、确认、作废回原领域台账；原页面尚不能按 ID 定位时需新增受权查询参数及打开详情能力。

CSV 导出当前查询的全部授权结果，非当前页。包含期间、筛选、口径版本、批次、导出时间及原始来源，空金额为空、零为 0.00。转义逗号换行引号及表格公式前缀，不导出签名 URL、令牌或无权字段。正式导出使用独立权限与审计。

## 09 数据来源与统一事实模型

拟新增领域数据集 ERP_COST_ENTRY、ORDER_LOGISTICS_COST、HR_EXPENSE；各领域读取自己的库，输出最小分析契约。BI 持久化源镜像和 bi_cost_fact，展示只查询 BI 库。原始业务服务仍是唯一写者；无需新建成本微服务，也不需要引入外部 Excel 作为本期事实源。

| 事实字段 | 来源与处理 |
| --- | --- |
| tenantId sourceService sourceTable sourceId | 原始租户与主键；组成唯一键，保持字符串 UUID，不转成数字 |
| sourceRevision documentNo title | 源版本、内部费用单号和事项；单号不能代替唯一键 |
| categoryCode typeCode premisesType | ERP category_code 和 premises_type；Order LOGISTICS；HR EXPENSE，未知值保留 |
| costDate costMonth | 各源 cost_date；ERP cost_month 可空；全局统计固定费用日期 |
| amount paymentStatus statusCode | 源 DECIMAL 金额与状态；未知付款值独立桶，空值不 COALESCE 成零后伪称完整 |
| sourceCityCode cityNameSnapshot operatingCityCode | 原始城市与保存名称、经营城市映射结果和 mappingVersion |
| employeeCode departmentId warehouseId createdBy | 原权限相关字段及快照；不是新增默认授权，保留空值原语义 |
| sourceSystem sourceDocumentRefs | ERP / Order 原始来源和引用数组；HR 标记 UNKNOWN，不能补造 SYSTEM |
| payerCode logisticsLegCode | Order 原承担方和运输环节；仅 COMPANY 计入公司费用，未知承担方单独提示 |

| recordedAt sourceUpdatedAt snapshotId | 原始创建/更新时间与分析批次；不能复用 Portal 对报销 createdTime 的展示补值作真实创建时间 |
| qualityFlags inclusionReason | 派生质量标记与计入原因，保留推导口径版本，不能修改原状态 |

建议数据库：三份最小源镜像、bi_cost_fact、费用刷新运行及来源检查点；来源引用可建子表，主事实金额不在引用 JOIN 中重复累计。索引以 tenant + cost_date + status/category/city/employee 为基准，实际用 EXPLAIN 核对；唯一键覆盖 tenant 与源身份。

不得直接把 data_json 整包透传浏览器；在领域适配层抽取白名单。原台账附件及敏感人员字段按需从领域受权读取，不全量复制 COS 内容。

## 10 接入前置项与刷新一致性

当前三个成本源主键为 VARCHAR(36) UUID；现有源仓储和 BiSourceSnapshotProjector 仅接受数字 ID 或 32 位二进制 UUID 十六进制游标。因此不能只向 BiSourceDatasets 添加名称就宣称接通。

拟将 binaryKey 二分策略扩展为明确的 NUMERIC、BINARY_UUID、TEXT_UUID，并同步领域分页查询、游标校验、BI 比较器及插入绑定。TEXT_UUID 按规范化固定格式与一致排序分页；采用源 SQL 确定的字节排序，不允许 JVM 与数据库比较规则不同；测试跨页、重复、回退、非法字符及至少 1001 笔记录。

每个数据集新增或复用可靠的单调变更版本。当前 guard.version 仅见锁读取，不能假设已经随写入递增。新增、编辑、确认、作废、纠错和必要的关联变更必须在同一业务事务内推进版本；不能仅凭 MAX(updated_time) 或记录数证明源未变化。

刷新流程：受权任务创建 snapshotId → 读取三源起始版本 → 逐页采集至本批候选区 → 校验字段集合、租户、唯一键、游标和行数 → 重查三源版本 → 生成分类、映射、质量及索引 → 在 BI 本地事务原子切换可见批次。失败回滚候选批次，继续服务上次完整快照。

这提供经过版本校验的完整采集批次，不是跨服务数据库在同一时刻的分布式快照。返回每源版本、采集时间及 completedAt，明确允许的源时间差。超过窗口或持续变更则有限重试并报失败，不用部分数据填零发布。

| 情形 | 正式行为 |
| --- | --- |
| 单源失败或结构不匹配 | 不发布半批成本，保留旧批次；首次失败无旧快照则显示不可用 |
| 编辑已确认变待确认 | 新快照移出确认金额，进入待确认；历史对比随更正重算并可追溯版本 |
| 作废或删除 | 投影保留状态或按完整快照替换清除；不能因只拉新增而继续累计旧金额 |
| 页面刷新 | 重新查询已发布快照；管理员可另行触发来源刷新，普通用户不能随点随启动全租户任务 |
| 周期与并发 | 建议 5 分钟周期和租户互斥，作为配置建议；上线前依据容量验收确定，不宣称现有 SLA |
| 批次过期 | 建议超过 15 分钟提示延迟；界面显示实际成功时间而非浏览器当前时间 |

## 11 API 与权限设计

以下为拟新增契约，不是已经上线的接口。沿用 /api/v1/analytics/supply，公共前缀为 /cost-dashboard。Portal 新增 src/api/core/cost-dashboard.ts，页面组件不直接调用源库或把源服务大分页总数当聚合结果。

| 方法与相对路径 | 入参与响应要点 |
| --- | --- |
| GET /filter-options | 返回授权城市、类别、来源、付款状态、可用期间、restrictedCategories；不可泄露完整租户候选项 |
| GET /overview | 返回四指标、可比期、趋势、类别、城市、freshness、coverage、snapshotId、metricVersion |
| GET /expenses | 返回报销指标、类型、员工分组；员工分页；无权限返回明确限制状态 |
| GET /entries | 全局条件加状态、员工、关键字、bucket、begin、step、snapshotId；返回全量查询计数、汇总及页数据 |
| GET /entries/{service}/{id} | 返回受权白名单详情、计入原因及源版本；无权与不存在遵守现有错误契约 |
| GET /quality | 问题类型、去重总数、授权问题明细、snapshotId；按页返回 |
| GET /export | 与 entries 同筛选同批次，额外校验导出权限，服务端分页生成 CSV |
| POST /refresh-runs | 受权后台刷新任务，返回任务 ID 与状态；同租户正在执行时复用或返回冲突 |

共同参数：from/to 为含端点的 LocalDate；regionCode 为经营城市稳定编码，未知桶使用明确保留标识；category、sourceSystem、paymentStatus、scope 由服务端白名单校验。禁止信任浏览器传入 tenantId 或员工可见列表。所有金额为精确字符串，计数为整数，缺失金额为 null。

多接口下钻必须携带 snapshotId。正式存储保留至少当前与上一可用批次，过期批次请求返回明确“数据已更新，请刷新”冲突；前端统一重取，不能静默把旧汇总与新明细混在一起。导出写入所用批次和口径。

拟新增 analytics:cost:read、analytics:cost:export、analytics:cost:refresh，与现有 analytics:dashboard:read、源类别读取权限求交集。仓库、地区、部门、员工、录入人等范围沿用源领域语义，不能只校验经营城市。既有角色如何补授权限由 IAM 迁移显式配置，不能默认所有看板用户获得报销人员明细。

BI 查询、筛选项、问题计数、合计、详情、导出采用同一授权过滤器；缓存键包含 tenant、权限版本、范围、过滤条件、snapshotId。没有 HR 权限时返回“当前合计不含报销”及 restrictedCategories，不把报销显示成零。

## 15 设计取舍与后续评审

本方案建议直接采用：费用日期统一口径；只统计确认台账；经营费用、采购、损耗分开；报销为经营费用子集；原始来源和归集状态可追溯；不自动扣减疑似重复；旧入口升级；不将薪酬、销售成本和利润并入 V1。

| 评审项 | 建议和影响 |
| --- | --- |
| 台账汇总与核定成本 | V1 名称使用台账，重复候选保留。需要经济去重总成本时另增明确业务关联与核定流程 |
| 费用日期与费用月份 | V1 按日期。若业务要求按归属月份，必须确定各源补录策略、历史回填和独立指标版本 |
| 旧城市成本导入 | 默认独立保留，提供历史查询说明。迁移需逐笔来源与覆盖范围核对，不按同城同月简单相加 |
| 原始城市映射 | 先使用现有唯一代码映射；多义项交由数据治理确认，是否新增显式维护入口作为后续独立功能 |

| 刷新与性能 | 5分钟刷新、15分钟延迟提示及10万行指标为初始设计目标，联调压测后定版 |
