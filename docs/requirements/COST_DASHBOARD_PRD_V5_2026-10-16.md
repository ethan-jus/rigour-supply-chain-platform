# 成本数据看板产品需求规格

版本 V5　日期 2026年10月16日　交付对象 产品 研发 测试 经营负责人

本规格定义现有系统成本数据看板的正式建设范围、业务规则、页面原型和上线验收要求。目标用户为经营负责人、CEO及老板。通过费用规模、期间变动、费用结构、城市分布和支出明细，支持经营复盘与费用核查。本版替代V1至V4的页面与交互定义。

## 01 产品目标与建设范围

数据全部来自系统已经录入的成本和报销台账。看板负责查询、归类、汇总、对比和追溯；原业务模块继续负责录入、更正、确认、作废。用户不需要为看板重复填报数据。

首版以已确认经营费用为主指标，采购登记金额和损耗登记金额分别分析。报销已包含在经营费用中。当前字段不足以形成完整财务成本与利润，界面不得使用“公司总成本”“净利润”“降本收益”等名称。

| 优先级 | 本次建设内容 | 交付要求 |
| --- | --- | --- |
| P0 | 费用总览 期间对比 费用结构 重点费用变动 累计趋势 | 统一口径及筛选，所有金额能够核对至明细 |
| P0 | 城市费用分布 城市费用对比 费用变动构成 支出对象分析 | 提供图表联动、维度切换和完整结果 |
| P0 | 本期与可比期明细 来源详情 全量导出 | 保留查询条件，遵循业务及数据权限 |
| P0 | 三域数据接入 可靠变更同步 数据状态 权限校验 | 是正式建设工作，现有BI尚未接入这些费用源 |
| 条件开放 | 城市费用规模参照 | 成本与订单城市、期间、权限可对齐后启用；不满足则不展示比值 |
| 后续需求 | 工资纳入 预算管理 预警规则 费用原因填报 | 不属于首版验收；不得放置不可用业务入口 |

首版不新增自动计价、租金生成、摊销分摊、库存结转、支付核销、现金流和自动派单。工资模块已经存在，其统计月份与薪资权限需独立设计后再纳入。

成功标准：使用者能够从费用总览识别费用规模与变动，定位对应城市、费用类别或支出对象，查询两期单据并导出核对。上线验收以第13、14节为准，不以图表数量或页面效果代替数据正确性。

## 02 信息架构与业务术语

在现有数据看板中升级成本入口，沿用 /supply-chain/bi/city-cost 及 supply.bi.city-cost 页面权限。外观沿用销售业绩、城市经营看板的系统导航、页签、深色内容区、蓝色主色与期间选择习惯。

| 页面或区域 | 正式名称 | 展示内容 |
| --- | --- | --- |
| 默认页 | 费用总览 | 本期经营费用、期间变动、结构与趋势、重点变动、费用状态 |
| 分析页 | 费用分析 | 城市对比、费用构成、支出对象；经营费用、采购、损耗分别查看 |
| 明细页 | 支出明细 | 费用记录、状态、金额、原始来源、本期与可比期切换 |
| 分析弹层 | 费用变动分析 | 期间对比、业务核对事项、分类或城市结构、两期明细入口 |
| 说明弹层 | 指标口径说明 | 费用范围、计算规则、期间规则与数据适用限制 |

页面标题使用明确业务名词。按钮使用“进入费用分析”“本期费用明细”“可比期费用明细”“导出全部匹配单据”。文案变更覆盖页面、弹层、图例、表头及导出，不仅修改首页标题。

| 旧表述 | 本版表述 | 业务含义 |
| --- | --- | --- |
| 钱主要花在哪些方面 | 经营费用结构 | 各费用类别金额及占比 |
| 优先查看哪些变化 | 重点费用变动 | 城市与费用类别的增减金额TOP 3 |
| 费用累计到哪一天开始拉开差距 | 经营费用累计趋势 | 两期费用发生额累计比较 |
| 哪些变化形成了本期金额 | 费用变动构成 | 可比期金额经各项增减形成的本期金额 |
| 结合经营规模看费用 | 城市费用规模参照 | 每百元订单应收金额对应的已登记经营费用 |

“支出明细”指费用登记记录，不代表银行付款明细。“已付款”“未付款”仅描述台账付款状态。增加不自动认定异常，减少不自动认定节约。原型中的版本、虚构数据标识和演示场景工具不进入正式业务界面。

## 03 全局筛选与期间规则

全局条件为年份、月份或全年、授权城市、对比方式。默认当前年当月、全部授权城市、上期对比。使用Asia/Shanghai业务时区。正式系统由服务端返回有效截止日期及快照生成时间，不依赖浏览器时钟，也不能用“最后一笔费用的日期”判断数据已录全。

| 条件 | 规则 | 边界处理 |
| --- | --- | --- |
| 当前月 | 月初至数据截止日；上期为上月同日起止范围 | 上月天数不足则裁剪到月末，并显示两期实际日期 |
| 历史月 | 完整自然月；上期为上一完整自然月 | 月份长度不强行补齐，明确实际区间 |
| 去年同期 | 去年对应月同区间 | 闰年2月29日裁剪至合法日期 |
| 全年 | 当前年截至数据截止日；历史年为全年 | 固定比较上年同区间；前端不能暗示比较上一月份 |
| 城市 | 默认授权城市集合；支持单城市及待归属组 | 待归属可见性来自原业务数据权限，不是全租户公开 |
| 未来期间 | 不开放查询 | 年月选项禁用未来月份；接口拒绝超出可用范围 |

切换年份、月份、城市或对比方式后，保留当前页面，清除该页面下钻条件及搜索词，明细回本期与第1页；状态和付款筛选保留并显式展示。所有金额、图表、排名和导出基于相同条件重新计算。返回费用总览时分析范围固定恢复经营费用。

显示本期与可比期的起止日期、人民币单位、数据更新时间。切换条件读取期间展示加载状态，响应未完成前不展示上一个范围的金额。快速连续切换时仅接受最后一次请求结果。

后端区分“读取完整但该分组无记录”和“缺少历史覆盖”。前者分组金额可为0；后者不计算增幅、变化排序和瀑布。首版无任何可比期确认记录时保守标注“无可比数据”，不将缺历史解释为零基数。真实零金额记录与无记录、空金额分别处理。

## 04 费用总览页面规格

阅读顺序为费用概况、重点费用变动、累计趋势及费用结构、采购与损耗、费用状态及归属。主指标突出经营费用；采购和损耗保持独立入口，避免被相加理解为财务总成本。

| 区块编号 | 字段与展示 | 操作及计算规则 |
| --- | --- | --- |
| O01 费用概况 | 本期已确认经营费用、确认笔数、可比期金额、变动额、增幅 | 进入费用分析保留全局条件；金额单位元，两位小数 |
| O02 统计摘要 | 期间增减金额、最大费用类别及占比 | 仅按事实组合固定模板，不生成原因和异常判断 |
| O03 重点费用变动 | 增加合计、减少合计、净变动额；前三个城市费用项 | 默认费用增加，可切换费用减少；卡片显示城市、类别、差额、贡献占比 |
| O04 累计趋势 | 本期与可比期累计曲线、精确累计终值 | 查看支出进入当前经营费用明细；悬停显示日期和累计额 |
| O05 经营费用结构 | 环形图、类别、金额、占比 | 点击扇区或图例打开类别分析，再按城市下钻 |
| O06 采购与损耗 | 两项独立金额及入口 | 进入相应范围的城市分析，不计入O01 |
| O07 费用状态及归属 | 未付款费用、待确认笔数及已填金额、缺金额笔数、待归属费用 | 默认折叠；分别进入对应明细；待确认不计入已确认指标 |

重点费用变动按城市×费用类别建立互斥单元。增加项按正差额降序取3项，减少项按负差额绝对值降序取3项；并列以稳定城市键、类别码排序。少于3项据实展示，不填充空卡。该区块不是自动异常预警。

增加合计为全部正差额之和，减少合计为全部负差额绝对值之和，净变动额等于二者之差。卡片贡献占比以同方向合计为分母。不得使用净变动额作为贡献分母，避免正负抵消后比例失真。

数据源读取失败、权限导致统计范围缩小等会影响理解的状态必须在主内容上方显示，不得收进折叠区。待归属费用保留在可见总额和结构中，不归入任一已知城市。

## 05 图表规格与展示规范

本版不使用横向条形图。图形必须直接表达业务关系，并提供精确数值或对应明细；不得通过新增装饰图形替代真实分析功能。

| 图表编号与名称 | 图型及编码 | 联动与特殊情况 |
| --- | --- | --- |
| G01 经营费用结构 | 环形图；扇区按费用类别编码，面积表示金额占比 | 图例列金额与占比；类别颜色跨页固定；点击类别下钻 |
| G02 经营费用累计趋势 | 双折线；横轴日序或月份，纵轴累计金额 | 本期实线，可比期虚线；无可比数据不绘制假零线 |
| G03 城市费用对比 | 纵向分组柱图；本期蓝色，可比期灰蓝 | 共享从0开始的金额轴；按本期降序展示最多8城，完整城市见矩阵 |
| G04 城市费用分布 | 城市×费用类别矩阵 | 金额、城内占比、变动额三模式；点击单元格携带两个条件 |
| G05 费用变动构成 | 纵向瀑布图；可比期起点、类别增减、本期终点 | 增加用暖色，减少用青色；标注正负号，不按好坏评级 |
| G06 支出对象金额排名 | 纵向柱图；当前维度金额TOP 8 | 不是TOP 8内部占比；下方保留全部对象及其金额、占比、笔数 |
| G07 费用发生趋势 | 纵向分组柱图；最近六个月与可比期，全年按当年逐月 | 当前未完月标注截止日；点击本期月份按该月重新查询 |
| G08 城市费用结构 | 环形图；用于采购、损耗及类别下钻 | 超过6组显示前5组与其他城市；其他组可展开全部组成城市 |

费用规模参照使用数值对照表，列为城市、经营费用、订单应收金额、每百元费用。此处需要精确比较分子和分母，不再绘制长度条。

金额轴统一0起点；瀑布按累计起终点计算。图表简写金额可使用万元，悬停和明细始终显示元及两位小数。占比保留一位，分项舍入可能合计99.9%或100.1%，不擅自修改最大项以凑整。零分母显示“—”。

图例用于下钻，不采用点击图例隐去类别后仍保留原总额的模式。单一类别绘制完整环，零总额显示无可计算占比；负金额如来源出现应阻止发布该批次并记录源错误，不能画为负扇区。长名称在柱轴最多两行，完整名称保留在悬停及明细。

## 06 费用分析与业务维度

分析范围包括经营费用、商品采购、商品损耗。每个范围提供城市对比、费用构成、支出对象三个视角。切换范围后先进入城市对比，清理不适用的维度条件；切换专题时同步其所属范围，标题和合计必须一致。

城市对比首先展示矩阵，随后为城市纵向对比及规模参照表或城市环形图。矩阵金额模式共用全表金额色阶；占比模式以各行城市为分母；变动模式按绝对差额着色并保留正负号。不得仅用颜色表达增减。

费用构成视角以环形图和瀑布图并列展示。经营费用按类别拆分；采购和损耗因范围只有一个类别，按城市拆分。瀑布起点加各项变动必须等于本期终点。

| 专题 | 可选分析维度 | 业务规则 |
| --- | --- | --- |
| 运费 | 运输环节 承运方 运输方式 | 仅公司承担；多关联订单不倍增运费 |
| 仓储费用 | 仓库或场地 合同 | 使用录入金额，不按面积、租期生成租金 |
| 办公费用 | 办公场地 合同 | 与仓储按场地类型区分；押金不进入费用 |
| 营销费用 | 费用类型 渠道 经办员工 | 展示费用分布，不推算营销ROI |
| 员工报销 | 报销类型 员工 部门 | 员工与部门按稳定编码分组；遵循报销权限 |
| 商品采购 | 供应商 商品规格 | 使用成本台账登记值，不重复累计采购订单 |
| 商品损耗 | 商品规格 损耗原因 | 只展示已登记损耗额，不推算库存损耗率 |

维度缺失归入“未记录”或“待归属”并保留金额；有主档ID的对象与仅手填名称的对象不自动合并。员工同名不同编码分别显示，名称变化按记录快照展示，分组以稳定ID为准。

对象分析同时显示本期金额、期间变动、未付款金额、TOP 8柱图、按月趋势和全量分组表。分组表占比基数为当前专题全量金额，不能只用TOP 8金额。维度已记录金额覆盖比例用于识别资料缺失，不自动评价业务人员表现。

## 07 下钻 明细与单据追溯

从城市、类别、矩阵格或变动卡进入费用变动分析弹层。弹层继承全局期间、城市、统计范围及授权，展示本期金额、可比期金额、笔数、变动额和增幅。只有一个分组条件时补充另一维度的环形结构。

弹层提供“本期费用明细”“可比期费用明细”，分别查询完整集合；本期主要支出最多显示金额最高8笔，仅作为预览。业务核对事项使用预置说明，不生成自动归因或责任认定。待归属记录提示核对城市归属。

| 明细功能 | 字段与规则 | 状态处理 |
| --- | --- | --- |
| 筛选 | 统计范围、确认状态、付款状态、搜索词、继承的城市类别对象条件 | 搜索单据号、事项、员工及原始单号；查询后回第1页 |
| 期间切换 | 本期、可比期 | 保留城市、类别、对象、状态、付款及搜索条件 |
| 默认列表 | 单据号、事项、类别、城市、费用日期、金额、确认状态、付款状态、详情 | 默认费用日期倒序，再按源服务及源ID稳定排序 |
| 汇总栏 | 匹配笔数、已确认金额、待确认已填金额、缺金额笔数 | 作废不计入已确认；空金额显示未填，不显示0 |
| 分页 | 正式版每页20笔，可选50或100笔 | 原型每页10笔用于交互展示；接口分页与全量合计分离 |
| 详情 | 费用主体字段、业务维度、备注、原始单据来源 | 源ID与版本折叠展示；不同业务域不伪造不存在字段 |
| 导出 | 全部匹配记录，包含当前筛选和期间标识 | 金额与页面全量合计一致；防CSV公式注入，下载时再次鉴权 |

原单跳转由服务端返回经过权限判断的领域页面路由及源ID，目标页再次鉴权。无原单查看权限则隐藏入口，不泄露原单号、附件或跨记录重复提示内容。附件沿用原业务受控下载，不返回永久公开地址。

费用更正仍在原模块进行。更正后返回看板，通过刷新获取新快照；若原记录已作废或无权访问，提示当前记录状态，不继续展示已失效的详情。源系统重复登记仅作为核对事项，不自动去重扣减。

## 08 指标字典与核对公式

统一粒度为一条费用记录，唯一键为tenantId、sourceService、sourceTable、sourceId。所有计算先执行租户和业务权限过滤，再按期间及条件汇总。金额使用BigDecimal或整数分，不能使用浮点数作为最终金额依据。

| 指标 | 公式和集合 | 显示规则 |
| --- | --- | --- |
| 经营费用 | CONFIRMED且金额非空的公司承担运费、仓储、办公、营销、报销、待分类场地费用之和 | 金额单位元，2位小数；不含采购、损耗、工资、押金 |
| 采购登记金额 | ERP PURCHASE确认且非空金额之和 | 独立指标，不等于已售商品成本 |
| 损耗登记金额 | ERP LOSS确认且非空金额之和 | 独立指标，不等于损耗率 |
| 变动金额 | 本期金额－可比期金额 | 有符号；无可比数据为— |
| 增幅 | 变动金额÷可比期金额 | 可比期0时显示零基数；不计算无穷大 |
| 结构占比 | 当前分组金额÷当前范围全量确认金额 | 0分母为—；未记录维度仍在分母中 |
| 变动贡献占比 | 单元增加额÷全部增加额，或单元减少额绝对值÷全部减少额 | 分母按同方向；不得除以净变动额 |
| 累计费用 | 起始日至当前横轴日期的费用金额之和 | 按费用发生日期累计，不按登记或付款时间 |
| 未付款费用 | 同一确认集合中paymentStatusCode为UNPAID的金额 | 是状态快照，不能推导逾期和实际实付 |
| 每百元费用 | 可对齐城市的经营费用÷同期有效订单应收金额×100 | 订单应收为0、缺费用或覆盖不齐显示— |

必须满足：类别合计＝城市合计＝确认明细合计＝主指标；累计曲线终点＝相应期间主指标；增加合计－减少合计＝本期－可比期；瀑布起点＋增减＝终点。付款状态枚举出现未知值时单列未记录，不能默认已付款。

演示核对值：2026-10-01至10-16经营费用180,048.71元；上月同期174,569.00元；净增5,479.71元；增加合计33,177.09元，减少合计27,697.38元。采购327,222.00元、损耗13,795.92元均独立。全部为虚构测试数据，不是经营结论。

## 10 权限与页面状态

页面权限与费用数据权限分别校验。经营负责人、CEO、老板是使用者身份，不代表自动拥有全公司费用或报销权限。所有查询、下钻、导出、缓存、详情与原单跳转采用一致的授权范围。

| 场景 | 页面行为 | 后端规则 |
| --- | --- | --- |
| 无看板权限 | 无入口；直接访问显示无权限 | 拒绝查询，不返回费用数据 |
| 部分城市权限 | 城市筛选仅含可见范围，标题注明授权范围 | 请求城市与授权范围求交集；越权参数拒绝 |
| 无报销权限 | 明示经营费用不含员工报销，报销专题不可见 | 汇总、明细、员工字段和关联提示均排除 |
| 待归属记录 | 仅展示源权限允许的待归属金额 | 没有城市映射不等于没有访问限制 |
| 首次加载 | 加载状态，保留筛选 | 不返回部分来源拼接结果 |
| 无本期数据 | 当前范围没有已登记数据 | 空集合与合法0分开，不显示无费用结论 |
| 无可比数据 | 本期正常，变动额、增幅、排序与瀑布不可用 | comparisonAvailable为false并返回原因 |
| 来源读取失败 | 提示失败；同范围旧完整快照可继续展示并标时间 | 无旧快照则只显示失败；不得混合不同批次 |
| 会话或权限变更 | 重新授权并清理不适用缓存 | 旧快照不能绕过当前权限；导出下载再次鉴权 |

报销权限不足导致的有意范围排除与报销源读取失败必须区别处理。前者可展示授权子集及范围提示；后者不得假装总额完整。缩小范围后的比较两期必须一致，规模参照只有两侧权限粒度一致才开放。

导出权限需独立控制，拟新增supply.bi.city-cost.export；已有权限目录命名若有统一规范，按规范落位并保持同一含义。查询、导出审计记录操作者、租户、时间、筛选、快照版本及结果状态，不记录敏感单据正文。

## 11 查询契约与研发分工

调用链为Portal → Gateway → BI查询服务 → BI本地读模型。ERP、Order、HR继续作为原业务数据单一写者，通过内部analytics-source接口提供分页事实。不得由Portal跨服务拼总额或由BI跨业务库执行SQL。

以下为拟新增接口契约，尚未上线。统一前缀 /api/v1/bi/cost-dashboard，实际遵循项目API版本规范；tenantId、操作者与授权信息由可信请求上下文提供，不能接受客户端自报权限。

| 查询能力 | 请求关键字段 | 返回关键内容 |
| --- | --- | --- |
| GET overview | year month compare city scope | 指标、确认笔数、状态统计、期间、快照及范围说明 |
| GET changes | 共用条件、direction、limit | 单元城市及类别、本期可比期差额、同方向贡献、增加减少总额 |
| GET breakdown | 共用条件、dimension、category、对象过滤、topN | 全量总额、分组金额占比笔数、未知覆盖、其他分组构成 |
| GET trend | 共用条件、grain、cumulative、category | 每点实际日期、金额、可比值、覆盖与截止状态 |
| GET records | 共用条件、periodSide、category、dimensionKey、status、payment、search、page、size | 全量汇总、totalCount、分页记录；金额不按当前页合计 |
| GET records详情 | sourceService sourceId snapshotId | 授权详情、业务维度、可访问原单路由及状态 |
| POST exports | 与records相同筛选、snapshotId | 导出任务ID；GET任务状态及受控下载地址 |

overview首次返回snapshotId，其余组件及下钻携带同一版本；正式刷新获取新版本后整体切换。全部响应携带metricVersion、snapshotId、generatedAt、effectiveCutoff、实际两期、includedSources、excludedScopes、comparisonAvailable和dataState。金额用十进制字符串或整数分，缺失值为null。

维度参数仅允许已定义枚举；超界月份、未来月份、不兼容专题维度与越权城市返回明确错误，不静默忽略。快照过期返回SNAPSHOT_EXPIRED，前端提示刷新整个范围，不能独自刷新一个图表。缓存键包含租户、权限版本、口径版本、快照及查询条件。

Portal按现有Vue组件和图表封装实现，手写API放src/api/core，禁止手改生成接口。BI负责统一指标、分组和权限；各领域负责事实读取、状态变化及版本稳定性；测试按同一数据集覆盖两端契约与用户路径。

## 12 数据更新与数据库实施

本次必须新增三个费用数据集及对应BI本地投影。具体表名和迁移序号在开发时按现有目录分配；不得复用历史bi_city_cost_record或前端样例金额作为现有成本事实。首次全量，后续按可靠源版本更新，并保留租户与来源唯一约束。

| 实施项 | 必须实现的规则 | 核验依据 |
| --- | --- | --- |
| 字符串UUID分页 | 增加TEXT_UUID键类型，统一排序、游标校验及续页 | 1001笔以上、边界重复值、并发变更无漏重 |
| 源版本推进 | 新增、编辑、确认、作废在源事务内更新可靠版本 | 不假定现有guard.version覆盖所有写路径 |
| 一致性发布 | 校验源读取前后版本，三个必需源完成后发布完整批次 | 单源失败保留上个完整批次；版本变化则重试 |
| 删除与更正 | 作废、回草稿、金额及日期变更反映到当前与历史期间 | 全量重建或可靠删除标记，不能仅追加不删除 |
| 可追溯性 | 保留原字段、映射状态、源版本和批次 | 图表和导出能定位源记录及统计口径 |
| 数据更新规则 | 与销售业绩看板一致：未由集中计划接管时，复用 BI 刷新配置，默认每轮完成后间隔1小时，服务启动后60秒首轮；集中接管后按同一 `BI_REFRESH` 计划的频率及启停执行 | 2026-10-19 用户确认替代原5分钟/10分钟目标；以环境有效配置为准，尚未进行部署调度验收 |

多源版本校验提供一致的发布批次，不代表跨数据库同一瞬间的分布式快照。页面显示最后成功更新时间，运维保留各源版本及读取完成时间。旧批次保留供在途查询，拟定保留24小时；过期统一要求刷新。

页面与销售业绩大屏一致，在进入、切换条件、点击刷新时重新读取已发布批次，不设置独立页面轮询；页面刷新不代表立即重新同步全部业务来源。首次无批次时可进行一次初始化。集中计划停用后不得通过旧定时入口绕过；来源失败保留上个完整批次并提示更新延迟，不再以超过10分钟作为延迟判定。

数据库变更仅通过新增迁移实施。操作前核对有效profile、Nacos最终配置、目标实例和schema、租户与主键类型、flyway_schema_history。新表字符集按项目utf8mb4及utf8mb4_general_ci规范；迁移前校验，禁止clean、自动baseline、乱序迁移、改已发布脚本或repair掩盖冲突。

DEV/local启动可能执行共享库迁移，不能作为只读检查。正式环境迁移由既有发布流程执行，不通过生产启动自动运行。实现遵循interfaces → application → domain，基础设施实现端口；跨服务使用既有服务名寻址、签名和数据权限链路。
