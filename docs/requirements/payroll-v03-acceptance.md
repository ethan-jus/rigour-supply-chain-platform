## 结论与环境

**已验证核心闭环：员工薪资标准 → 独立规则 → 选月份与员工 → 批量计算 → 工资表 → 绩效、商品分类、SKU、订单明细 → 回款来源 → Excel。不能宣称 V0.3 全部增强功能已完成。** 尚未完成项和未执行项见下表，不能以原型演示代替正式验收。

- 正式前端：本机 Portal 5100；本机 HR 26889，连接现有 DEV 领域服务；通过现有 IAM 登录，不绕过权限。
- 北京两位指定测试人员使用真实员工入职日期、订单、回款、ERP 商品以及 Sales 打卡来源。底薪、绩效金额和未确认 SKU 标准保留“测试”标识，不作为真实发薪标准。
- 本轮通过界面重新核算两人，结果均为“待确认”；人工底薪、绩效、补贴覆盖均未参与最后一次结果。
- 未确认、登记或实际发放工资；未修改真实订单、回款、ERP 商品、Sales 打卡记录；本轮未新增数据库迁移。
- 原型是独立演示会话，其示例工资不等于正式系统按真实来源计算的测试结果。

## 本轮发现并修复

1. 员工档案不能因具有员工资料查看权限就隐式获得薪资查看、修改权限；后端和界面分别检查薪资权限。
2. 一位销售旧测试工资有人工底薪覆盖，导致不能证明由档案规则计算。通过界面清除覆盖并重新核算；清除操作保留补发补扣和其他扣款。
3. 批量核算跨筛选丢选：采用表格保留选择、按员工编号去重、月份变化清空选择。
4. 提成追溯补充订单金额、累计回款、退款、首次付清日和核算截止日；跳转回款列表展示的是当前源单，历史工资仍引用核算快照。
5. 绩效逐日扣减属于封顶前原始扣减；页面和 Excel 明确标注，月度实际扣减以过程额度封顶，避免二次扣款。
6. 城市总 Excel 移除不适用的单项系数，新增综合绩效汇总，显示基数、加权完成率、综合系数、保护/考核天数和结果。
7. 提成、补贴列表从一条规则摘要改成具体商品标准、补贴项目行，标准金额、角色、单位、编码和版本明确可查。
8. 薪资标准区分当前与未来版本，展示三档金额和调薪对比；未来变更、过期版本和读取权限的回归通过。
