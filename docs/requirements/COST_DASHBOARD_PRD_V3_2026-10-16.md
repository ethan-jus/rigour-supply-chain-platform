# 成本数据看板产品需求与设计方案

版本 V3.0　日期 2026-10-16　适用对象 经营负责人 CEO 老板

本版将成本看板定位为经营管理工具。使用者先了解费用规模与变化，再找到主要城市、费用类别和支出对象，最后追溯原单据。设计结合 Microsoft Power BI、Dynamics 365、SAP Concur、合思 BI 的官方分析模式，以及本系统当前已有的成本、报销和销售数据。业务继续在原模块录入，看板读取并计算。

## 01 面向管理层的设计目标

主使用者已明确为经营负责人、CEO 和老板。首页服务于经营例会和日常查看，财务处理、来源诊断和录入不占据首页主要位置。金额大小只表示支出规模，不能直接推导费用合理性、城市经营好坏或可节约金额。

| 管理层问题 | 本版回答方式 | 下一步动作 |
| --- | --- | --- |
| 费用规模有多大 | 经营费用 商品采购 商品损耗分开显示 | 切换所需范围，下面全部分析同步变化 |
| 与上期相比发生什么变化 | 同期对比、变化金额与瀑布拆解 | 查看增减最大的类别或城市 |
| 钱集中花在哪里 | 类别金额、占比及前若干项集中度 | 类别到城市，再到原单据 |
| 哪些城市值得进一步看 | 城市和费用交叉矩阵、同尺度对比 | 查看某城某项费用及其支出记录 |
| 城市规模差异如何理解 | 已登记费用与同期交易额参照 | 回看费用集合及销售数据范围 |
| 具体花在什么事项上 | 七类成本专题中的对象排行 | 查看承运方 场地 渠道 供应商 员工等 |

设计判断：V2 完成了基本金额与占比展示，但对管理层而言，缺少清晰的变化解释、城市与类别交叉分析，以及现有业务对象的进一步拆解。V3 调整信息层级与分析路径，保留现有双层导航、深色看板、蓝绿配色和期间筛选习惯。

范围包括新版需求、原型和实现方案。正式入口继续使用数据看板中的成本入口，保留 /supply-chain/bi/city-cost 与 supply.bi.city-cost。V1 和 V2 保留作历史参考，后续展示设计以本版为准。

调研日期为 2026-10-16。以下为官方文档明确描述的功能模式，非产品排名、市场份额或购买建议；未登录厂商付费系统做实际采购评测。借鉴分析逻辑，视觉继续遵循本系统。

所有成本与报销共享确认状态 DRAFT、CONFIRMED、VOID。成本金额来自原单登记值，不重新以商品参考价格乘数量、不重新生成租金、不推导外部订货宝费用。台账里已有的外部来源与原始单号仅用于追溯。

薪酬在系统中另有核算及支付功能，不能误称为不存在；但其归属月份、确认更正、薪资权限及是否计入本次经营费用需另行确定，本期不直接加进这三类费用台账。销售交易额已有明确指标，但“收入确认、完整经营成本、利润”不能由本版字段自动替代。

## 04 页面结构和默认阅读顺序

全局保留年份、月份或全年、授权城市、上期或去年同期对比。顶栏始终显示实际本期与可比期日期，单位为人民币元。默认当月截至最近完整可用业务日，不拿当月半月与上月全月比较。原型截止日固定为 2026-10-16。

| 页面 | 页面内容 | 交互目标 |
| --- | --- | --- |
| 经营总览 | 三范围金额卡、变化额、集中度、未付款辅助指标；费用走势、金额占比、变化瀑布、本期重点查看 | 先发现变化，再定位类别 城市 |
| 城市与结构 | 城市与费用矩阵；金额 城内占比 增减切换；城市双条对比；经营规模参照 | 一屏同时比较城市和费用项 |
| 成本专题 | 物流 仓储 办公 营销 报销 采购 损耗；每类使用对应业务维度 | 从类别进入承运方 场地 渠道 供应商 员工等 |
| 单据追溯 | 期间与范围标签、状态 付款 搜索、精确金额、分页及全量导出 | 查证图表对应的原始支出 |

经营总览和城市页顶部的三张卡是互斥分析范围：经营费用、商品采购、商品损耗。切换范围后趋势、构成、变化、城市矩阵及下钻都切换，不做三个范围的相加总成本。专题页自己选定业务类型，同时锁定对应范围。

金额采用大数字；构成用排序条形加金额与百分比；变化用瀑布桥接；城市关系用交叉矩阵。趋势和对比采用统一零起点刻度。颜色主要区分系列和类别，不能只凭红绿判断费用健康。

示例路径：老板发现办公室费用增加 → 点击重点查看 → 看城市分布 → 点击武汉办公室费用 → 看该格金额及对比期 → 查看对应单据。每一步保持期间、城市、类别和权限条件，清除或返回必须明确，不静默扩大数据范围。

## 05 统一指标和统计口径

基本粒度为一条成本或报销记录。唯一键使用 tenantId + sourceService + sourceTable + sourceId。一张运费记录关联多张订单、多个配送点或附件，金额仍只统计一次。按供应商和商品展开也必须以费用记录为粒度。

| 指标 | 计算规则 | 解释 |
| --- | --- | --- |
| 已确认经营费用 | 公司承担运费 + 仓储 + 办公 + 营销 + 报销 + 待分类场地费用 | 确认且金额非空；报销已包含其中 |
| 商品采购 | PURCHASE 已确认非空金额合计 | 已登记采购金额，不等于销售成本 |
| 商品损耗 | LOSS 已确认非空金额合计 | 已登记损耗金额，不等于库存损耗率 |
| 较上期变化 | 本期金额 − 可比期金额 | 与本期同一授权及业务范围 |
| 增幅 | 差额 ÷ 可比期金额 | 上期为零不算无穷大；无历史不造增长 |
| 构成占比 | 某类或对象金额 ÷ 当前分析集合金额 | 分母随范围 城市 期间变化 |
| 集中度 | 按金额降序的前若干项累计占比 | 前两项占比；达到80%的最少项数及实际比例 |
| 未付款金额 | 同一确认集合中 UNPAID 金额 | 当前台账付款标记，不是到期应付或现金流 |
| 待确认金额 | DRAFT 中已填金额之和 | 同时列总笔数和未填笔数，不混入确认费用 |

金额用 BigDecimal 或整数最小货币单位计算。最终展示两位小数；图表坐标可用万元缩写，悬浮和明细必须给精确金额。百分比一位小数，城内与全局占比不能混淆，显示和可因舍入为 99.9% 或 100.1%。

合法零元保留记录笔数；空金额显示未填；无记录与真实零值分开。VOID 和非公司承担运费不纳入上述确认费用；押金只作详情字段。未知付款状态单独保留，不能强行归未付款。

跨模块同一经济事项可能被重复登记。ERP 办公费用与 HR 办公租赁报销只能作为疑似重复提示，未经业务确认不自动扣减。这个限制直接影响是否能称为核定财务成本。

## 06 总览趋势和变化分析

费用走势展示最近六个可用月份；全年模式展示该年截至截止日的各月。每个月显示当月和其可比期两条柱，统一尺度。当前月用星号和截止日说明不完整期间，避免把部分月份下降误认为完整月份下降。历史不足显示缺失，不补造零值。

当前月环比：本月1日至截止日，对比上月1日至对应日并裁剪到合法月底；历史完整月按完整自然月对比，实际天数差异在说明中保留。同比使用上年相同区间，2月29日按上年合法月底裁剪。全年模式“上期”和“去年同期”均使用上一年同截止日，界面说明二者等价。

| 图表或提示 | 计算与展示 | 下钻 |
| --- | --- | --- |
| 费用构成 | 当前类别排序条形、金额、占比及累计集中度 | 类别到城市，再到单据 |
| 变化瀑布 | 从上期合计开始，依次加各类差额，终点等于本期合计 | 配套变化项目及城市入口 |
| 采购损耗变化 | 对应范围内按城市差额拆解 | 城市及对应范围单据 |
| 增加金额最大 | 同范围中正差额最大项，显示绝对金额 | 查看该项城市分布 |
| 城市变化金额最大 | 已映射城市按差额绝对值取最大 | 查看该城构成；待归属金额另保留 |

瀑布条段的高度和起终点必须表达金额，连接线显示前后累积值；各差额合计等于总差额。增加与减少使用中性对比颜色，文案只说金额增加或减少，不称异常、浪费或节约。

没有可比期覆盖时不画变化桥接、不生成“最大增长”结论。当某类别可比期零而本期非零，标为上期零基数，仅显示金额变化。分组缺失只有在整个可比期数据已完整覆盖时才能视作该组无记录。

## 07 城市交叉分析和经营参照

城市与结构页以城市为行、费用类别为列，保留待归属城市。默认显示金额，每格可同时显示城内占比。提供金额、城内占比、较上期变化三个模式，全部来自同一集合。金额颜色按全表统一尺度；占比按各城100%；变化颜色深浅按绝对差额，并明确正负号。

点击单元格打开分析抽屉，显示该城市该类别的本期、可比期、差额及金额最大的8笔单据；查看全部保留交叉条件。点击城市行查看该城的构成，再点击类别不能丢失城市条件。待归属城市也能下钻，不自动将其归总部或公共费用。

城市金额排名只回答谁登记更多费用。经营规模参照回答另一个问题：每100元交易额对应多少已登记经营费用。计算为已确认经营费用 ÷ 同期销售订单应收金额 × 100，使用已有 BI salesAmount 定义，即 bi_sales_order_fact.payable_amount，按 order_date 排除删除和 CANCELLED 订单；不得替换为回款额、商品行金额或会计收入。

| 参照成立条件 | 展示规则 |
| --- | --- |
| 同一租户 城市 期间 | 费用按 cost_date，交易额按 order_date；日期区间完全一致 |
| 城市映射确定 | 使用现有经营城市与地区映射；缺失或多义不猜，列出排除金额 |
| 权限范围兼容 | 两侧使用相同城市及可比数据范围；只有部分费用权限时标注所含类别；订单仅部分员工范围时不计算全城比值 |
| 来源完整且金额大于零 | 交易额为零 缺失 读取失败时显示不可计算；费用缺失不能当零 |
| 只作经营观察 | 同期发生不保证收入与费用会计配比，不叫利润率或核定费用率，不设未经批准红线 |

原型用独立虚构订单事实展示此逻辑，没有以成本金额反推销售额。正式实现直接复用 BI 已有订单事实与权限能力，只增加跨指标范围校验。该参照仅用于经营费用，不把采购额或损耗额替换进分子。

## 08 七类成本专题

每个专题统一提供确认金额、较可比期变化、未付款辅助数、对象排行、走势、全量对象列表和单据入口。对象榜只显示前10项，完整列表和金额分母包含全部对象。维度选择只提供当前专题确实存在的字段。

| 专题 | 分析维度及来源字段 | 处理规则 |
| --- | --- | --- |
| 物流费用 | legCode carrierName transportMethodCode | 三段运输分开；公司承担；每条运费统计一次，承运方按名称快照归组 |
| 仓储费用 | warehouseId warehouseName；rental.premisesName | 仓库ID优先；手填场地单独保留，不根据名称随意合并 |
| 办公费用 | rental.premisesName contractNo cityCode | 场地和合同快照定位；无稳定场地ID时展示名称归组提示，不声称已统一物业主档 |
| 营销费用 | typeCode marketing.channelName ownerEmployeeCode | 类型复用业务字典；渠道按录入字符串；不计算投入产出或自动摊销 |
| 员工报销 | typeCode employeeCode departmentId | 员工及部门使用编码；名称为快照；同名员工不合并 |
| 商品采购 | goods.supplierId supplierName productId variantId specification | 有ID用ID；手填名称单列；规格不可只按商品名混算 |
| 商品损耗 | goods.lossReason productId variantId warehouseId | 先展示原因和商品；缺原因归未记录；不以新参考价回算历史损耗 |

字段完整性在当前专题说明或详情中体现：已记录维度金额覆盖率 = 具备该维度的确认金额 ÷ 专题确认金额。未知项仍进合计和占比。覆盖率只描述字段填写程度，不代表费用准确、合规或经济去重完成。

部门并不是所有费用的天然共同维度。HR 报销和部分 ERP 记录有 departmentId，不能给物流、采购或场地按录入人部门自动分摊。跨全成本的部门成本排行暂不开放。面积、数量、租期虽存在，也不能混单位或跨期间直接算每平方米每月成本、每单配送成本。

## 09 单据追溯和交互状态

从任何图表下钻时，查询上下文必须包含租户、授权范围、口径版本、数据版本、本期与可比期、范围、城市、类别及所选业务维度。抽屉先给业务事实和对应单据，来源服务、源键、版本等放在可展开区域。

| 操作 | 明确行为 |
| --- | --- |
| 图表下钻 | 显示当前条件及相应合计，保持与点击金额一致 |
| 本期和对比期切换 | 只切日期，保留其他条件，不把两期单据混合 |
| 清除下钻 | 只清交叉条件；全局期间 城市 权限仍生效 |
| 状态筛选 | 确认 待确认 作废可查询，合计分别标识，作废不进确认金额 |
| 搜索 | 单号 事项 员工 原始单号；条件与全量导出一致 |
| 导出 | 全部匹配记录，不仅当前页；保留空金额 原始来源 源ID 日期 口径和查询上下文 |
| 原单跳转 | 回所属 ERP Order HR 页面再次鉴权，修正发生在原领域 |

导出必须在服务端再次校验范围，并使用与图表一致的数据版本；大导出沿用现有异步机制或分页流式读取。CSV 处理逗号 换行 引号与公式前缀；文档和导出不得泄露不可见报销员工或疑似重复对方的信息。

空数据展示没有登记数据；真实零金额显示零及笔数。加载失败保留上次完整成功数据并标过期；禁止某源失败导致整类金额假性归零。报销无权限时排除该类别并明确当前合计不含报销，不显示报销为零。筛选选项、图表、抽屉、来源、导出使用同一授权范围。

## 10 服务分工和实现方式

调用路径保持 Portal → Gateway JWT 与 IAM 会话校验 → BI 查看权限与数据范围 → BI 本地分析数据。BI 通过 ERP、Order、HR 的内部 analytics-source 契约读取已有台账，复用 bi_source_* 投影；销售参照直接用 BI 已有订单事实。业务不再录入看板专用数据，也不新增外部采集服务。

| 组件 | 实施内容 |
| --- | --- |
| ERP Order HR | 增加费用读取契约和必要专题字段，输出原状态 城市 金额 日期 权限字段及源身份，保持本域唯一写者 |
| BI 接入 | 三类费用数据集、TEXT_UUID 分页、可靠变更版本、完整成功结果发布；解析所需 JSON 字段 |
| BI 计算 | 统一金额集合、期间、范围、城市映射、分组、对比、矩阵、瀑布和经营参照条件 |
| Portal | 复用现有成本入口和销售城市看板组件，手写 API 放 src/api/core，图表使用现有图表库 |
| IAM | 沿用原入口权限，补明确查看 导出和原单访问；与源类别和行级权限求交集 |

建议接口前缀 /api/v1/analytics/supply/cost-dashboard。GET /overview 返回三范围指标、趋势、构成、变化和重点项目；/matrix 返回城市类别单元格；/topics/{category} 返回可选维度及分组；/operating-reference 返回交易额参照及可比条件；/entries、/entries/{id} 和 /export 提供追溯；/filter-options 返回授权选项。

共同响应包括 range、comparisonRange、unit、metricVersion、snapshotVersion、lastSuccessfulAt、coverage、restrictedCategories。金额为精确十进制字符串；不可计算返回 null 和 reasonCode，不能只给0。响应中提供每个点击项的 drillFilter，前端不另写另一套金额口径。

展示读取最近完整结果，页面刷新重新查询。源变更由既有 BI 刷新流程反映，建议以5分钟作为初始联调目标，实际频率根据当前刷新调度与容量确定，不承诺实时生效。后台技术状态保留在运维或说明层，不占经营首页。

## 11 数据一致性和上线边界

当前源码已确认三个成本台账尚未进入现有 BI 成本读取链路。已有源记录不代表页面现成可读，需补足内部契约与计算。旧 bi_city_cost_record 和 cockpit-costs.ts 示例不与新事实叠加，生产不可用演示数据回退。

| 风险 | 必须实施的规则 |
| --- | --- |
| UUID 字符串分页 | 原费用 ID 为 VARCHAR UUID；适配当前仅数值或二进制UUID的游标查询 排序 校验，验证1001笔以上无漏重 |
| 变更版本 | 新增 修改 确认 作废在本域事务内推进可靠版本；不能假设现有 guard.version 已完整递增 |
| 部分批次 | 读取前后校验源版本；单源失败保留旧完整结果，不发布不一致混合金额 |
| 城市语义 | 复用 OperatingCitySql 经营部门与 CRM 地区映射；歧义保留待归属 |
| 权限范围 | 成本来源权限和 BI 权限求交集；缓存含权限版本，报销隔离覆盖重复提示与导出 |
| 源更正 | 确认后编辑回 DRAFT；作废移出确认合计；不同快照不能混用图表与明细 |
| 名称与编码 | 员工 供应商 商品优先稳定ID；自由名称按快照展示，不自动判为统一主体 |

源版本校验不等于跨服务同一时刻的分布式数据库快照。运营页面显示最近成功时间，运维保留各源版本和完成时间。

数据库操作前核对 profile、环境变量、Nacos 的最终配置、实际实例和 Schema、租户类型及 flyway_schema_history。DEV/local 启动可能自动迁移共享库。新增迁移遵守 utf8mb4_general_ci、validate、禁止 clean/自动baseline/out-of-order，不能改已发布 V/B 脚本或用 repair 掩盖失败。保持服务分层，不跨业务库 JOIN，不将凭据或真实导出入 Git。

本期不包含成本预算、预算执行、存货结转、完整利润、实际付款现金流、逾期应付、营销ROI、自动分摊和自动异常判责。未来加入须先具备事实、口径、权限和验收证据。界面不放无数据支撑的虚假指标占位。
