# ERP 与订货宝响应字段差异及补齐记录

更新时间：2026-08-11

## 对比口径

本次按以下链路核对，而不是把订货宝原始 JSON 直接复制到 ERP：

```text
订货宝接口响应 -> Integration Dhb*View 规范化响应 -> ERP 本地实体/API -> Portal 展示
```

依据：`docs/DHB_API_CONTRACT.md`、`docs/ERP_SUPPLY_CHAIN_DATA_DESIGN.md`、
`docs/ERP_PRODUCT_MASTER_DATA_V2_DESIGN.md`，以及 Integration 中的供应链和商品主数据规范化模型。

## 已确认的缺失与处理

| 数据域 | 之前缺失或不完整 | 本次处理 | Portal |
| --- | --- | --- | --- |
| 供应商 | 来源 ID/GUID、地址、邮箱、开户名称、发票抬头、纳税人号、备注、来源更新时间 | 返回完整的已脱敏 ERP 投影 | 列表增加地址、邮箱、发票抬头、备注 |
| 仓库 | 来源 ID/GUID、原始状态码、协作方 ID | 同时返回展示值和原始 `T/F` 状态码 | 保留 `T=正常`、`F=停用` 和备注展示 |
| 库存 | 商品/仓库 GUID、第一和第二规格 GUID/编码/名称 | 返回全部规范化库存维度，仍按仓库编码数值正序 | 继续展示仓库、商品、规格和数量 |
| 采购单 | 来源单据 ID、供应商/仓库来源 ID、经办人、下载标记、备注、内部沟通 | 列表投影补齐 | 列表增加经办人，详情保持源响应方向 |
| 采购退货 | 来源单据 ID、供应商/仓库来源 ID、经办人、联系人、城市路径、父单、设备、下载标记 | 列表投影补齐 | 列表增加经办人，详情展示联系人、城市、父单 |
| 入库单 | 来源入库单/仓库/供应商 ID、经办人、快递单号、运费、来源时间、备注 | 列表投影补齐 | 列表增加经办人、运费 |
| 入库单详情 | ERP 原先没有对外详情查询 | 新增 `GET /api/v1/erp/warehousing-receipts/{id}`，返回头、明细、关联采购单 | 新增详情按钮、详情弹窗和明细表 |
| 商品 SPU | 来源分类/品牌 ID、`multi_id`、换算条码 | 实体、迁移、ERP API 和 Portal 均补齐 | 商品列表和 SKU 抽屉展示 |
| 商品图片 | 商品来源 ID、原名、原始文件地址 | API 返回安全元数据和短时 URL | SKU 抽屉展示图片名称 |
| SKU | 第一/第二规格值来源 ID | 实体、迁移、导入和 API 均补齐 | SKU 明细展示两个规格值来源 ID、规格组合 ID、市场/采购价 |
| 分类/品牌 | `externalReferenceId` 未在 ERP API 返回 | 从来源绑定的 `sourceCode` 返回 | 列表来源信息中展示 |
| 规格 | 只有规格值数量，没有嵌套值明细 | API 返回 `values`，包含来源 ID、父级 ID、编码、名称、排序和状态 | 规格列表展示规格值名称 |
| 标签 | 当前规范化模型已完整 | 不重复加字段 | 保持现有展示 |

## 数据库迁移

- `V9__erp_warehousing_source_identity.sql`：入库单增加来源仓库 ID、来源供应商 ID。
- `V10__erp_product_response_fields.sql`：SPU 增加来源分类 ID、来源品牌 ID、换算条码；SKU 增加两个规格值来源 ID。

## 明确不直接暴露的字段

这些不是遗漏，而是边界设计：

1. `sourceFields` 留在 Integration Raw Landing，ERP 不复制到公开 API。
2. 商品图片 COS `objectKey` 是私有存储定位信息，ERP 只返回短时访问 URL 和安全的来源文件元数据。
3. ERP 内部状态与订货宝来源状态分开返回，订货宝 `T/F` 不直接覆盖 ERP 内部业务状态。

## 回填条件

历史 ERP 记录在执行 V9/V10 前不会自动拥有新增来源字段；迁移后需对对应对象至少执行一次同步，才能写入新增字段。这是历史数据回填条件，不是接口映射缺失。
