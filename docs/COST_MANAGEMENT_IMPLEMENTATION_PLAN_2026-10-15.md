## 前期架构与实施背景（历史记录）

范围确认日期：2026 年 10 月 15 日。用户明确当前阶段先支持业务方手工录入，由系统保存和查询。目标是货品进货、损耗、三段运费、仓储、办公室、推广广告与代言的人工台账。

一期提供录入、编辑、确认、作废、查询、附件、导出和分类汇总，复用现有费用页面及后台基础。业务方填报数据，系统负责校验、留痕和记录；系统已有单据、商品或仓库可以选用，没有对应数据也能独立登记。

原先提出的库存计价、自动报损扣库、运输分摊、租约自动出账、预算管理、付款核销、关账及 BI 完整经营利润不纳入本期。这些能力不是手工记录的前置条件。本期业务代码与新增迁移已实现，尚未部署到共享环境或执行目标数据库迁移。

### 现有调用链

| 场景 | 实际调用及约束 |
|---|---|
| 用户请求 | Portal → Gateway → 领域 API；Gateway 向 IAM 确认会话，去掉客户端自填身份头并签名；领域服务验证租户、动作权限和数据范围 |
| 服务发现 | Gateway 使用 `lb://`；领域客户端注入 `RestClient.Builder`，通过 `ServiceAddressResolver` 和 Nacos 寻址；不能硬编码对端 IP |
| 外部同步 | Integration 采集、保存原始证据和任务进度 → CRM/ERP/Order/HR 领域投影接口 → 各自数据库 |
| 销售出库 | Order 保存执行意图 → 查询 ERP 执行回执 → ERP 回调 Order claim 核验 → ERP 本地扣库 → Order complete；失败通过回执重查恢复 |
| 物流来源 | Order → ERP `/logistics-cost-sources` 取得采购与调拨；DELIVERY 当前仍由 ERP → Order `/cost-sources/deliveries` 回查订单并补仓库信息 |
| 营销与仓租 | Portal → ERP；营销经办员工通过 ERP → HR 查询，仓库取 ERP 本域，类型来自 Foundation |
| 薪酬考勤 | HR → ERP 商品引用、Order 交易回款事实、Sales 外勤与考勤证据；HR 维护最终确认结果 |
| BI 刷新 | BI → 各领域版本化、分页的 analytics-source → `bi_source_*` → 本域分析表；不跨业务 Schema JOIN |

每个领域是自己 Schema 的唯一业务写者。统一成本入口与统一报表不要求把所有费用搬到同一个服务。旧 [经营成本方案](经营成本核算与人事绩效落地方案.md) 提议 ERP 主写物流和报销，与当前 Order/HR 实现不同；实施前应更新边界说明，不能沿用旧提议造成双写。现有服务边界文档中 AI 等职责描述也包含规划范围。

## 每类登记什么

以下为建议表单字段；日期、归属范围和业务对象至少要明确。金额未知时可暂存，显示“待补金额”，不能转换成零。确认零金额需要说明。

| 页面 | 业务字段 | 登记规则 |
|---|---|---|
| 进货记录 | 日期、归属城市/部门、商品名称、规格、单位、进货单价、数量、金额、供应商、仓库、备注、附件 | 商品/SKU 可选已有数据，也可手填；只知道进货单价时可以先保存，不要求编造数量和总额 |
| 损耗记录 | 日期、归属城市/部门、商品名称、规格、单位、损耗数量、损耗金额、仓库/发生地点、原因、备注、附件 | 数量和金额由业务填报；不知道金额保留待补，不自动从参考采购价估值 |
| 物流费用 | 日期、归属城市/部门、运输段、发货方、收货方、起止地点、承运方、运单号、承担方、运费、备注、附件 | 三段为厂家到中心仓、中心仓到城市端、城市端到客户端；可以不关联采购、调拨或销售订单 |
| 仓储费用 | 仓库名称、地址、面积、费用所属月份、本次租赁费用、备注、附件 | 已有仓库可选择，否则手填名称；合同号、出租方、租期、押金可选，每笔金额明确所属期间 |
| 办公室费用 | 办公室名称、地址、面积、费用所属月份、本次租赁费用、备注、附件 | 作为独立场地类型登记，不需要创建库存仓库 |
| 营销费用 | 日期、费用所属月份、归属城市/部门、类型、事项、金额、收款方、经办人、备注、附件 | 复用推广、广告、代言等字典；无需先建立活动、预算或合同 |

系统单据号、商品、仓库和员工引用全部是可选关联。手填名称和规格按原文保存为记录快照，不生成虚假商品、SKU、仓库或人员，不根据名称猜测业务编码。以后可以补关联，修改要留痕。

单价和数量齐全时，系统可提供乘积作为填写辅助；这不是库存计价。保存金额与乘积不一致时提示并允许填写说明，不能悄悄改掉业务填报数。单位不同的数量不直接求和。

租金由业务按月份或明确的服务期间手工登记。一次付三个月且要分月看时，由业务分别填写各月记录，系统不自动摊销；押金单列，避免混入租赁费。付款状态沿用可选的人工标记，不扩展收付款账务。

## 统一操作与展示

1. 新增、保存、查看、编辑，复用待确认、已确认、已作废状态；确认表示业务已核对本条记录，不表示库存、付款或会计处理已经完成。
2. 记录录入人、录入时间、修改人、修改时间和前后版本；修改已确认记录填写原因并重新确认，作废保留历史，不物理删除费用。
3. 按日期/费用月份、城市/部门、类型、业务对象和状态筛选；查询与 CSV 导出的权限和范围一致，字段包含本类业务明细。
4. 上传图片或票据附件，按既有 fileKey、签名访问和租户归属校验实现，附件可选。
5. 各类列表展示已登记金额、已确认金额和待补金额条数；作废不计入有效金额。跨类别不直接给出“实际经营总成本”或“净利润”。
6. 对重复点击和网络重试沿用 requestId 幂等；相同日期、对象和金额可给重复提示，但不能仅因金额相同阻止正常重复业务。

本期的进货金额只是业务登记的采购记录，不等于已经售出的货品成本；进货记录和损耗记录可能覆盖同一批货，因此不直接相加作为经营总成本。金额为空、确认零金额、作废记录分别展示。既有 BI 样例不能标成这批手工台账的真实汇总，本期不增加自动 BI 投影。

## 代码与数据库操作规范

服务按 `api/interfaces → application → domain/port` 分层，`infrastructure` 实现出站端口；领域层不依赖 Spring 或数据库。跨服务只依赖 API/客户端模块，不依赖 server，不跨库业务查询。当前持久层同时有 MyBatis-Plus 和 JDBC，沿用被修改模块的既有模式。

金额使用 BigDecimal/DECIMAL，按现有数量和单价精度设计；辅助乘法计算明确舍入方式。tenant、权限、数据范围、乐观锁、审计和幂等必须在后端实际执行。Portal token 按规范只存内存；Workbench 当前仍有 localStorage token 和 Hash Router，属于已识别的实现差异，不能照抄旧说明。

数据库执行顺序：

## 验收场景

- 本系统没有对应单据时，可补录订货宝等外部来源的实际单号、单据日期和发收方，再登记并确认三段运费；只保存外部来源快照，不创建正式订单。
- 没有系统商品或仓库，也能登记进货、损耗和场地；原文保存，不自动创建主档或推断 SKU。
- 只有进货单价、缺数量/总额时可保存；未知金额显示待补，不进入已确认金额，也不当作零。
- 录入仓库和办公室名称、面积、所属月份及租金不依赖完整合同；不为办公室创建虚假库存仓库。
- 推广、广告、代言独立登记；附件、手填经办人及系统登录录入人可区分。
- 修改、确认、作废及并发版本冲突有正确提示和历史；重复请求不多生成记录。
- 各类按日期、城市和状态筛选、汇总、导出一致；有效金额不包含作废，跨类不计算未经定义的总成本。
- 无仓库 ID 的手工记录仍受租户和归属权限限制，列表、详情、编辑、历史、附件及导出不能越权。
- 登记和确认不触发库存变化、业务单据生成、付款、自动分摊或 BI 样例回填。

实现后按受影响模块运行定向测试、类型检查和构建；数据迁移、权限及登录业务单独验收。源码实现与专项验证已完成；目标环境迁移、登录后的真实业务及 COS 附件联调仍须验收。
