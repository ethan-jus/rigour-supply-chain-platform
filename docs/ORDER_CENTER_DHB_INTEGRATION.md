# 订单中心与订货宝接入说明

## 1. 接口边界

订货宝官方接口、本平台 Integration 接口和订单中心查询接口是三层边界。第三方协议、凭据、重试和限流只允许存在于 Integration；订单中心不直接访问订货宝。

| 类型 | 接口 | 作用 |
|---|---|---|
| Integration 官方适配器 | `getTokenValue`、`getOrderList`、`getOrderContent`、`getShipsList/getShipsContent`、`getWaitShips` | 认证并同步订货宝原始数据，凭据只从Secret引用读取 |
| 订单中心平台接口 | `GET /api/v1/orders/sales-orders` | 查询我方销售订单列表 |
| 订单中心平台接口 | `GET /api/v1/orders/sales-orders/{id}` | 查询我方销售订单详情 |
| 订单中心内部接口 | `POST /internal/v1/orders/dhb/sync` | 接收 Integration 已采集、已映射的订货宝销售订单批次 |

Portal 只调用订单中心的销售订单业务接口。手动同步、定时同步和修复同步统一进入 Integration 订货宝同步中心；Order Center 不再编排订货宝同步，也不暴露浏览器可调用的模块级同步接口。

## 2. 分层职责

```text
Integration
  -> DhbClientAdapter   订货宝HTTP协议、Token、超时、重试、限流和脱敏
  -> Raw Landing / 同步批次
  -> 订单中心内部导入契约
       -> OrderSalesOrderService / MybatisPlusSalesOrderRepository
       -> order_sales_order / order_sales_order_line / order_sales_order_payment

Portal -> Gateway -> order-center-service -> 本地订单投影
```

- `DhbClientAdapter` 是订货宝唯一的外部适配器，位于 Integration。
- 物流查询使用订货宝 `getWaitShips`，入参为订单号 `orders_num`；返回 `shipped` 已出库/已发货记录和
  `wait_stock` 待出库明细。该调用发生在 Integration，订单中心只接收已归一化的物流数据。
- 订单中心只拥有内部订单模型和查询/导入持久化边界，不读取第三方凭据。
- `SalesOrder` 是平台内部销售订单模型，内部流程只使用我方订单状态、收款状态、出库状态和发货状态。
- 订货宝状态作为 `source_status_code` 展示、筛选和对账，不直接作为我方人工流程动作。
- 订单中心是 `order_sales_order`、`order_sales_order_line`、`order_sales_order_payment` 的唯一写入服务；ERP、库存、客户和 BI 通过服务接口消费业务数据。

## 3. 内部数据表

| 表 | 说明 |
|---|---|
| `order_sales_order` | 我方销售订单主表；保存订单号、客户快照、归属销售人员编码、金额和状态 |
| `order_sales_order_line` | 我方销售订单商品明细；保存商品编码、规格、数量和价格快照 |
| `order_sales_order_payment` | 我方销售订单收款记录 |
| Integration Raw / 外部映射 / 编排运行记录 | 保存订货宝来源报文、外部 ID 绑定、同步批次和对账证据 |

销售订单业务幂等键为：

```text
tenant_id + order_no
```

明细幂等键为：

```text
sales_order_id + line_no
```

订货宝原始报文不再放在 Order Center；来源报文、来源覆盖、外部 ID 绑定和同步对账证据由 Integration 统一保存。Order V17 会删除旧 Order 内部订货宝镜像、导入和审计表。

## 4. 订单状态边界

2026-11-03 用户进一步明确：当前以订货宝同步为主，没有启用我方完整履约流程；订货宝已完成同步为已完成，收款独立，不要求补走发货/签收。以下规则替代此前“外部完成不推进我方完成”的实现。

| 主状态 | 内部编码 | 业务含义 |
|---|---|---|
| 草稿 | `DRAFT` | 单据尚未确认，可继续完善 |
| 进行中 | `SUBMITTED` | 订单已确认，业务尚在进行 |
| 已完成 | `COMPLETED` | 来源确认订单已结束，或自建订单已完成履约 |
| 已取消 | `CANCELLED` | 保留记录供查询，不参与业务统计 |
| 已删除 | `DELETED` | 来源明确删除，保留记录供查询，不参与业务统计 |

`SUBMITTED` 沿用已有存储编码，展示名称为“进行中”。主状态统一读取 `SALES_ORDER_STATUS` 字典；名称、说明、排序可维护，编码和流转由 Order 控制。列表、详情、筛选与 CSV 使用同一租户字典。前端限定上述五个编码，V53 停用历史混入项，V54 修正完成条件说明；不改已执行迁移。

### 订货宝同步映射

| 来源状态（接口值） | 来源投影编码 | 我方主状态 |
|---|---|---|
| 待核价（pricing） | PENDING_PRICING | 草稿 |
| 待审核（pending） | PENDING_REVIEW | 草稿 |
| 待出库（stock_up / stockup） | PENDING_OUTBOUND | 进行中 |
| 待发货（shipped） | PENDING_SHIPPED | 进行中 |
| 待收货（received） | RECEIVED | 进行中 |
| 已完成（finished） | COMPLETED | 已完成 |
| 强制完成（forcedone） | FORCE_COMPLETED | 已完成，保留强制完成来源，不伪造签收 |
| 已退货（return / returned） | RETURNED | 已完成，表示原订单已结束，保留退货来源，不自动退款 |
| 已取消（cancel / canceled / cancelled / closed） | CANCELLED | 已取消，保留可查询 |
| 已删除（delete / deleted / removed，或明确删除标记） | DELETED | 已删除，保留可查询 |
| 来源结算金额明确为 0 | CANCELLED | 已取消，保留可查询 |
| 未识别值 | 不默认映射 | 进入同步问题池，人工核对 |

新建、整单更新、来源状态/资料更新采用相同的订单状态规则；不创建我方履约执行或签收记录。完成、强制完成、退货映射不修改收款状态、实收或欠款，不能据此视为已结清。正常商业金额更新仍按既有规则独立计算金额。

已有已完成、已取消、已删除订单不会被旧来源阶段重新打开；来源取消仍可走专用路径。相同报文校验和只有在主状态也一致时才跳过，因此此前“来源已完成但主状态仍进行中/草稿”的订货宝订单，在后续正常同步时可修正；不批量改库。未知状态、历史关联、旧版本保护继续生效，已关联飞书历史主体不因本次规则被整单覆盖。

2026-11-04 用户修正：取消/删除/零金额不再隐藏业务投影。失效来源接口保留订单、明细、回款原记录及金额，设置主状态 CANCELLED/DELETED，`deleted` 逻辑删除字段保持 0。此前隐藏的订单在后续收到明确失效来源时恢复主表查询；不自动恢复已被旧逻辑删除的明细或回款，避免恢复原先已废弃的版本。

首次收到失效来源也保留订单号和可取得的来源字段，不要求客户/商品映射或补走流程；缺少下单日期保持空值（Order V61），不伪造日期。不能把未返回某订单、请求失败或 404 当作明确删除。原有未映射飞书历史保护和多来源关联组核对继续保留，不能因一张来源失效而取消整个有效关联组。

已取消/已删除订单可通过主状态筛选，分页条数表示查询命中数；订单、明细、回款汇总、应收、期间/月业绩、成本/提成来源和 BI 均排除它们。BI 订单、明细、回款事实按所属订单失效状态退役，包括订单变化而回款未更新的场景；源镜像仍保留原证据，不执行真实资金冲销或删除回款。Foundation V55 增加“已删除”字典，不改写既有迁移。

### 自建订单

自建订单仍可按每条有效明细的我方累计签收数量判断完成；部分签收、取消/删除记录不计入，签收更正后重新计算。该规则只作用于自建订单，不让补录发货倒改同步订单的来源完成结论。收款、出库、发货、退货退款分别记录，不把“已结清”等混入主状态。

### 付款凭证同步与自有 COS（2026-11-04 核对）

订货宝付款单的 `resource[]` 附件由 Integration 下载实际文件并上传自有 COS；业务关联保存租户自有对象 key，不保存临时来源 URL 供页面长期使用。通过 `ReceiptsNum` 及已确认核销关系精确定位回款，Order 将附件写入对应回款的凭证关联，列表“付款凭证”和详情使用自有存储访问地址回显。

下载或上传失败不建立关联；来源收款号缺失/未匹配进入待处理，不按订单号或金额猜测。重试刷新来源状态和临时地址；重复同步不重复挂图，保留人工上传/排除记录。付款来源取消只撤销本来源维护的关联，不删除其他来源或人工附件；订单取消/删除的统计排除不等于付款撤销。

## 5. 领域事件

当前订单到 ERP 的协作通过受控服务接口完成：销售订单确认出库时，Order 调用 ERP 销售出库能力生成 `erp_stock_out_order`。如后续需要领域事件，事件载荷只允许包含业务 ID、业务编码和状态，不包含手机号、地址、Secret、Token 或原始报文。

## 6. 后续扩展约束

1. 新增自研下单流程时，直接创建 `order_sales_order`，不伪造订货宝报文。
2. 新增其他外部来源时，只新增对应的 Translator 和 Provider Adapter，不修改内部订单流程。
3. 订货宝写操作暂不开放；新增、修改、审核、发货需要另行定义内部订单状态机和权限。
4. 外部凭据只通过Secret注入，不能写入数据库、日志和API响应。

## 7. Integration与订单中心的后续契约

Integration 到订单中心的导入契约只允许服务间可信上下文调用。命令携带租户、连接器、来源任务和已映射业务数据，绝不能携带订货宝账号、密码、API Key 或 Token；Secret Resolver 只能存在于 Integration。该契约不得被 Gateway 作为浏览器菜单接口暴露。
