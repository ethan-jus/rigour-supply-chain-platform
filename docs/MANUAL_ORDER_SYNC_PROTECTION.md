# 人工修正订单的订货宝同步保护

## 规则

人工确认的历史金额、退货数量和付款凭证可能与订货宝原单不同。来源校验和未变时的幂等跳过不能代替人工修正保护；来源后续修改、取消、删除仍可能触发自动校准。

`order_manual_sync_protection` 按租户、连接器、来源订单及系统订单记录保护，关联原修正的 `operation_id`、原因和操作人。仅对有明确人工处理依据的订单启用，不按姓名、备注关键字或更新时间批量推测。

Order 的来源订单、失效状态、回款、历史回款状态和凭证关联入口统一检查保护。检查同时覆盖新来源关系、原回款关系、已删除的付款记录、核销关系及原凭证关联，避免上游改绑绕过保护。关联组中包含受保护订单也会拦截。

命中后返回 `MANUAL_PROTECTED`，不更新订单、商品行、回款、期初核销或凭证。来源报文保留在 `order_dhb_projection_change_audit` 的 `PROTECTED_*` 记录；同一来源连续重放相同报文不重复写审计。Integration 保留其原始报文及待核对结果，不能把保护拦截解释为已入账。

普通订单继续走原同步流程。此保护不替代人工财务权限，也不自动确认到账、生成退货入库或修改金额。

## 维护和发布

1. 人工修正前确认来源关联、备份订单/回款/凭证及原同步数据，记录批准依据。
2. 在无正在执行的来源写入时，由 Order 的数据库写入账号在修正事务中登记保护。记录所有相关来源，保留订单和来源原始身份，不改来源校验和冒充一致。
3. 后续确需恢复自动同步时，先核对上游与人工结果，另存解除保护的审批和前值，再移除对应保护记录。同步任务不得自行解除保护。
4. 新增 V75（V73、V74 已由物流迁移占用）；已有 Flyway 迁移不修改。生产保持关闭启动迁移，结构由迁移管理员按标准流程执行，业务保护记录由 Order 写入。
5. 发布验证应包括真实 MySQL、原始来源重放、受保护订单全字段不变、已删除回款不复活及普通订单对照；不只看健康检查。
