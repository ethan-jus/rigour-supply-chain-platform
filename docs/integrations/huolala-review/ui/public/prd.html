物流运输记录与货拉拉数据接入产品需求文档

版本：V2.5 待确认稿　日期：2026-11-10

本版按最新要求修正：主列表继续使用“物流运输记录”，同时承接货拉拉自动同步和手动录入。货拉拉列表、详情先保存到本系统，同步后直接出现在物流运输记录中；业务再关联本系统订单和员工。不新增一个与物流运输记录并列的“货拉拉订单”业务主入口。

1 业务目标

让业务人员在同一张物流运输记录列表里查看全部运输。货拉拉提供的订单、路线、费用、人员等自动取得，减少重复录入；其他物流公司、自营运输或无法从平台取得的记录仍可手动登记。

主流程：货拉拉同步／手动录入 → 本系统保存运输记录 → 同一列表查看详情 → 人工关联业务订单和人员 → 沿用成本确认与统计流程。

货拉拉记录没有关联订单、没有关联员工、仍在运输中或已取消，都不阻碍先保存和查看。不能要求先填写费用、收货人、地址或完成成本确认，才能看到同步结果。

2 本期范围与现有使用方式

本期暂不新增岗位角色、主管／财务／管理员分工、角色权限矩阵或按岗位区分的按钮。沿用现有系统的登录和菜单使用方式，不要求业务先配置角色才能使用物流功能。

本期只围绕三件事：平台运输数据自动保存展示、业务订单及员工关联、手动补充运输记录。已确认／待确认／已作废对应的操作限制继续保留，这是已确定的单据流程，不是本轮新增角色权限。

货拉拉应用开通及账户授权属于读取平台私有订单的前提，和本系统暂不划分岗位权限是两件事。连接页面只显示连接状态、连接／重新连接、同步设置；密钥、回调地址、环境参数和接口处理由代码及服务配置完成。

3 一张列表、两种来源

数据来源如何产生自动取得／手动处理同步更新规则
货拉拉同步自动定时或点击“同步货拉拉订单”平台信息自动保存，只人工关联业务订单和员工更新平台字段，保留人工关联和历史操作
手动录入点击“新增运输记录”先选运输类型及业务订单，能从本系统带出的客户、收货信息自动带出；填写承运商、运单、费用等必要信息不受平台同步覆盖

货拉拉每个源订单对应一条本地运输记录，重复同步更新同一条，不生成第二笔运输费用。若业务在手工入口选择货拉拉且填写同一货拉拉订单号，系统检查重复；已有记录时直接引导查看、关联，不能再计一遍费用。货拉拉订单号、运单号、本系统费用单号分别保存，不互相冒用。

历史手工记录缺少平台订单号时，不根据姓名、金额或日期相似自动合并；业务核对后再建立来源关系。

货拉拉同步记录的物流公司由系统固定为“货拉拉”，不要求接口额外返回物流公司名称，也不要求业务选择。列表可选列、编辑、详情及导出使用同一值，编辑时只读。手动新增仍从物流公司字典选择；手动选择货拉拉不改变“手动录入”的数据来源。

费用信息订单总费用、费用项目、已付、未付、退款、赠金及优惠相关信息详情分别展示，金额不混为一个口径

司机车辆司机称呼、平台可提供的联系电话、脱敏车牌及车型详情
回单凭证平台允许取得的回单、费用凭证等详情

这是接入范围，不保证每张订单都返回所有字段。平台未提供的内容显示“-”，不伪造、不改为业务必填，不把缺失金额当作0。有效零金额显示0.00。司机信息可能限时、号码可能是虚拟号、车牌可能脱敏；不承诺完整真实号码和车牌。装卸货照片、实际行驶里程等额外能力暂不作为必有字段。

4.1 本次官方资料核对后的接入选择

你本次给出的详情链接属于货拉拉APP业务，企业平台订单及员工目录是另一套接口。按现有企业订单与员工关联需求，本版建议企业版接入；不是把APP详情链接直接替换进原企业查询。

列表取得订单编号后先保存，再补详情。单独一份详情接口不能枚举全部订单；平台员工信息也不能由下单联系人姓名代替。只有APP订单能力而没有企业员工目录时，不能承诺自动取得企业员工及部门。

现行文档的企业订单列表与详情历史期限不同。超过可取详情期限的旧订单仍保留已取得的列表资料，详情显示未取得；可通过历史报表补充，但不得把当前数据当作旧订单资料。

常规同步先采用定时查询。指南提及的消息通知能否覆盖你们已经在平台网页或APP创建的订单尚需确认，本版不承诺只配通知就能自动取得全部历史及新增订单。

5 物流运输记录列表

5.1 页面布局与入口

保留“成本管理 → 物流运输记录”。依次为筛选区、列表工具栏、表格、分页，沿用现有蓝白风格。无需把“货拉拉待关联”“来源差异”作为与主列表并列的日常页签；通过来源、关联状态筛选及具体记录详情处理。

工具栏：新增运输记录、同步货拉拉订单、自定义导出。员工关联、同步记录、显示列为辅助操作，可放在同一工具栏次要位置。连接状态、连接／重新连接和自动同步开关放“货拉拉连接”设置；不增加本期岗位权限配置。

5.2 默认字段与顺序

顺序字段展示规则
1勾选自定义导出选择记录
2费用单号本系统完整编号，点击查看详情
3数据来源货拉拉同步／手动录入
4运输类型销售订单配送／仓间调拨／其他费用；平台记录未关联时显示“-”
5运输日期平台用车日期或手动登记的运输日期
6收货方多收货方逐行列出；无名称显示地址，不仅写“2个收货点”
7货拉拉订单号平台原始编号；其他承运商显示“-”
8运输费用（元）平台记录显示已取得的订单总费用，手工记录显示登记费用；不是已确认成本合计
9单据状态待确认／已确认／已作废；与货拉拉订单状态分开

11操作查看、编辑及按状态允许的操作；业务订单关联可在编辑或详情中处理

可选列：物流公司、运单号、货拉拉订单状态、货拉拉下单员工、本系统关联员工、员工关联状态、已关联业务单号、订单关联状态、业务员、部门、已付、未付、退款、最近同步时间。

联系人、电话、地址、司机、费用项目等完整数据放详情。字段独立命名；货拉拉订单状态不能当作本系统单据状态。费用单号、平台订单号和业务订单号不放到同一个单元格。

5.3 独立筛选

常用：费用单号、数据来源、运输类型、运输日期、单据状态、订单关联状态。

更多条件：货拉拉订单号、运单号、物流公司、货拉拉员工姓名、员工关联状态、本系统业务单号、本系统员工、业务员、部门、收货地点、手机号。每项独立输入；查询本地保存的数据，不在打开列表或每次查询时临时拉取平台整批数据。

5.4 操作和状态

单据状态可用业务操作
待确认查看、编辑、确认、作废；不能删除
已确认查看、撤销；不能直接编辑、作废或删除
已作废查看、删除

操作记录放详情，不再以列表操作按钮挤占宽度。撤销后回到待确认；只有已作废才能删除。附件在待确认编辑时维护，已确认需先撤销。

货拉拉平台信息不能直接编辑；待确认记录的“编辑”仅维护本系统关联、归属等内容。已确认记录更改业务关联会影响历史成本，必须先撤销；平台新数据仍能同步保存，但不能静默改写已确认成本。

6 物流运输记录详情

同一个详情入口，按数据来源显示相应内容。顶部显示费用单号、单据状态及当前可用操作。新增、编辑、详情的共用区域统一按“基本信息 → 关联业务订单 → 发货信息 → 收货信息 → 费用信息 → 备注”排列；同一字段保持相同名称、顺序和含义。详情使用只读文本，编辑时可填写项使用输入控件，源字段使用只读控件。

基本信息字段顺序：数据来源、运输类型、订单类型、运输日期、物流公司、运单号、货拉拉订单号（货拉拉记录适用）。费用信息先展示运输费用、费用负责人、已确认运输成本；货拉拉来源在其下展示只读平台账单。收货信息按每个收货方分别列出收货联系人、收货联系电话、收货地址。

货拉拉订单状态、精确用车时间、司机车辆、人员关联、回单等平台专有资料放在共用区域之后。货拉拉订单备注与本系统业务备注分别保存，不能在编辑时互相覆盖。

货拉拉同步记录的详情包括：

  1. 平台订单：完整货拉拉订单号、平台状态、下单时间、用车时间、完成时间、车型、备注、用车原因。
  2. 配送信息：发货点、全部收货点按顺序显示，完整列出名称、联系人、电话及地址。
  3. 平台账单：依次展示账单汇总、费用明细、凭证，均为只读。支付与退款单独表达，不在页面重复累加或扣减；具体规则见第6.1节。
  4. 司机与车辆：按平台返回展示司机、联系电话及脱敏车牌；号码类型可用时显示虚拟号等标识。资料缺失显示“-”，不要求手工补出原始隐私信息。
  5. 人员关联：平台下单员工、手机号、平台部门、本系统员工与部门、关联状态。
  6. 业务订单关联：类型、单号、客户或收货仓库、业务员、部门及关联时间。
  7. 回单与附件：平台回单与本系统人工附件区分来源，平台无回单不要求业务补传才能查看。
  8. 操作记录：同步更新与人工关联、更正、确认、撤销分别留痕。

手工记录展示承运商、运单号、运输信息、费用、负责人、关联业务单及人工附件；不展示一排无意义的货拉拉专用空字段。

平台配送信息与所关联业务单的客户、收货资料并列保留，不覆盖平台地址、不写回客户档案。详情暂未取得时先展示已保存的列表资料，提示“详细信息暂未同步，请重新同步此单”，不隐藏整条运输记录。

6.1 平台账单、费用明细与凭证

在详情“费用信息”中固定分为以下三块，不新增一个独立账单列表入口。待确认编辑页仍只维护本系统资料，平台账单不出现可修改的输入项；从编辑可回到同一详情查看。

区域展示字段与交互规则
账单汇总账单总计（元）、已支付（元）、未支付（元）、退款（元）；下方显示赠金抵扣、账单更新时间、最近同步时间全部自动取得、只读；缺失显示“-”，明确为零显示0.00；账单总计与付款情况分别表达
费用明细费用项目、金额（元）、凭证使用平台原有费用名称，费用增加及抵扣逐行展示；支持平台新增费用项目，无需业务手动建立每个费用项目；有凭证可查看
凭证所属费用、文件、凭证状态、取得时间、查看／下载自动关联到对应费用；支持同一项多份凭证；平台凭证不允许业务替换、删除或改金额；人工上传附件另行保留来源

费用分项不设独立的“计入成本”操作，不逐条生成运输费用单。付款、退款、赠金也不生成额外费用单。平台费用项目不做擅自合并，同名费用允许存在多行。运输回单与费用凭证分别展示，避免把送货回单当成付款或费用证明。

截图账单示例：专享价108.85元＋高速路桥费20.00元＋搬运费11.00元＋税费2.79元－货运券抵扣5.00元＝账单总计137.64元；已支付137.64元是同一笔账单的付款情况，不能再加成275.28元。此示例可核对，不作为所有订单通用计算公式；平台可能有其他费用组合或汇总层级。

凭证未提供时显示“暂无平台凭证”；平台已提供但暂未取得文件时显示“待获取”，系统继续补取。不能因为图片暂未取得就删除已保存账单、用空值覆盖旧凭证或要求业务重录费用。正式文件按实际取得的图片或文件预览、下载；原型提供明确标注的演示文件，不冒充收费票据。

6.2 已确认成本与账单变化

“运输费用”展示最新平台账单金额或手工登记费用；“已确认运输成本”展示本系统按既有承担及分摊规则确认的成本。账单已支付不等于本系统成本已确认，尚未确认时已确认运输成本显示“-”。平台账单、费用分项、付款信息不是三笔成本。

确认时保留对应的账单和费用归属。平台后续更新金额或费用项目时，最新账单照常保存，详情提示“平台账单已更新，已确认成本仍为¥××，请核对后处理”，并保留账单变更记录；不能静默覆盖已确认金额。需要调整时先撤销，再按最新账单核对、确认，统计以当前有效确认结果替换原结果，不叠加两次。仅付款进度变化、取得新凭证不自动触发撤销确认。

原型演示整笔由我方承担的情况：先确认137.64元，随后补收停车费5.00元，账单更新为142.64元，已确认成本仍是137.64元；再次同步仍只是一条运输记录。实际承担比例和多单分摊沿用既有规则，本轮不增加新的费用审批或支付流程。

7 关联本系统业务订单

运输类型自动带出的订单类型可选择范围
销售订单配送销售单本系统已有且有权访问的销售单
仓间调拨调拨单本系统已有且有权访问的调拨单
其他费用其他订单活动、领用、赠送、品鉴等其他出库类订单

操作：在记录详情点“关联订单”，或在待确认记录的编辑页处理关联 → 选择运输类型 → 搜索、勾选业务订单 → 保存关联。订单类型自动带出且不可修改。

顶部只读显示当前货拉拉订单、用车时间、配送地点、费用。独立查询业务单号、客户、业务员、部门、日期；候选表展示业务单号、客户／收货仓库、业务员、部门、日期、业务单金额、已关联运输笔数、推荐依据。

推荐只作辅助，不自动决定关联对象。可一张货拉拉订单对应多张业务单，也可一张业务单对应多张货拉拉订单；已有运输笔数不作为禁用条件，同一对关系不能重复。

保存关联时不再要求抄录平台金额、承运商、地址、收货电话等。缺少平台员工关联或原单发货仓库，不阻碍先保存正确的业务单对应关系。后续业务确实需要时，可在本系统补选发货仓库，不写成平台原始信息。

首次关联无需填写原因；更改或解除已有关系填写原因并保留操作人、时间及前后关系。

8 员工关联

货拉拉员工资料先自动保存，再由业务选择对应本系统员工。平台订单联系人不等于平台员工，不根据同名或电话相似直接自动保存关系。

从主列表工具栏或详情进入。员工列表展示：货拉拉员工姓名、手机号、平台部门、本系统员工、本系统部门、关联状态、操作；姓名、手机、状态独立筛选。

关联弹窗只需选择本系统员工，候选显示姓名、员工编号、手机号、部门、在职状态。首次无需原因，更改、解除需要原因。

一个货拉拉员工对应一个本系统员工。保存一次后，该员工的相关运输记录自动显示对应员工，无需逐单处理；与业务订单关联相互独立。员工关联不修改HR档案，也不覆盖已确认历史成本归属。

9 手动新增运输记录

先选择运输类型，对应订单类型自动锁定；选择已有业务单，自动带出客户及收货信息。原单发货仓库缺失时允许单独选择。

字段要求
运输类型、关联业务单必填，先选类型再选单，可多选
运输日期、物流公司必填；物流公司使用字典，新增字典无需修改页面代码
运输费用确认前必填，允许0；登记时未知可暂缺，不得确认成本
运单号、货拉拉订单号平台提供或实际存在时填写；货拉拉订单号用于重复检查
收货方、联系人、电话、地址优先从业务单和客户档案自动带出；确实缺失时按业务要求补充
发货仓库、费用负责人来源能带出则带出，缺失时允许选择，不强制把下单员工当负责人
付款状态、费用归属日期、备注、附件沿用现有运输费用业务规则；附件待确认可维护

手工登记应补充平台未覆盖的业务，不要求业务再手建一遍已同步的货拉拉订单。

收货信息从所选业务单和客户档案带出显示平台原有配送信息，不因更换关联订单覆盖每个收货方分别展示

9.2 发货信息

新增、编辑、详情统一在“关联业务订单”之后、“收货信息”之前显示“发货信息”。字段包括：发货仓库、发货方、发货联系人、发货联系电话、发货地址。地址独占一行，避免长地址被压缩。

  • 手动记录：业务单明确有发货仓库且所选订单来自同一仓库时，带出仓库、发货方、联系人、电话和地址；原单无仓库时允许选择本系统仓库，或直接填写实际厂家／发货方。不能默认把所有运输写成武汉仓。
  • 业务单缺少发货仓库、关联多个不同仓库或含有未知仓库时，不擅自选第一张单的仓库；由业务核对实际发货信息。已经手动填写或主动选择的发货信息，不因增减业务单被静默覆盖。
  • 选择仓库后带出的信息允许按本次运输补充，不修改仓库档案；保存记录当时的发货资料，编辑和详情按该记录回显。
  • 货拉拉同步记录：发货方、联系人、电话和地址读取平台路线，所有发货点均展示，编辑只读；平台未提供时显示“-”或“暂无发货信息”，不自动套用本系统仓库。平台发货点不重复藏在“货拉拉订单信息”中。

发货仓库不强制选择，厂家直接发客户的场景可以填写发货方。本轮补齐发货信息及保存回填，不额外收紧现有保存必填规则；缺失信息不伪造。正式实现时仓库使用编码关联，并保存单据上的发货资料快照。

10 自动同步与保存

先保存平台列表，再按单保存详情。列表成功、某单详情失败时，保留记录并单独重试；未关联、取消、费用未知均不是拒绝整单入库的理由。

重复同步更新平台状态、时间、路线、费用、司机等源字段；保留人工订单关系、员工关系、运输类型、负责人等本系统数据。手工记录不得被同步覆盖。

同步结果区分列表已保存、详情已保存、详情待补、失败数量；部分详情失败显示“部分成功”，列出对应单号。平台暂不可用或授权失效不影响查询已保存列表与详情。

平台取消不自动作废本系统费用，因为取消订单也可能有实际费用。平台费用更新不自动覆盖已确认成本、不重复计费；在具体记录提示复核，不增加日常“来源差异”主页面。

“货拉拉连接”仅展示连接状态、连接／重新连接及自动同步设置，不展示密钥或回调参数，不设置新的岗位权限。连接失败不影响查看本地记录或手动录入。

10.1 账单自动录入的处理顺序

  1. 自动同步取得货拉拉订单后，按原平台订单保存到原运输记录；物流公司自动为“货拉拉”，未关联订单或员工也可先查看。
  2. 自动保存账单汇总与全部费用分项；费用名称、金额和凭证由接口带入，不让业务再抄一遍。后续新增的有效费用项目按原名称展示。
  3. 自动取得凭证并归到对应费用项；账单先保存，文件取得失败单独重试。页面读本系统已经保存的账单和凭证，不在打开详情时临时等待一整轮平台请求。
  4. 重复同步同一订单及相同账单不增加记录、不增加费用行、不重复保存同一份凭证；有变化时更新原账单并保留变化前的内容。同步不能覆盖业务已维护的订单、人员、负责人或备注。
  5. 自动录入的记录初始为待确认。业务核对订单关联及实际承担费用后按原流程确认；同步任务和平台“已支付”都不能代替确认。
  6. 已确认账单发生费用变化，保留原确认成本并提示核对；撤销后重新确认替换原有效成本。多张业务订单分摊、重试同步、Excel补录均不能把同一平台费用重复统计。

11 成本归属与看板

平台订单费用、本系统关联关系、成本确认分别管理。运输记录同步入库不等于费用已确认；未确认费用不混进已确认成本统计。

物流成本按关联销售单的部门、业务员及费用分摊归属。平台下单员工、平台部门用于追溯，不替代销售归属。一笔运输对应多张业务单时，整笔费用只计一次，再按已确认的分摊规则分配，不能重复计给每张单。

采购运费仍归采购成本，采购成本仍按收货仓库关联部门归属。其余成本状态、附件、看板、自定义导出等已确认需求继续保留，本轮不再增加无关流程。

12 导入、导出与现有访问控制

自动同步为主，Excel为未开通接入或历史补充入口，模板、导入放辅助操作；接口和Excel同一平台订单去重，人工关系保留。历史手工记录仅在来源明确时合并。

主列表支持自定义导出：未勾选导出当前筛选全部结果，勾选后仅导出所选；弹窗明确范围、数量及可选字段。日期统一、金额两位小数、长单号按文本保留。导出继续遵守现有系统的访问控制，不额外划分新的岗位角色。

本期不新增权限分配页面、角色审批链和部门隔离规则；既有登录、身份和租户校验保留，状态操作按第5.4节处理。删除本系统作废记录采用可追溯的删除方式，保留平台源标识，重复同步不得复活一条重复成本。
