# 货拉拉订单接入与物流成本核对

> 方案状态：2026-11-09已按用户要求改为“物流运输记录统一展示货拉拉同步与手工录入，平台列表和详情先落库，人工再关联订单和员工”。最新产品方案见 [产品需求文档V2.4](huolala-review/产品需求文档.md)，数据保存设计见 [数据接入与保存说明](huolala-review/数据接入与保存说明.md)。下文记录的是此前开发实现及待调整点，不能用作V2.4方案已完成的依据。最新接口核对见 [接口能力核对与接入方案](huolala-review/接口能力核对与接入方案.md)；本期暂不新增岗位角色和权限矩阵。

本期从货拉拉只读同步企业订单及员工资料，业务人工关联已有单据后生成待确认运输记录。企业应用尚未申请上线，真实授权、字段回执及费用口径需在应用上线后完成联调，不能用隔离测试代替平台验收。

## 页面与职责

| 位置 | 内容 |
| --- | --- |
| 外部同步 → 货拉拉接入 → 企业授权与同步设置 | 企业账号、授权状态、历史范围、同步频率及开关 |
| 外部同步 → 货拉拉接入 → 员工关联 | 平台姓名和手机号、本系统员工及部门、关联、更改、解除 |
| 外部同步 → 货拉拉接入 → 同步记录 | 进度、读取与处理计数、无需更新计数、失败明细 |
| 成本管理 → 物流运输记录 → 货拉拉待关联 | API 或 Excel 来源，选择运输类型和原业务单据，核对净费用，生成运输记录 |
| 成本管理 → 物流运输记录 → 来源差异 | 已关联来源的账单变化，撤销原成本确认、编辑费用、核对差异、重新确认 |
| 物流运输记录详情 | 原业务单据及分摊、平台账单构成、已付未付、核对金额、附件和操作记录 |

运输类型与单据类型沿用当前系统：仓间调拨对应调拨单、销售订单配送对应销售单、其他费用对应其他出库单。采购运费仍属于 ERP 采购成本。多收货方逐行展示，手工录入、Excel 导入和自定义导出继续保留。

平台员工关联只用于下单人追溯和费用负责人候选。物流成本部门、业务员仍取关联销售单的冻结归属和分摊结果；不得用货拉拉部门、下单人或员工当前部门替代销售归属。采购成本继续取收货仓库所关联的部门。

## 企业授权前的配置

Integration 服务读取环境变量中的凭据。页面只提交同步偏好。企业绑定、凭据引用、回调与环境由部署配置提供；浏览器传来的旧技术字段将被忽略，不可用隐藏参数切换来源企业。

| 环境变量 | 用途 |
| --- | --- |
| RIGOUR_HUOLALA_APP_KEY | 已上线企业应用的 APP KEY |
| RIGOUR_HUOLALA_APP_SECRET | 同一应用的 APP SECRET |
| RIGOUR_HUOLALA_TOKEN_KEY | 32 字节随机密钥的 Base64 值，用于 AES GCM 令牌加密 |
| RIGOUR_HUOLALA_TOKEN_DIR | Integration 部署环境中的私有持久化目录，绝对路径，权限 700 |
| RIGOUR_HUOLALA_REQUEST_INTERVAL_MS | 可选请求间隔，默认 500 毫秒，可设 100～10000 毫秒；这属于本系统限速策略 |

如果服务端凭据引用使用另一个前缀，则 APP_KEY、APP_SECRET 相应使用该前缀；TOKEN_KEY、TOKEN_DIR 为服务级配置。令牌文件权限为 600，加密附加数据绑定租户和连接。多实例部署需共用具有相同权限的持久化卷及加密密钥，目录和密钥要纳入运维备份。丢失密钥后需重新授权。

回调为本系统同源的 `/huolala-authorized.html`，正式环境使用 HTTPS；本机可使用 HTTP。将完整回调地址登记在开放平台。临时授权码只在授权窗口和 Integration 服务间传递，浏览器不持久化 access token 或 refresh token。请求参数中的临时码使用 `credential` 字段以适配统一日志脱敏。

应用未上线或配置不完整时保持未授权，授权或同步按钮不可用。先保存设置不等于完成平台授权。

服务端非敏感接入配置使用 `rigour.huolala.enterprise-id`、`enterprise-name`、`secret-ref`、`redirect-uri`、`sandbox`。同一属性也可由 Spring 环境变量形式提供。已有连接未显式配置新属性时沿用其既有绑定；首次连接缺企业绑定或回调时提示管理员完成接入，不接受浏览器提供这些值。密钥仍只从部署环境读取。企业名称是否可在授权时自动取得尚未实测，不将此作为当前能力承诺。

## 同步与费用核对

列表 API 按用车时间查询，未提供的更新时间增量参数不自行构造。手工补同步限制近三年、一次最多 93 天；日常任务复查当前月和上月，每日复查详情接口支持的近一年。单次最多 10000 单，超过上限时失败并提示缩小范围。每页保存进度；任务心跳中断可重新同步，来源按租户和货拉拉订单号去重。

原始回执、员工映射、人工关联留痕、同步批次和失败原因复用 Integration 现有表。新增一张企业连接表；Order 来源队列增加 API 来源、账单摘要、最新回执和净费用核对字段。本期每租户一个企业连接，不支持直接替换企业或环境来混用历史来源。

平台订单总价与费用项目分别保留。已付、未付是支付进度，不直接决定成本是否成立。仅当详情完单、无退款或申诉等疑问、金额明确并通过金额核对时允许关联生成；赠金、退款、来源总价和支付合计不一致时要求管理员核对净费用并填写依据。不会对总价再机械扣一次优惠或退款。原生 Excel 的月结记录也须核对净费用，不能将未付款的零元实付认定为零成本。

同步和 Excel 导入只写来源队列，不自动确认成本。业务选择对应原单、核对金额并保存后生成待确认运输记录。待确认可以编辑、确认或作废；已确认只能查看和撤销；撤销回到待确认；只有已作废可删除。只有已确认成本进入正常成本看板。

API 新账单不会覆盖人工创建的运输费用，也不会改写已确认成本。已生成运输记录的来源快照保持不变，最新账单单独保存。金额或费用构成变化时标记来源差异，确认接口再次加锁核验，禁止绕过页面直接确认。处理差异需先撤销成本确认，再核对净费用、编辑成本金额、接受来源差异后重新确认。净费用核对及接受差异有独立操作记录。

## 权限

接入页使用 `integration:huolala:read`、`integration:huolala:write`、`integration:huolala:sync`。租户范围待关联与来源差异处理使用 `order:logistics-cost:manage-imports`，仅默认授予租户超级管理员，其他角色显式授权。普通上传人仍只能查询自己的导入记录。员工候选查询同时受 HR 现有权限约束，不能借接入页绕过员工读取权限。

API 到 Order 使用签名服务身份及独立同步权限，仅允许写入来源，不允许自动创建或确认成本。Order、ERP、HR 保持各自数据主权，BI 通过现有分析来源投影汇总。

## 迁移与真实联调检查

本次迁移为 Integration V28、Order V69、IAM V150、V151。保留已执行迁移原件，不修改已执行脚本，不关闭 Flyway 校验。Order 共享库已有同事的 `V68__payment_owner_evidence.sql`，本机现按明确授权启用精确 V68 临时放行，仅校验过文件名、描述、成功状态和校验值后允许前向迁移。取回原件后关闭 `rigour.order.flyway.allow-missing-v68` 并移除临时适配；其他环境不启用该配置。

应用上线后逐项核对：

1. 使用同一企业应用、环境和企业账号完成授权，实测 token 响应结构、有效期、刷新和授权撤销。当前兼容的有效期字段需以实际响应确认。
2. 用已付、未付月结、优惠券、赠金、额外费用、取消退款、多收货点订单，对照平台页面及报表核对总价、费用构成和最终净费用；未明确字段继续保留待核对。
3. 员工手机号只推荐候选，由业务确认关联；验证更改、解除及不同租户隔离，不修改 HR 主档。
4. 验证一笔平台单对多张销售单、多笔平台单对同一销售单；无原业务单据不得生成成本；原单缺发货仓库时允许单独选择。
5. 先 Excel 后 API、先 API 后 Excel、重复补同步均不得重复计费。付款进度更新不得制造成本变化；账单变更必须进入差异处理。
6. 走待确认、确认、撤销、编辑、附件维护、作废及删除，并核对操作记录与重开页面回填。
7. 下载默认模板及未勾选、单选、多选、自选列导出，核对实际文件，再对照部门和业务员分摊、成本看板及来源金额。

## 已确认方案对照与本机验证边界（2026-11-09）

- 接入入口：外部同步／同步控制／货拉拉接入。企业授权、员工关联、同步记录在同一页；IAM V151 补齐应用内动作节点，服务加载后核对实际权限。
- 物流列表：常用条件为费用单号、货拉拉／运单号、业务单号、运输类型、运输日期、单据状态。客户、业务员、归属部门、物流公司、付款状态及费用归属放更多条件。
- 默认列依次为勾选、费用单号、货拉拉／运单号、运输类型、运输日期、收货方、本单我方费用、单据状态、创建人、操作；物流公司、发货方、原单、部门、业务员、付款状态可通过显示列开启。
- 推荐关联：先选运输类型，锁定单据类型；单号、客户、业务员、部门、日期独立筛选。接口多收货点和 Excel 收货文本参与电话、地址、客户名候选提示，日期及下单员工一致只作提示，不自动绑定。
- 详情：平台账单紧接订单摘要，再读关联业务单据及冻结归属、收发货节点、费用分摊、附件；平台实际地址与业务地址分别保留，不一致时提示核对。
- 看板：采购货款、采购运费、采购合计、各运输类型、物流合计并列；运输类型按事实分组并查字典展示，不写死分组列。人员分摊合计、运输类型合计分别等于部门物流合计；下钻及导出保留货拉拉／运单号。
- 日常复查当前月和上月，每日再复查近一年；不把月结未付和已付款直接等同为成本金额。
- 定向测试和构建不能代替真实授权、同步、退款账单对账、角色权限及真实业务确认。企业应用未上线，相关真实接口场景仍未验收。
