# 货拉拉订单接入与物流成本核对

本轮按已确认的 [产品需求文档 V2.5](huolala-review/产品需求文档.md) 和原型实施。字段保存见 [数据接入与保存说明](huolala-review/数据接入与保存说明.md)，平台能力边界见 [接口能力核对与接入方案](huolala-review/接口能力核对与接入方案.md)。本期不新增岗位角色和权限矩阵。

## 页面与业务流程

| 位置 | 当前行为 |
| --- | --- |
| 成本管理 → 物流运输记录 | 同一主列表展示货拉拉自动同步和手动录入；不再单设“货拉拉待关联”“来源差异”主列表页签 |
| 列表查询 | 单号、来源、运输类型、运输日期、状态及关联状态；运单号和货拉拉订单号独立查询；其他条件按现有紧凑筛选规范展开 |
| 列表展示 | 勾选、费用单号、来源、运输类型、日期、各收货方、货拉拉订单号、运输费用、单据状态、创建人、操作；其余字段通过列设置开启 |
| 新增／编辑／详情 | 基本信息 → 关联业务订单 → 发货信息 → 收货信息 → 费用信息 → 备注；平台记录增加只读账单、凭证、回单及平台信息 |
| 列表辅助操作 | 自定义导出、列设置、员工关联、同步记录、货拉拉连接、历史报表补录；未勾选导出全部筛选结果，勾选导出选中记录，默认选择全部字段 |
| 外部同步 → 货拉拉接入 | 页面只显示授权状态、授权操作、同步设置、员工关联和同步记录；密钥、回调地址和环境配置由服务端处理 |

同步取得的订单先落库，形成待确认运输记录，缺少人员或业务单据关联也可以查看。业务再选择运输类型、关联原单和本系统员工；平台资料不要求业务重复录入。物流公司固定为货拉拉，平台订单号、日期、账单、司机、收发货节点及平台凭证只读。

手动新增先选运输类型，再按锁定的订单类型选择原单。仓间调拨对应调拨单，销售订单配送对应销售单，其他费用对应其他出库单。销售单收货资料来自原单和客户档案。原单没有发货仓库时可单独选仓，或填写实际发货方；同仓自动带出仓库资料，缺失值不伪造。采购运费仍属于 ERP 采购成本。

平台员工关联用于下单人追溯和负责人候选。物流成本部门、业务员取关联销售单的归属及分摊，不能用平台部门、下单人或员工当前部门替代。采购成本取收货仓库关联部门。原单部门缺失时保留缺失，不编造归属。

## 金额与状态

- 运输费用展示最新平台账单总额；已付、未付、退款及各费用项目分别留存，不再叠加生成第二笔成本，也不机械再次扣优惠或退款。
- 平台账单汇总、明细及凭证只读。账单信息不明确时保持待确认，确认前需要业务核对依据；不提供手工改写平台总价入口。
- 手动费用按输入金额计算；多单分摊使用金额分值精确分配尾差。原有多项费用、非我方承担和特殊分摊记录继续通过原费用明细维护，不能简化覆盖原配置。
- 自动同步不能自动确认成本，也不能覆盖已确认成本。已确认后新账单单独保存并提示变化；撤销后重新确认以新结果替换原有效成本，不累加成两笔。
- 待确认：查看、编辑、确认、作废；已确认：查看、撤销；已作废：查看、删除。撤销回到待确认，删除为逻辑删除并保留审计。
- 待确认附件可新增、更换、移除；已确认只读。附件重试复用原单，只处理未完成项，每项成功后刷新版本。

## 服务职责、幂等与文件

Integration 负责企业授权、平台列表与详情查询、员工资料、原始回执、同步进度、文件下载及重试。按列表先保存、逐单补详情，单条详情失败不删除已经取得的列表记录。日常复查当前月和上月，另复查详情接口可查的历史范围。补同步范围、限速和上限沿用当前接入实现；实际可查询历史范围须按企业授权接口核实。

Order 是物流成本单一写者。平台来源、业务关联和成本事实分开保存；平台来源按租户和订单号幂等。重复同步复用同一运输记录，软删除后不因重复同步重新生成。相同平台订单身份的既有运输记录复用原单；普通手工记录不按金额或相似名称覆盖。Excel 为历史补录辅助流程，不能替代 API 同步成功的证据。

平台凭证、账单图片、运输回单由 Integration 下载到既有公司私有 COS。对象路径为 `{tenantId}/integration-huolala-vouchers/{connectorId}/{platformOrderNo}/{voucherId}.{ext}`，元数据包括 `source-service=integration`、`source-system=HUOLALA`、`business-domain=ORDER`，与 ERP、Order 人工附件区分。业务页面只使用自有文件标识；Order 核验租户、运输记录可见范围和文件归属后签发短期访问地址。部署时沿用目前共享私有桶配置。

文件失败独立重试，不阻止账单入库。文件已存 COS、Order 投递失败时只重试投递；重复同步保留已有 COS 引用。下载限制来源域名、HTTPS、文件大小与真实格式，不接受任意跳转。原平台临时 URL 只留在内部下载任务中，不展示给业务人员。

API 到 Order 使用签名服务身份及既有同步权限。业务列表、原单、员工查询、确认和附件继续核验现有租户、城市、仓库及动作权限；不新增产品岗位权限配置。ERP、HR 各自维护所属数据，BI 消费领域分析投影，不跨库写入。

## 企业授权前的配置

Integration 服务读取环境变量中的凭据。页面只提交同步偏好。企业绑定、凭据引用、回调与环境由部署配置提供；浏览器传来的旧技术字段将被忽略，不可用隐藏参数切换来源企业。

| 环境变量 | 用途 |
| --- | --- |
| RIGOUR_HUOLALA_APP_KEY | 已上线企业应用的 APP KEY |
| RIGOUR_HUOLALA_APP_SECRET | 同一应用的 APP SECRET |
| RIGOUR_HUOLALA_TOKEN_KEY | 32 字节随机密钥的 Base64 值，用于 AES GCM 令牌加密 |
| RIGOUR_HUOLALA_TOKEN_DIR | Integration 部署环境中的私有持久化目录，绝对路径，权限 700 |
| RIGOUR_HUOLALA_REQUEST_INTERVAL_MS | 可选请求间隔，默认 500 毫秒，可设 100～10000 毫秒；这属于本系统限速策略 |

如果服务端凭据引用使用另一个前缀，则 APP_KEY、APP_SECRET 相应使用该前缀；TOKEN_KEY、TOKEN_DIR 为服务级配置。令牌文件权限为 600，加密附加数据绑定租户和连接。多实例部署需共用具有相同权限的持久化卷及加密密钥，目录和密钥要纳入运维备份。丢失密钥后需重新授权。

回调为本系统同源的 `/huolala-authorized.html`，正式环境使用 HTTPS；本机可使用 HTTP。将完整回调地址登记在开放平台。临时授权码只在授权窗口和 Integration 服务间传递，浏览器不持久化 access token 或 refresh token。请求参数中的临时码使用 `credential` 字段以适配统一日志脱敏。

应用未上线或配置不完整时保持未授权，授权或同步按钮不可用。先保存设置不等于完成平台授权。

服务端非敏感接入配置使用 `rigour.huolala.enterprise-id`、`enterprise-name`、`secret-ref`、`redirect-uri`、`sandbox`。同一属性也可由 Spring 环境变量形式提供。已有连接未显式配置新属性时沿用其既有绑定；首次连接缺企业绑定或回调时提示管理员完成接入，不接受浏览器提供这些值。密钥仍只从部署环境读取。企业名称是否可在授权时自动取得尚未实测，不将此作为当前能力承诺。

## 检查与真实接入边界

后端 48 项定向测试通过，覆盖账单金额、幂等、已确认金额保护、来源合并、代理装配及 COS 文件重试。reactor verify 限定上述测试执行；Portal 74 项相关定向测试、类型检查、定向 ESLint 和生产构建通过，数据库排序规则脚本检查通过。这些结果不等同生产业务验收。
