# 供应链查询缓存

实现日期：2026-11-10。适用 BI、Order、CRM 三个服务及 PC 端；不改变数据库作为业务事实来源，也不改变权限、订单金额或回款计算规则。

## 已接入范围

| 查询 | 缓存粒度 | 默认有效期上限 |
| --- | --- | --- |
| 经营总览、城市经营看板、销售业绩看板 | 权限范围 + 筛选条件的统计结果 | 60 秒 |
| 回款风险看板 | 权限范围 + 筛选条件 + 业务日期 | 30 秒 |
| 订单列表、订单明细 | 数据库分页后的当前页 | 15 秒 |
| 订单列表、明细的总数和汇总 | 相同筛选条件跨页复用 | 30 秒 |
| 订单历史资金覆盖状态 | 租户及授权范围内跨页复用 | 30 秒 |
| 订单回款列表及汇总 | 当前页 / 独立总数与汇总 | 10 秒 |
| CRM 商家库、公海、私海及地图聚合成员 | 数据库游标分页后的当前页 / 独立总数 | 10 秒 |
| CRM 省、市、县地图聚合及覆盖统计 | 当前权限和筛选下的完整行政区统计 | 30 秒 |
| CRM 街道级地图 | 固定空间网格块 | 10 秒 |

只在查询发生时填充缓存，不一次性加载全库，也不预热所有筛选和分页组合。TTL 随机缩短最多约 10%，避免集中到期。首访或低频筛选仍查询数据库；慢 SQL 本身的成本不会因缓存自动消失。

## 一致性与权限

- 每次查询仍解析当前授权。缓存键包含环境、服务、租户、调用人及授权快照、查询条件、数据版本；CRM 还包含行政区划版本、展开后的部门成员及公私海条件。
- 每个服务自己维护 `query_cache_version`。业务写事务在提交前增加本租户版本，同一事务只增加一次，事务回滚同时撤销版本变更。版本更新不依赖 Redis，避免 Redis 故障期间漏失效。
- 订单、回款、退款、发货、历史同步，以及 CRM 认领、释放、审核入库、经营状态、拜访、生命周期事实变更，均已接入相应版本更新。BI 在本地事实/权限/人员/商品投影更新后切换版本；BI 的源同步延迟仍由原有同步机制决定。
- 读请求使用数据库版本；事务内存在未提交写入时不读写缓存。旧版本查询即使晚完成，也不能填入新版本键。已开始的并发读可能返回其事务快照，后续新请求使用提交后的版本。
- 认领、核销等写操作继续使用原有数据库校验、版本检查和锁，不依据缓存决定是否允许操作。
- 直接 SQL 维护或未来新增写入口必须在同一个事务更新本服务版本。跨服务不要直接更新对方表。

## 地图和浏览器

行政区地图先缓存完整地区聚合，再按视野裁剪地区。街道地图以固定网格取数，密集网格继续聚合；视野过大时降低细度，不截断数据。网格使用半开边界，WGS84 和 GCJ02 分开聚合，并为转换预留边缘范围。地图数量的含义是“视野及周边”，聚合点可查看完整成员分页。

前端保留未变化的标记，变化标记才移除/添加；街道图钉使用 LabelsLayer 批量绘制，缺少对应 SDK 能力时使用原有标记。坐标转换结果最多保留 4096 项，原始坐标不变。浏览器合并相同在途读取，请求完成后不长期保存业务响应；写请求开始和成功后都会隔离旧的在途请求。

看板刷新、地图重新加载可跳过缓存。接口支持 `Cache-Control: no-cache` 或 `X-Query-Cache-Bypass: true`，仍执行授权和并发限制，并刷新缓存。导出路径强制回源。

## 配置与观测

三服务复用现有 `spring.data.redis` 单机连接配置（含 TLS、用户名、密码、数据库编号）。当前适配器不支持 Redis Cluster/Sentinel。默认 Redis 连接超时为 150ms、命令超时为 500ms（`QUERY_CACHE_COMMAND_TIMEOUT_MS` 可调整），失败后短暂熔断 5 秒并回源；相同查询合并，单实例同时回源默认 16 个，超载返回 503 和 `Retry-After: 2`。业务异常不会作为缓存降级被吞掉。

```yaml
rigour:
  query-cache:
    enabled: true
    namespace: dev:your-nacos-namespace:crm # 每个环境、服务必须不同
    command-timeout-ms: 500
    max-entry-bytes: 2097152
    max-tenant-bytes: 33554432
    max-concurrent-loads: 16
```

默认命名空间由 profile、`NACOS_NAMESPACE` 和服务名组成，内部再附加 `v2` 数据格式版本；可用 `QUERY_CACHE_NAMESPACE` 覆盖，但不要给不同服务配置相同值。开关可用 `QUERY_CACHE_ENABLED` 覆盖。上述配置可由各服务 Nacos 配置提供，当前在服务启动时读取，不承诺动态刷新。

每条响应解压后最多 2 MiB；32 KiB 以上的 JSON 在压缩有收益时使用 GZIP，解压也检查大小上限。每租户每服务按实际存储字节加估算元数据限制为 32 MiB，超过预算先淘汰较早到期的缓存。此预算不是 Redis 进程内存硬限制；共享 Redis 仍需结合租户数监控实际内存。不会执行 `KEYS *` 或 `FLUSHDB`。

Actuator/Micrometer 指标：`rigour.query.cache.requests`（region、outcome：hit/miss/put/redis_unavailable/decode_failure/oversize/version_unavailable），`rigour.query.cache.load`（回源耗时）。标签不包含租户、用户或查询内容。评估时同时比较命中率、接口 P95、DB 查询耗时/并发、Redis 内存及不可用次数。

## 启用、回退与验收

新增迁移：CRM V35、Order V72、BI V29 新建服务自有的版本表；CRM V36 增加租户及坐标索引，支持地图网格冷查询。DEV/local 随现有 Flyway 启动流程执行。生产启动仍遵循仓库规则关闭自动迁移，需先按发布流程执行新增迁移，再启用新代码；不能让未接入失效的旧实例长期与新实例混跑。

本地服务由用户在现有 IDEA 运行项重启：CRM、Order、BI。前端采用更新后的开发服务或构建产物。代码开发和隔离测试不等于线上部署验收。

故障回退可关闭查询缓存并重启对应服务；数据库版本表可保留。重新开启前等待最长 TTL（60 秒）或换用新的服务专用命名空间，避免复用关闭期间未跟踪更新的旧键。新命名空间会自然冷启动，不需要清空共享 Redis。

上线验收使用相同账号、条件、页大小比较冷/热请求；分别验证翻页、筛选、空结果、权限变化、认领/释放、回款写入、回滚、地图跨网格平移与缩放。Redis 故障演练仅在隔离环境执行。确认金额、总数和授权范围保持一致后，再记录真实数据量下的 P95 和地图交互耗时，不能用单元测试替代性能结论。
