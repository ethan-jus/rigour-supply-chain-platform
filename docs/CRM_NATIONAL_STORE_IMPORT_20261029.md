# 全国台球门店公海导入验收 · 2026-10-29

## 结果与边界

已向共享 DEV 的 CRM 新门店库导入 **169,957 家门店、169,960 个高德 POI 身份**，全部为无归属的公海门店。关联 Foundation 当前发布目录 `MCA_20251231`，覆盖本数据包的 31 个省级地区、七大区域。

本次没有查询匹配、映射或迁移旧客户档案、历史订单、历史拜访和企微客户。旧业务入口不切换。新库尚未建立合作事实，价值保持 `UNRATED`、交易活跃度保持 `UNKNOWN`；不据此推断门店历史上从未合作。旧 `crm_customer` 当前共 2,933 条，包含先前订单联调创建的测试客户，本次导入脚本不写该表。

原 12 家 DEV 联调门店改为 `SUSPENDED`，保留归属、拜访及订单测试历史；6 个测试 POI 转入 `DEV_TEST_CN` 非活动身份范围。真实公海查询不会混入这些样本，也不会因测试 POI 被占用而漏导真实门店。

## 导入实现

- `scripts/database/prepare-billiards-import.py` 生成 accepted/review/duplicates/manifest，清洗阶段不写库。
- `scripts/database/import-billiards-stores.py` 要求显式 `--apply`、DEV CRM 配置、租户、审计操作者以及入库文件哈希。每 1,000 家一个事务、每 250 行一条批量 INSERT。
- 使用租户级导入锁及现有准入策略锁，写入 `crm_store_master`、`crm_store_summary`、`crm_store_identity`、`crm_store_event`。新建内部 `store_id`，POI 作为独立外部身份，文件来源为 `FILE_IMPORT`。
- 每家写一条 `FILE_IMPORTED` 审计事件。未设置负责人、归属轮次、历史合作订单或历史拜访。`store_type_code` 不从高德分类臆造内部经营类型，原分类保留在来源事件中。
- 已存在 POI 自动跳过，不覆盖既有门店。多 POI 组出现部分已存在或分属不同门店时停止并要求复核；失败回滚当批，已完成批次可续跑。
- 实际中断续跑与全量再次执行均验证：全量重跑新增 **0** 家，跳过 **169,957** 家；主档、摘要、身份、事件数量一致。无新增 Flyway 迁移，CRM 仍为 V30 成功状态。

## 真实权限与页面验收

管理员使用现有 Chrome 登录会话；业务员使用两个独立普通 IAM 账号，经浏览器登录接口及 OIDC Code + PKCE 获取正式令牌，通过 Gateway 调用真实 CRM 接口，没有伪造员工请求头或借管理员身份测试。

两个临时角色成员仅有公海/私海读取功能和 `SELF` 数据范围，分别绑定 HR 杭州、兰州测试员工；部门地域权限来自现有城市授权配置。

| 场景 | 验收结果 |
| --- | --- |
| 管理员全国页面 | 169,957 家，显示“当前范围：全国” |
| 管理员华东 / 浙江 / 杭州 / 上城筛选 | 45,251 / 8,768 / 1,341 / 123 家，与清洗及数据库结果相同 |
| 杭州普通业务员 | 仅杭州市，14 页共 1,341 家，全部 POI 对应本市导入集合 |
| 兰州普通业务员 | 仅兰州市，7 页共 639 家，全部 POI 对应本市导入集合 |
| 两账号跨区域、省、市、县筛选 | HTTP 200，0 条；不能借筛选扩大权限 |
| 两账号访问本市 / 跨市门店详情 | 本市 200，跨市 403 |
| 无商家库管理功能权限时请求 ALL 视图 | 403 |
| 私海 | 两个新测试员工均为 0 条，不把公海显示为私海 |

每页 100 条、两账号并行遍历的 DEV 端到端请求中位耗时：杭州约 1.21 秒，兰州约 1.20 秒，包含 Gateway/IAM/HR/Foundation 及数据库调用，不是纯 SQL 耗时。

验收发现 CRM 未转换 IAM 的功能拒绝响应，导致无管理权限的请求误返回 500；已在 `HttpStoreReferenceClient.access` 将下游 403 转为本地授权拒绝。回归测试先失败后通过；用户重启 CRM 后，两账号真实接口均复验为 403，正常公海查询和跨市拒绝仍通过。

两临时测试账号、凭据、成员及角色已停用，员工绑定已解除并保留历史；原令牌再访问均为 401。未修改管理员或既有业务员的角色与城市授权。
