## 3. 影响真实统计的具体缺口

### 3.1 商品、SKU与单位

- 62条Order明细缺商品/SKU和单位，涉及60笔订单，行金额104446.000004元；BI同样保留62条缺关联/缺单位记录。
- 非空商品/SKU主键都能匹配当前ERP；SKU所属商品主键未发现错配。但主键有效不证明历史语义正确。
- 有1个SKU组存在不同规格快照，涉及173条明细，不能据此宣称各种型号各自销量已核验。
- 有1条GRAIN单位明细无法匹配现有PRODUCT_UNIT字典项，其他非空单位可匹配。字典能解释单位，不代表已验证数量换算。
- 当前销量是原订单数量，BI退款金额按订单行金额比例分摊；没有SKU级退货数量事实，不能给出完整净销量/退货率。
- ERP有41个SKU，订单明细只有6个非空SKU主键组；这不直接等于其他35个SKU真实零销量，缺关联及错绑须先核对。
- 现有历史商品复核预览本次为1条READY、1条BLOCKED，未见APPLIED预览；不能把预览生成称为历史修复完成。

### 3.2 客户、人员与真实经营口径

- 1,721客户全部有城市和归属员工编码，全部能匹配HR员工；2,242订单中2,241能匹配客户与有效HR员工，另1笔需核对。
- 1,721客户的customer_type_code全部为空；1,651扩展档案的类型ID和类型名称也全部为空。不能用已有类型字典虚构客户类型分布。
- 客户来源字段1,721条有值，经营类别字段67条有值。这些可作为待接入维度，须保留空值和字典映射质量。
- crm_customer_policy为空。当前BI缺失账期时默认30天，并据订单日期计算到期日；现有“逾期”属于默认规则结果，不能视为已确认的客户合同账期。
- 当前“建联”根据有联系人或电话判断，不等于已完成拜访、实际沟通或签约。使用这些名称前要统一业务口径。
- 复购、客单价、客户贡献等可从真实订单计算；统计公式、期间和排除规则仍必须明确。
- HR来源状态已确认104人在职、51人离职。HR把离职归为INACTIVE，页面也显示离职，但EMPLOYEE_STATUS字典把INACTIVE解释为停用，另有LEFT表示离职及自动生成的同义项，需要统一领域语义和来源映射。
- HR工资、提成、考勤核算没有对应现行事实实现；服务名称带payroll不能作为功能完成证据。拜访和打卡属于Sales域，需要另外核查员工/门店关联后再接入，不能由HR档案推算。

### 3.3 库存、履约与目标

- ERP仓库、库存、采购、出入库、库存流水当前均没有记录；Order发货单也没有记录。只能标注“数据未就绪”，不能把0记录解释为真实零库存、零发货或无缺货风险。
- 当前BI采购量取采购订单行，并排除草稿/取消，不是确认收货入库数量；“发货量”取ERP销售类型出库行，不是物流签收事实。
- bi_business_target当前无记录。经营目标功能已有，但完成率须使用正式录入的目标，不默认填目标或把缺目标算0%。
- 没有库存、实际采购价和销售成本事实时，库存周转、补货量、实际毛利不能作为真实结果。补货模型即使基于真实记录，也应标为规则建议。

## 4. 按本次要求的实现范围

### 第一组：已有数据，完善接入与核验

1. 保留并统一销售额、应收、累计回款、实际到账、待回款、订单数、客单价、销售/城市排名、客户贡献、复购及商品分类/品牌分析。
2. 接入HR员工与岗位投影，按员工编码关联CRM和Order，提供城市/岗位人员结构与人员业绩；入职日期缺失单列。人员在岗期间和销售岗位范围需明确，不能以“有订单的人数”充当全部在职销售人数。
3. 商品主表展开SKU，直接展示订货数量+单位、金额、订单数、客户数及关联核验状态；规格未区分的历史订单保留待核对。
4. 接入有依据的客户来源/经营类别，不把空类型补成猜测分类。
5. 字典解释统一，异常单位、员工状态冲突和未关联记录提供准确的处理入口。

### 第二组：功能已有，业务事实需要补齐

- 仓库、期初库存与后续库存变动、采购、入库、出库、调拨、发货、退货、经营目标、客户类型及账期。
- 来源导入由Integration负责协议、原始证据和映射；领域服务负责业务表写入。BI只能消费确认后的事实，不能为了出图直接补写业务数据。
- 当前核查不自动执行全量同步、历史修复确认或测试单据创建。

### 第三组：真实性约束

- 活动、成本的样例按用户本次例外单独标记，不能参与其他真实指标或掩盖真实数据缺口。
- 成本不完整时，由成本派生的经营结余、利润、ROI同样不能标记为真实经营结果。
- 其他指标只显示真实事实、可解释的真实数据计算结果、未就绪或待核对；不使用固定数字填充，不把缺数据或请求失败当成0。
- “暂无业务记录”和“已完整同步且确实为0”需要不同状态；保留来源最后成功时间和完整性信息。

## 5. 接入后的验收标准

1. 每个指标能对应来源域、表/接口、主键、期间、单位、状态范围和权限范围。
2. Order与BI按来源单号、订单及明细主键、金额和数量核对；单位、规格及归属结论独立。
3. 商品→SKU→订单/发货/退货明细下钻保持筛选范围，金额与数量分别守恒。
4. HR按员工编码关联；禁止仅按姓名拼接。当前在职与历史期间任职口径分开。
5. 没有来源、默认规则、比例分摊、估算、样例均可识别；成本和活动例外不向其他指标传播。
6. 代码测试、数据库核对、已登录页面验证和生产部署验收分别记录。
